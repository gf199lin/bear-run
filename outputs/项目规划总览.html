毫米波雷达体感跑酷游戏 · 项目规划总览

一页纸速览版 ｜ 第 2 版（2026-10-16）｜ 详细文档见项目 docs/ 目录

01我们要做什么

用 矽典微毫米波雷达，无接触操作一个跑酷游戏。

雷达采集 → 人体动作识别 → 游戏响应 → 计分结算

玩家站姿，站在雷达前方 0.5–1.5 m，通过左右移动身体切换跑道，跳起或蹲下躲避障碍物，撞到扣命，3 条命用完结算。

02硬件事实：先记住这 4 条，能省下很多返工

#事实为什么重要
1 我们手上有两块板：1T2R（DEV202H / ICL1122，链路已打通）＋ 2T4R（一直在手上，链路验证进行中） 两块板能力不同，用哪块当主力要先定
2 USB 转换芯片是 CP2102，装 CP210x 驱动 原方案写的「装 FTDI 驱动」是错的，别照着做
3 帧率 7.7 Hz（129.5 ms/帧，1T2R 实测） 这是全项目体验上限：动作做完约 0.13–0.3 s 后画面才响应。2T4R 需重新确认
4 1T2R 垂直角不可用 → 测不了人体高度；2T4R 有 4 个接收通道，理论上可测俯仰角 → 能直接测高度 这决定了跳 / 蹲走哪条实现路径（见第 04 节）
授权（Vikey）已确认可用，1T2R 设备可以连上。工具日志里那些窗口 / 线程记录不是「连接失败」，不用再排查这一项。2T4R 的授权与连接验证进行中（10/16 起，结论未出）。

03已经定下来的

项目决定
题材跑酷类（地铁跑酷风格）
交互范式动作触发：身体移动一次 → 角色切一条道（不是位置映射）
识别目标左 / 中 / 右 ＋ 跳起 / 蹲下（已确认全部纳入 MVP）
规则3 条命 / 不限时 / 按距离计分 / 速度分段递增
安装桌面固定，近距 0.5–1.5 m，站姿
兜底模拟器模式（拔掉雷达也能完整演示）是 P1 需求，不是可选项
验收阈值由本项目依硬件上限提出、小组确认（已有提案，待签字）

为什么选「触发式」而不是位置映射：7.7 Hz 下用绝对位置映射，玩家得一直保持站位，手感很差。触发式只需做一次动作就能换道，与低帧率天然兼容。

04跳起 / 蹲下：已进 MVP，但要选实现路径

决策：跳起 / 蹲下确定纳入 MVP（团队决策）。

问题背景：1T2R 没有俯仰角通道，无法直接测人体高度。
另一条路：手上的 2T4R 板 → 4 个接收通道可做「方位＋俯仰」二维角 → 理论上能直接测人体高度，跳 / 蹲可靠性大幅提升。

两条实现路径（需二选一或并行对照）

路径原理优点风险
A. 2T4R 俯仰角测高 二维角 → 直接得到人体高度变化 原理直接、最可靠 该板链路验证进行中（10/16 起实验中，结论未出；授权 / 连接 / 参数 / 数据通道）；帧率等参数可能与 1T2R 不同
B. 1T2R 多普勒＋距离间接特征 垂直运动经视线投影产生径向速度；时序包络区分跳 / 蹲 沿用已打通的链路 距离分辨率 0.68 m 偏弱；最大不模糊速度 ±1.53 m/s，跳跃可能速度模糊；尚未证实
关键理解：「纳入 MVP」是范围决策，不等于「已经能实现」。验证的目的因此从「要不要做」变成「用哪条路做」。
P0 进行中验证 2T4R 能否正常连上（授权、串口、参数配置、数据导出）
10/16 起实验中，结论未出｜最优先，10/17 前

0.5 天

1–2 天
