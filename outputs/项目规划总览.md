# 毫米波雷达体感跑酷游戏 · 项目规划总览

**一页纸速览版** ｜ 2026-10-15 ｜ 详细文档见 `docs/`（本页结尾有索引）

---

## 一、我们要做什么

用 **矽典微 DEV202H 毫米波雷达**，无接触操作一个跑酷游戏。

```
雷达采集 → 人体动作识别 → 游戏响应 → 计分结算
```

玩家站姿，站在雷达前方 **0.5–1.5 m**，通过左右移动身体切换跑道，躲避障碍物，撞到扣命，3 条命用完结算。

---

## 二、硬件事实：先记住这 4 条，能省下很多返工

| # | 事实 | 为什么重要 |
|---|---|---|
| 1 | 模块是 **DEV202H / ICL1122 / 1T2R** | 不是 2T4R。另一块 2T4R 板**不在我们手上** |
| 2 | USB 转换芯片是 **CP2102**，装 **CP210x 驱动** | **原方案写的「装 FTDI 驱动」是错的**，别照着做 |
| 3 | 帧率 **7.7 Hz**（129.5 ms/帧） | 这是**全项目体验上限**：动作做完约 0.13–0.3 s 后画面才响应 |
| 4 | **垂直角不可用** → 测不了人体高度 | 直接后果：「跳起/蹲下」没法靠测高识别 |

**授权（Vikey）已确认可用，设备可以连上**——工具日志里那些窗口/线程记录不是「连接失败」。

## 三、已经定下来的

| 项 | 决定 |
|---|---|
| 题材 | 跑酷类（地铁跑酷风格） |
| 交互范式 | **动作触发**：身体移动一次 → 角色切一条道（**不是**位置映射） |
| 识别目标 | 左 / 中 / 右（**必做**）；跳起 / 蹲下（**待验证**，见第四节） |
| 规则 | 3 条命 / 不限时 / 按距离计分 / 速度分段递增 |
| 安装 | 桌面固定，近距 0.5–1.5 m，站姿 |
| 兜底 | 模拟器模式（拔掉雷达也能完整演示）**是 P1 需求，不是可选项** |
| 验收阈值 | 由本项目依硬件上限提出、小组确认（现已出提案，待签字） |

> 交互范式为什么选「触发式」：7.7 Hz 下若用绝对位置映射，玩家得一直保持站位，手感很差。触发式只需做一次动作就能换道，与低帧率天然兼容。

## 四、最大的不确定性：跳起 / 蹲下

**问题**：1T2R 没有俯仰角通道 → **无法直接测人体高度**。

**AI 分析结论**（问题：「能不能靠多普勒 + 距离变化间接识别跳起和蹲下？」）：

- **多普勒（有希望）**：垂直运动与雷达视线成夹角时会产生径向投影。雷达在桌面高度看 1 m 外的人，上半身仰角可达 30–45°，跳起约 1 m/s 时径向分量可达 **0.5–0.7 m/s**，远超速度分辨率 **0.05 m/s**，必然可见；而且「起跳—腾空—落地」与「下蹲—停留—站起」的**时序包络形状不同**，这比符号更稳。
- **距离（弱）**：距离分辨率 0.68 m，且正对时躯干的径向距离几乎不变。只有在**雷达略高、略微俯视**时，蹲下才会让反射点下移、距离明显变远——**所以安装高度是可以优化的杠杆**。
- **已知的坑**：最大不模糊速度约 **±1.53 m/s**，人跳跃垂直速度常达 1–2 m/s，**可能速度模糊**，必须实测确认。

**处理方式：不承诺，先验证。**

| 阶段 | 内容 | 时间盒 |
|---|---|---|
| T0 | 跑 ONELAB 内置手势算法 `algorithm_gr` 探路（参数 `UD_SpeedMin = 0.400` 暗示支持上下动作） | 0.5 天 |
| T1 | 导出 2D FFT 数据，离线做特征可分性分析（留一交叉验证） | 1–2 天 |
| **T2** | **决策点**：通过 → 实现；不通过 → 跳/蹲不进 MVP，等 2T4R | **10/18 前** |

**底线：即使跳/蹲做不了，左/中/右 + 完整跑酷闭环也必须能玩。**

## 六、分工与本周重点

| 角色 | 本周（10/15–10/18）重点 |
|---|---|
| **A** 硬件与数据采集 | 连接与参数确认；**跑 T0 探路**；采集跳/蹲数据（含几何对照）；负责真值标注 |
| **B** 数据接口与处理 | 解析官方 demo 输出，**M0 结束前冻结 `RadarFrame` 字段**；搭数据录制通道 |
| **C** 游戏主程 | 确定游戏框架；跑通无雷达的跑酷骨架（先吃模拟器数据） |
| **D** 集成测试与体验 | 真值标注；准备验收测试表执行；设计模拟器演示脚本 |
| **全员** | 签字确认验收阈值（Q6） |

**协作铁律**：真实雷达与模拟器**必须实现同一事件接口**，且能用**一个热键在 1 秒内切换**——现场演示不允许因为设备问题中断。
