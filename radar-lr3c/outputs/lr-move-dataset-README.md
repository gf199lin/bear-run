# 左右移动数据集（1T2R 毫米波雷达）

> 交付对象：需要左右移动样本的同学
> 生成时间：2026-10-21
> 生成方式：由 `radar-pointcloud/radar_actions.py` 的 `analyze_file()` 离线复算录制文件，
> 脚本见 `.deepworks/tmp/export_lr.py`（可重跑复现）

---

## 1. 这份数据是什么

用矽典微 DEV202H（ICL1122，**1T2R**）雷达，录制的**真人左右横移**动作。
每个立方文件对应一个站位，受试者在雷达前按语音提示做「向左移动 / 向右移动」，
每次动作有明确的**人工 cue 标注**（真值来源）。

| 文件 | `segment` | 站位 | 帧数 | 帧率 | 动作数 | 检出率 |
|---|---|---|---|---|---|---|
| `seg_00.70.bin` | `d00.70` | 0.70 m | 1031 | 7.72 Hz | 5 左 + 5 右 | 44.7% |
| `seg_00.85.bin` | `d00.85` | 0.85 m | 1031 | 7.72 Hz | 5 左 + 5 右 | 48.3% |
| `seg_01.00.bin` | `d01.00` | 1.00 m | 1030 | 7.72 Hz | 5 左 + 5 右 | 31.8% |
| **合计** | | | **3092** | | **15 左 + 15 右** | **41.6%** |

- 原始录制文件：`.deepworks/tmp/oncehot-oncehot/lr/seg_*.bin`
- 人工标注：同目录 `seg_*.labels.jsonl`
- 帧周期 129.5 ms（≈7.72 Hz），**这是全项目体验上限**，数据集里所有时间列都由此换算。

## 2. 交付文件

### `lr-move-frames.csv` — 逐帧表（3092 行）

一行 = 一帧。

| 列 | 含义 |
|---|---|
| `segment` / `file` | 数据段标识 / 原始文件名 |
| `distance_m` | 受试者站位（米） |
| `board` | 板型，本数据集全部为 `1t2r` |
| `frame` | 帧号（0 起） |
| `t_s` | 时间（秒）= 帧号 × 0.1295 |
| `action_id` | 该帧所属动作编号，如 `d00.70_03`；不在任何动作窗内为**空** |
| `direction` | **方向标签**：`LEFT` / `RIGHT` / `IDLE`（IDLE = 动作窗口之外） |
| `rel_t_s` | 相对本动作 cue 起点的秒数（仅动作窗内有值） |
| `n_pts` | 该帧检测到的点数，**为空 = 该帧无目标** |
| `px_m` / `py_m` | 目标簇的横向 / 纵向质心位置（米） |
| `r_mean_m` | 簇的平均距离（米） |
| `v_rad_mps` | 径向多普勒速度（米/秒） |
| `deg_span` | 簇的方位角展宽（度） |
| `energy` | 簇能量 |
| `v_lat_mps` / `dx_m` | 窗口横向速度 / 横向位移（识别器输出，属派生量） |
| `band_lo` / `band_hi` | 本次复算使用的距离门（米） |
| `events` | 该帧触发的事件名，多个用 `;` 分隔 |

### `lr-move-actions.csv` — 动作级汇总（30 行）

一行 = 一次移动（15 左 + 15 右）。

| 列 | 含义 |
|---|---|
| `action_id` | 动作编号 |
| `direction_label` | **人工 cue 标注**（真值来源） |
| `t_start_s` / `t_end_s` / `frame_start` / `frame_end` | 动作窗（已扣除受试者反应时间） |
| `frames_with_target` | 窗口内有目标检出的帧数 |
| `px_start_m` / `px_end_m` / `px_delta_m` | 窗口首末帧的横向位置与位移 |
| `px_range_m` | 窗口内横向位置的极差 |
| `mean_v_lat_mps` / `mean_deg_span` / `mean_range_m` | 窗口均值 |
| `px_direction` | **仅凭数据判出的方向**（`px_delta_m` 正负） |
| `dir_matches_label` | 数据方向与人工标注是否一致（`yes` / `no`） |

## 3. 方向标签的含义（重要）

- `direction` / `direction_label` 是**录制时人工 cue 的真值**，即当时要求受试者做的方向。
  这是本数据集里**方向的主标签**，请以此为准。
- `px_direction` 是**从测得的横向位置反推**的方向，仅作参考。

### 一致性现状（必须知道）

| 人工标注 | 数据 `px` 走向与标注一致 |
|---|---|
| `LEFT` | **13 / 15** |
| `RIGHT` | **3 / 15** |

也就是说：LEFT 的动作，`px` 大多**减小**（13/15 符合「左移 → 位置变小」）；
但 RIGHT 的动作，`px` 也**多数在减小**（12/15 与标注相反）。

这**不是**本数据集独有的偶发问题，而是这个项目此前已经记录在案的现象：

> 「同批数据**方向标签 10/10 反向**（『向右』时 `px` 减小 → 判成 `LANE_LEFT`）。
> ⇒ **先做 30 s『左手边』确认（看 `px` 增大还是减小）**，再谈瞄准与阈值。」
> —— `docs/handoff-leftright-radar.md`

结论：**`px` 的正负号与人体左右的对应关系，学术上尚未用独立实验确认**。
本数据集**不替使用者做符号翻转**，只如实给出 `px_delta_m`，把判断权留给使用者。

## 4. 已知限制（用之前请先读）

1. **检出率只有 41.6%**：超过一半的帧没有目标点；动作窗内也有 59% 的帧无检出。
   原因是当时**雷达没有瞄准人**（静息主回波方位角约 +40°，横向偏 1.1~1.5 m，贴 ±45° 视场边缘），
   人再往视场外侧走就会直接出视场。**这是这批数据「不够清晰」的根本原因**，不是本次整理引入的。
2. **每帧点数极少（通常 2~6 个）**：横向质心 `px` 由零星点算出，抖动较大。
3. **窗口可能混入回程**：标注窗口只扣了反应时间，若受试者走得过快，
   窗口可能部分覆盖「回到中间」的返程，从而把返程当成动作（项目文档亦有此记录）。
4. **站位 0.70 m 是问题站位**：主回波功率占比过高（83.9%），项目新决策是主采 1.5~2.0 m。

### 使用建议

- **可以直接用**：`direction` 作为方向标签，配合 `px_m / py_m / v_rad_mps / energy` 等物理量做特征。
- **不要直接做**：用 `px_delta` 的正负去训练/评估「左右分类器」，除非先完成符号标定。
- **建议先补一步**：让一个人固定站在雷达**正前方偏左**处静止 30 s，
  看 `px` 是增大还是减小，即可定下符号约定，之后这份数据立刻可用于左右分类。
