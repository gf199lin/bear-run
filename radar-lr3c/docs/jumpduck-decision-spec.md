# 跳/蹲 判别规格 v1.0

> 本文集中记录**所有**能用于区分跳/蹲的判据、参数、实测数字、失败边界，以及"为什么不用别的办法"。
> 代码位置、复现命令、证据文件均在此。
> **所有阈值均为本项目提案，待小组确认。**

## 1. 硬件与坐标系

| 项 | 值 |
|---|---|
| 板型 | 1T2R（DEV202H / ICL1122） |
| 安装 | **竖放**（Rx 阵列垂直地面），仰视，人站 1.0–1.2 m |
| 帧率 | 7.73 fps（帧周期 **129.5 ms**） |
| 分工 | **这块板只判跳/蹲**；左右移由另一块横放的 1T2R 负责 |

**本板不判左右，也不判方向。** 左右移在本文里只作为"需要排除的切向运动"出现。

### 1.1 径向速度符号

`v_r` 是带内能量加权平均径向速度：

- **正** = 靠近雷达 = 身体**向上**（跳、起身）
- **负** = 远离雷达 = 身体**向下**（下蹲）

实测依据：中蹲序列为 `-0.32 -0.64 -0.45 ... +0.21 +0.32 +0.80`，先负后正，符合"先蹲后起"。

### 1.2 为什么不用方位角

`data/jumpduck_battery/20261113-133307_S01` 的 `rest0` 段（93 帧、无人动）az 跨度已达 **159.4°**，`dphi` 在 ±3.14 满幅跳；跳/蹲 146–165°、左/右 43–165°、弯腰 148–156°，**各组无差异**。

即方位角连"有人/没人"都分不开，是纯噪声。**本文所有判据只依赖多普勒轴。**

另测 `mv_feats`（只在 `|v|≥0.15` 的非零多普勒单元求相位差）：`ang_mv` 跨距 150°、每块 20–44 个不同取值，同样是噪声。

## 2. 判据总览（三层）

```
第 1 层  有没有动作          nz_share
第 2 层  切向 还是 径向      doppler_width
第 3 层  跳 还是 蹲          因果 EMA 后的同号段长度   ← 核心
```

### 2.1 第 1 层：有没有动作

`nz_share` = 零多普勒外能量占比（`|v| < 0.15 m/s` 之外的功率占比）。

| 状态 | `nz_share` |
|---|---|
| 静息 | 0.00–0.03 |
| 跳/蹲 | 0.60–0.90 |

门限（提案）：

- 块级：`nz_p90 >= 0.50`
- 逐帧（状态机）：`nz_share >= 0.30`

余量约 14 倍，这一层最可靠。

### 2.2 第 2 层：切向 vs 径向（只用于防误触发）

`doppler_width` = 多普勒速度轴的加权标准差，**只由"运动方向与视线的夹角"决定，与雷达板绕光轴怎么转无关**。

| 动作 | `w_p90` |
|---|---|
| 左/右移（切向，垂直于视线） | 0.15–0.20 |
| 跳/蹲（径向，有视线投影） | 0.29–0.54 |

门限（提案）：`w_p90 < 0.22` → 判为切向，不是跳/蹲。

> **术语**：不要叫它"横向/纵向"，容易误读成雷达的方位角方向。正确表述是**切向 / 径向**，基准是**视线**。

### 2.3 第 3 层：跳 vs 蹲 —— 核心判据

#### 2.3.1 因果 EMA 平滑

```
vs[i] = 0.5 * v_r[i] + 0.5 * vs[i-1]
```

**为什么必须平滑**：慢速动作（浅蹲）的 `v_r` 在 ±0 之间来回翻符号，**凑不出"连续同号段"**。实测浅蹲 `|v_r|` 最大值中位 **0.401 m/s**（远超门限），却测出 `nb = pb = 0`。平滑后 `nb` 从 0 变成 3–4。

只用过去帧，**实时可用**，群延迟约 1 帧（129 ms）。

#### 2.3.2 同号段长度

| 量 | 定义 |
|---|---|
| `nb` | 连续满足 `vs < -0.15` 的最长帧数（允许段内 1 帧回落） |
| `pb` | 连续满足 `vs > +0.15` 的最长帧数 |

判定（提案）：

```
nb <= 2   →  JUMP
nb >= 3   →  DUCK
```

**分界 3 帧 = 0.39 s。**

#### 2.3.3 实测分布（EMA 后）

| 组 | `nb` | `pb` |
|---|---|---|
| 轻跳 `jump_k`（不蓄力） | **1 1 1 2 1 2 2 1 1 2 1 2** | 0–2 |
| 中跳 `jump_m` | 1–2 | 1–2 |
| 大跳 `jump_l`（自然蓄力） | 2–3 | 2–4 |
| 浅蹲 `duck_s` | 2–4（EMA 前全 0） | 2–4 |
| 中蹲 `duck_m` | 4–5 | 4–6 |
| 深蹲 `duck_l` | **4 6 4 5 4 4 4 4 5 4 4 5** | 4–6 |

**轻跳 1–2 与深蹲 4–6 零重叠。**

#### 2.3.4 为什么不用幅值

| 动作 | 最大负峰 | 最大正峰 |
|---|---|---|
| 跳（14 次） | 0.36–0.71 | 0.38–0.78 |
| 蹲（14 次） | 0.45–0.64 | **0.38–0.88** |

**蹲的起身正峰（0.88）比跳的正峰（0.46）还大。** 按幅值判，蹲的起身会被当成"更强的跳"。

物理原因：7.7 Hz 抓不到跳跃的爆发瞬间——上冲只占 1–2 帧，被 129.5 ms 窗口平均掉了。而蹲的起身是受控的、持续 3–5 帧，峰值反而完整。

#### 2.3.5 为什么不用位移

负向位移 `∫v·dt`（cm）：

| 组 | 中位 | 范围 |
|---|---|---|
| 中跳 | 23.4 | 19.3–37.3 |
| **大跳** | **38.2** | 28.3–48.4 |
| 中蹲 | 30.3 | 23.2–38.5 |
| 深蹲 | 29.4 | 25.8–33.0 |
| 浅蹲 | 21.6 | 15.9–34.5 |

**大跳蓄力 38.2 cm 比深蹲 29.4 cm 还深**——人做"尽量跳高"时本能深蹲。位移方向完全重叠，不可用。

#### 2.3.6 为什么不用谱宽

大幅跳与深蹲的 `w90` 差值 Cohen d = +0.06，方向还随幅度翻转。不可用。

## 3. 逐帧状态机（实时实现）

代码：`tools/jumpduck_sm.py`

```
IDLE
  ├─ nz < 0.30              → 保持
  ├─ 原始 v_r < -0.15       → NEG(nb=1)     [触发用原始值，避免 EMA 冷启动削半]
  └─ 原始 v_r > +0.15       → POS0

NEG
  ├─ vs < -0.15, nb+1
  │    └─ nb >= 3           → 发 DUCK → SUPPRESS
  ├─ vs > +0.15             → 发 JUMP
  └─ |vs| < 0.15 连续 3 帧
       ├─ nb >= 3           → 发 DUCK → SUPPRESS
       ├─ nb >= 1           → 发 JUMP   [7.7 Hz 漏掉上冲时兜底]
       └─ 否则              → IDLE

SUPPRESS  （蹲已确认，起身后摇被吞掉）
  └─ nz < 0.30 连续 6 帧    → IDLE

任意事件后：冷却 8 帧（1.03 s），防止一次动作重复触发
```

**关键设计点**：

1. **动作一旦开始就不再检查 `nz`**——起跳腾空瞬间 `nz` 会掉到门限以下，用它维持会把跳跃正段掐断（实测 `jump_k` 有 3 块因此完全无事件）。
2. **触发用原始 `v_r`**，不用 EMA——EMA 冷启动会把首帧削半（0.19 → 0.096），轻跳会漏。
3. **`nb >= 1` 的兜底 JUMP**——短负段后平静下来且没转正，说明 7.7 Hz 漏掉了上冲，负段短即快速动作，不能丢。

## 4. 参数总表（全部为提案值，待小组确认）

| 参数 | 值 | 作用 | 依据 |
|---|---|---|---|
| `NZ_T_ON` | 0.30 | 逐帧动作门（`nz_share`） | 静息 0.00–0.03，动作 0.6–0.9 |
| `NZ_P90` | 0.50 | 块级动作门 | 同上 |
| `W_LAT` | 0.22 | 切向门（`w_p90` 低于此判切向） | 切向 0.15–0.20 / 径向 0.29–0.54 |
| `ALPHA` | 0.5 | 因果 EMA 系数 | 0.4 漏浅蹲、0.6 拖长大跳；0.5 最平衡 |
| `V_T` | 0.15 m/s | 同号段速度门限 | 平滑后静息 |vs| 稳定 <0.05 |
| `NB_DUCK` | 3 帧 | 判蹲的负段长度 | 跳 1–2 / 蹲 3–6，分界 0.39 s |
| `QUIET` | 6 帧 | 抑制态回 IDLE 的静默帧数 | 覆盖起身后摇 |
| `COOLDOWN` | 8 帧 | 事件后冷却 | 一次完整跳 4–6 帧 |

## 5. 实测性能

### 5.1 数据

四批有效采集，单人同日，共 96 个跳/蹲样本：

| 目录 | 块数 | 内容 |
|---|---|---|
| `20261113-133307_S01` | 37 | 中/小/大幅跳蹲 + 左/右 + 弯腰/转身/踏步 |
| `20261113-134832_S01` | 21 | 中跳 ×10 中蹲 ×10 |
| `20261113-140614_S01` | 33 | 中跳/中蹲/大跳/浅蹲 各 8 |
| `20261113-142228_S01` | 25 | **轻跳 ×12 + 深蹲 ×12** |

（另有 `20261113-140448_S01_VOID`、`20261113-142042_S01_VOID` 因雷达歪斜/掉线作废，未接入评估。）

### 5.2 状态机结果

| 指标 | 结果 |
|---|---|
| 判对 | **82/96 = 85.4%** |
| 蹲 | **47/48 = 97.9%** |
| 跳 | **35/48 = 72.9%** |
| 延迟中位 | **388 ms**（3 帧） |
| 最差延迟 | 906 ms |
| 静息块误触发 | **0 次** |
| 单次动作只发一个事件 | 86.1%（修 `_emit` 抑制后为 100%，见 §5.3） |

**轻跳 + 深蹲专项**：轻跳 **12/12**、深蹲 **12/12**、单次事件 **24/24**，延迟 跳 517 ms / 蹲 388 ms。

### 5.3 失败构成（全部 14 例）

| 类型 | 数量 | 原因 |
|---|---|---|
| 大跳 `jump_l` | 9 | 蓄力下蹲达 3 帧，与真蹲在特征上重叠 |
| 中跳 `jump_m` | 4 | 同上（部分样本自然蓄力） |
| 浅蹲 `duck_s` | 1 | 负段仅 2 帧，低于分界 |

**没有一例失败来自轻跳或深蹲。**

## 6. 失败边界与已知限制

### 6.1 自然大跳 = 蹲（物理不可分）

大跳的蓄力段与浅蹲在 `nb`、`negPk`、位移上全部重叠，因为**它们就是同一个动作**（浅下蹲 + 起身），只是意图不同。

**处置**：游戏教学要求"**轻跳：只弯一点膝盖，脚跟离地即可**"。按此执行时跳 12/12。

### 6.2 负样本全部误报（未解决）

| 动作 | 实测 `w90` | 判定 | 后果 |
|---|---|---|---|
| 弯腰捡东西 ×3 | 0.48 / 0.49 / 0.49 | 径向 | **误触发跳或蹲** |
| 原地踏步 ×2 | 0.54 / 0.52 | 径向 | **误触发** |
| 转身 ×3 | 0.32 / 0.45 / 0.36 | 径向 | **误触发** |

负样本 8/8 全部误报。**这是并入游戏前的首要未解决问题**，需要补采负样本后设计否决项（例如要求单次孤立动作、增加起身后静默要求）。

### 6.3 其他限制

- 数据来自**单人、单日、单一安装几何**（雷达离地约 0.5 m，人站 1.0–1.2 m）；换人、换高度需重新标定。
- 帧率 7.73 Hz 是硬上限：动作短于 129 ms 必然漏采。
- 距离只有 1.02 / 1.70 两个 bin（0.68 m 分辨率），`auto-band` 必须覆盖两个 bin，否则丢约 48% 帧。

## 7. 复现方式

```bash
# 逐帧状态机评估（推荐）
python tools/jumpduck_sm.py data/jumpduck_battery/20261113-142228_S01

# 四批全量
python tools/jumpduck_sm.py data/jumpduck_battery/20261113-133307_S01 ^
                            data/jumpduck_battery/20261113-134832_S01 ^
                            data/jumpduck_battery/20261113-140614_S01 ^
                            data/jumpduck_battery/20261113-142228_S01

# 块级判据（对照）
python tools/eval_vr_rule.py data/jumpduck_battery/20261113-142228_S01

# 采集（现场）
python tools/jumpduck_battery.py --port COM3 --id S01 --tier p6
```

- 状态机：`tools/jumpduck_sm.py`
- 块级判据：`tools/eval_vr_rule.py`
- 采集器：`tools/jumpduck_battery.py`（网页引导 + 语音 + 自动真值）
- 分析报告：`docs/jumpduck-battery-analysis-1113.md`
- 现场手册：`docs/jumpduck-battery.md`
- 证据产物：`outputs/jumpduck-battery-1113-*.csv` / `*.png`

## 8. 游戏侧接入

`dual-radar-kit/tools/radar_live_ws.py` 新增：

```
--jump-engine sm      用本状态机替换 ActionRecognizer 的跳/蹲事件
--jump-band 1,3       状态机使用的距离 bin 带（默认 1,3）
```

原 `legacy` 判据保留，默认不启用新引擎。

启动：

```bash
python dual-radar-kit\tools\radar_live_ws.py --port COM3 --role ud --vertical --jump-engine sm
```

游戏侧无需改动：它本来就监听 `jump` / `crouch` 的上升沿，状态机事件映射成同样的单帧脉冲。
