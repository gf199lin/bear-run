# 双板共存：1T2R（左右）+ 2T4R（跳蹲）会不会互相干扰

> 状态：**分析 + 待实测**。本文的数字里，射频参数来自 `docs/radar-uplink-dev113p-2t4r.md` L200-210 与协议实测；
> 干扰强度是**雷达方程估算**，不是实测值。**没有任何一次"两板同时工作"的录制**（全仓库只有单板文件）。

---

## 0. 先说结论

| 问题 | 结论 |
|---|---|
| 会有射频干扰吗 | **会。** 两板频段重叠，且 1T2R 的整个带宽落在 2T4R 的扫频范围内 |
| 干扰是什么形态 | **抬高噪声底**（不是单个假目标）——因为两板 chirp 斜率不同（1.04 vs ≈5 MHz/µs） |
| 串口会冲突吗 | **不会。** 1T2R 是 CP210x/COM3/921600，2T4R 是 FTDI/COM4/1500000，芯片和端口都不同 |
| 软件能同时跑吗 | **能**，但当前是单板架构，要起**两个 `server.py` 实例 + 两个 `--http-port`**，前端要消费两路 |
| 2T4R 能辅助左右判断吗 | **不建议。** 它只有 **1.92 Hz**，比 1T2R 慢 4 倍，做左右会直接拖垮延迟 |

**一句话**：能一起用，但**必须做物理隔离并实测**；而且 2T4R 只该干"跳/蹲"这一件事。

## 1. 两块板的射频参数（都是 24 GHz 频段，但配置差很多）

| | 1T2R（DEV202H / ICL1122） | 2T4R（DEV113P） |
|---|---|---|
| 中心频率 | **24.125 GHz** | **24.5005 GHz** |
| 带宽 B | **220 MHz** | **999 MHz** |
| 占用频段 | 24.015 ~ 24.235 GHz | **24.001 ~ 25.000 GHz** |
| 波长 λ | 12.43 mm | 12.24 mm |
| 距离门距 | 0.6813 m | 0.15 m |
| 帧周期 | **0.1295 s（7.7 Hz）** | **0.5208 s（1.92 Hz）** |
| 水平阵元间距 | 6.250 mm | 5.900 mm |
| 串口 | COM3 / CP210x / 921600 | COM4 / FTDI / 1500000 |

**关键一行**：1T2R 的 **24.015~24.235 GHz 完整落在** 2T4R 的 24.001~25.000 GHz 之内。
⇒ 两板不可能靠"频率错开"共存，**硬件层面无法规避**。

## 2. 干扰形态：为什么是"抬高噪底"而不是"假目标"

FMCW 雷达之间干扰的产物是**拍频**：

```
f_beat = |f_A(t) − f_B(t)|
```

- **如果两板斜率相同**：拍频近似恒定 → 落在**某一个距离门** → 表现为一个假目标（好处理）。
- **如果两板斜率不同**：拍频随时间扫过一段范围 → 散布到**多个距离门** → 表现为**噪声底整体抬高**（难处理）。

实测参数：

| | 1T2R | 2T4R |
|---|---|---|
| 带宽 / 扫频时间 | 220 MHz / 212 µs | 999 MHz / 未测 |
| 斜率（估） | ≈ **1.04 MHz/µs** | ≈ **5 MHz/µs**（若扫频时间同量级） |

⇒ **斜率差约 5 倍 ⇒ 属于"抬高噪底"这一类，最坏的那一类。**

**不对称性（对我们有利的一点）**：

- **2T4R → 1T2R**：2T4R 扫 1 GHz，扫过 1T2R 的 220 MHz 时都会产生干扰 ⇒ **污染 1T2R 的全部距离门**。
- **1T2R → 2T4R**：1T2R 只占 220 MHz，只影响 2T4R 扫频的 **约 22%** ⇒ **只污染 2T4R 的一部分距离门**。

而 2T4R 只用来测"人在 1 m 附近"的俯仰角，**距离门是已知且窄的**，
所以"1T2R 干扰 2T4R"这一半相对可控；**"2T4R 干扰 1T2R"才是主要风险**。

## 3. 干扰强度估算（雷达方程，非实测）

自由空间直接耦合：

```
P_干扰 / P_发射 = (λ / 4πd)²          → 20log10(λ/4πd)
```

目标回波（人，RCS ≈ 0.5 m²，距离 1 m）：

```
P_目标 / P_发射 = G²λ²σ / ((4π)³R⁴)
```

取 G = 5 dBi/天线（保守），λ = 12.4 mm：

| 两板间距 d | 直接耦合 | 相对目标回波 |
|---|---|---|
| 0.20 m | −46.1 dB | **强 18 dB** |
| 0.30 m | −49.6 dB | 强 14.5 dB |
| 0.50 m | −54.1 dB | 强 10 dB |
| 1.00 m | −60.1 dB | 强 4 dB |

⇒ **两板靠近且主瓣相对时，干扰比人体回波强 10~18 dB。**
但天线有方向性：若两板**背对背**，主瓣互不照射，隔离度可再加 20~30 dB，
此时干扰会落到目标回波之下。

**这与 `#51` 的实测是一致的**：单板时噪声底约 `1.15e4`（左）/ `9716`（中）/ `1.18e4`（右），
两板互扰会把这个数字整体推高。**验证方法就是对比"单开 vs 双开"的噪声底。**

## 4. 串口与软件层：不冲突，但要改架构

### 4.1 串口层：干净

| | 芯片 | 端口 | 波特率 |
|---|---|---|---|
| 1T2R | CP210x | COM3 | 921600 |
| 2T4R | FTDI | COM4 | 1500000 |

不同芯片、不同 COM、不同速率 ⇒ **物理上互不干扰**。
（注意 `AGENTS.md` 记的"CP210x 驱动"只针对 1T2R；2T4R 走 FTDI，驱动另装。）

### 4.2 软件层：当前是单板设计，要动

`server.py` 已经是参数化的：

```
--port       串口（auto / COM3 / COM4）
--board      auto / 1t2r / 2t4r
--http-port  默认 8099
```

所以两板共存的最小改造是**起两个实例**：

```powershell
# 1T2R：左右主链路
python radar-pointcloud\server.py --port COM3 --board 1t2r --http-port 8099

# 2T4R：跳/蹲
python radar-pointcloud\server.py --port COM4 --board 2t4r --http-port 8100
```

**但下面这三件事必须一起解决，否则跑了也没用**：

| 问题 | 说明 |
|---|---|
| **前端只认一个源** | `radar-runner/js/InputSource.js` 消费单个 ws/SSE，要改成双源并合并 |
| **事件语义冲突** | 两个实例都会输出 `LANE_*`/`JUMP`/`DUCK`。必须约定：**8099 只取 LANE，8100 只取 JUMP/DUCK**，否则互相打架 |
| **时间戳对齐** | 两板独立晶振、帧周期 129.5 vs 520.8 ms，2T4R 一帧跨 4 个 1T2R 帧。融合时要按**到达时间**对齐，不能按帧号 |

> 另注：`capture-checklist.md` §0.6 提到"跑采集前要先停 8099 服务（它独占 COM4）"——
> 那是采集脚本与 server 争**同一个**串口的情形，不是双板互斥。只要各自指向不同 COM 即可。

## 5. 2T4R 到底该不该"辅助左右"——参数上就不该

用户设想的三种角色，逐条对一下：

| 角色 | 2T4R 能不能胜任 | 依据 |
|---|---|---|
| 测跳/蹲 | ✅ **能** | 俯仰角通道可用（`VertAngleInfo = 5.900,1.000,0,2;5,2,3`），动作慢，1.92 Hz 够 |
| 辅助左右判断 | ❌ **不该** | **1.92 Hz**：一次左右移动约 0.6~1.0 s，只剩 1~2 帧；而 1T2R 有 5~8 帧。加进来只会**拖慢**而不是帮忙 |
| 提高左右精度 | ❌ **不明显** | 左右靠的是**方位角**，两板水平阵元间距 6.25 vs 5.90 mm，差别很小；2T4R 的优势在**俯仰**，不在水平 |

**建议**：**左右只由 1T2R 做，2T4R 只做跳/蹲。** 让 2T4R 参与左右，收益为负。

> 顺带一个与 `AGENTS.md` 硬约束 5 相关的事实：2T4R 的俯仰通道组合存在，
> 但**虚拟通道索引到物理天线高度的映射仍未确定**（`radar-uplink-dev113p-2t4r.md` L106-108），
> 所以"能测高度"还不是已证结论，只是"有通道"。

## 6. 验证方案（设备可用后，约 30 分钟）

**唯一需要回答的问题：双开时 1T2R 的噪声底抬高多少？**

```
A 段：只开 1T2R，空场静置 60 s       → 记 j0..j7 噪底
B 段：只开 2T4R，空场静置 60 s       → 记噪底
C 段：两板同时开，空场静置 60 s     → 记 1T2R 噪底
D 段：两板同时开 + 人在 1 m 做左右   → 看 LANE 命中率是否掉
```

判据（提案，待小组确认）：

| 指标 | 可接受 | 需处理 |
|---|---|---|
| **C 段 1T2R 噪底抬升** | **< 3 dB** | ≥ 3 dB 就要加隔离 |
| D 段左右命中率相对 A 段下降 | < 10 个百分点 | ≥ 10 就要重排安装 |

**安装建议（按性价比）**：

1. **背对背 + 拉开 ≥ 0.5 m**（利用天线方向性，最先做，成本零）
2. 两板之间加**吸波材料**（金属板反射会二次耦合）
3. 让 2T4R 的天线法线**避开** 1T2R 的主瓣方向
4. **不要**指望改频率——硬件固定，改不了
