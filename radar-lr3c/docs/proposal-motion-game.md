## 一、项目定位与一句话

本项目是**基于毫米波雷达的开发应用**：把一个真实毫米波雷达模块接成可用的无接触交互输入设备，本期**初步选定体感小游戏**作为落地载体（题材：跑酷）。

用矽典微 **DEV202H 毫米波雷达（ICL1122，1T2R）** 无接触操作一个跑酷游戏，闭环为：
**雷达采集 → 人体状态识别 → 游戏逻辑 → 计分结算**。

## 二、选题背景与要解决的问题

1. 常见体感交互依赖**摄像头**，存在隐私顾虑与光照限制；
2. **毫米波雷达不采集图像**、不受光照影响、可穿透一定遮挡，适合作为无接触输入；
3. 课程已提供雷达硬件与授权，**无需额外预算**，选题可在两周内做出可演示原型。

## 三、目标与预期成果

**MVP 成功定义**：现场的普通观众能**在无人指导下**站到雷达前，用身体动作完成一局游戏并看到分数。

## 四、技术路线概要

- **数据链路**：DEV202H（ICL1122，24GHz，1T2R）→ **CP2102** USB-UART → 串口 921600 → 官方 Python demo（`data_transfer`）自研解析 → 统一帧 `RadarFrame`。
- **软件架构**：雷达采集层 / 状态识别层 / 事件层 / 游戏逻辑层 / 表现层；层间**唯一耦合点是事件流**（`LANE_LEFT`、`LANE_RIGHT`、`JUMP`、`DUCK`、`CALIBRATED`、`TARGET_LOST`、`TARGET_BACK`），游戏层不直接读串口。
- **识别方法**：**规则法**（阈值 + 滞回 + 最小切换间隔），不引入深度学习；交互范式为**动作触发**（身体移动一次 → 角色切一条道）。
- **硬约束**：帧周期 **129.5 ms（≈7.7 Hz）**，这是全项目体验上限；水平视场 ±45°、垂直波束 ±25°；距离分辨率 ≈0.68 m；速度分辨率 ≈0.05 m/s。
- **演示兜底**：**模拟器模式为 P1 硬需求**（拔掉雷达也能完整演示），现场不允许因设备问题中断。

## 五、关键风险与验证门

| 风险 | 现状与对策 |
|---|---|
| 1T2R **无垂直角通道** → 无法直接测人体高度（跳/蹲） | 跳/蹲**已纳入 MVP**，但**实现路径未定**：路径 A（2T4R 俯仰角测高，首选）/ 路径 B（1T2R 多普勒+距离间接特征，对照与兜底） |
| 2T4R 链路未知 | **P0 验证进行中（10/16 起实验中，结论未出）**：授权、连通、参数、取数、帧周期 |
| 多普勒速度模糊 | chirp 周期 2.02 ms → 最大不模糊速度约 ±1.53 m/s，跳跃可能接近上限，**需实测确认** |
| 进度落后 | 砍功能顺序：难度递增 → 音效动效 → 跳/蹲（仅在验证门均不通过时）；**死保「左/中/右识别 + 完整闭环」** |

**验证门**：**P0**（2T4R 链路）→ **T0**（内置算法探路）→ **T1**（离线特征可分性）→ **T2**（定路径）。门未过之前，跳/蹲不写入「已实现功能」。

## 七、资源需求与合规

- **硬件（已具备）**：DEV202H / ICL1122（1T2R）、2T4R 板、CP2102 转接板；ONELAB v1.5.4.1，Vikey 授权**已确认可用**。
- **软件**：Python（PySide6 / pyqtgraph / pyserial / numpy）、游戏框架待定；**无额外预算**。
- **合规**：厂商官方资料、授权文件（`.lic`）、课程材料**不外传**；雷达数据为**不含图像的人体数据**；全程**本地运行**，不上传数据、不写生产环境、不涉及账号与支付；AI 使用留**决策记录表**。
- **证据**：测试必须带**真值标注**（人体实际位置/动作）方可计入，否则不算测试。
