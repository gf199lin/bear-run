# 雷达 → Bear Run 游戏：插上就能玩

> 状态：**端到端已实机验证**（2026-10-30）。
> 游戏新版：<https://gf199lin.github.io/bear-run/>（含「雷达联调台」`radar-connect.html`）

---

## 1. 怎么用（推荐路径）

**双击项目根目录的 `启动-游戏页面.cmd`。**

它会依次做：

1. 在 8766 起「左右」桥，自动识别雷达串口（1T2R 的 CP2102 优先）
2. 在 8771 用本机 http 托管**新版游戏页**（`bear-run-new/`）
3. 等 8 秒后打开：

```
http://127.0.0.1:8771/?input=radar&radar=ws://127.0.0.1:8766&debug=1
```

页面上点「游客」进入，输入源选「雷达」。

**为什么不用官方 https 页面**：见 §2，HTTPS 页面连 `ws://127.0.0.1` 会被浏览器拦截。

**插拔不用重启**：程序每秒重新枚举串口，拔掉显示「未连接」，插回自动恢复。

## 2. 关键坑：HTTPS 页面连不了 ws://（2026-10-30 现场卡住的原因）

游戏官方站是 `https://gf199lin.github.io/bear-run/`，雷达桥是 `ws://127.0.0.1:8766`。
浏览器按**混合内容**策略直接拒绝，页面报：

```
连接失败 ws://127.0.0.1:8766（code=1006）
本页是 https，浏览器会拦 ws:// —— 用 http 打开本页，或让雷达侧提供 wss://
```

**采用的解法：把同一份源码搬到本机 http 下托管**，页面与 `ws://` 同为 http 源，不再拦截。
不需要证书、不需要改游戏代码。

```bash
python tools\serve_bear_run.py                     # 默认新版 bear-run-new → 8771
set GAME_DIR=bear-run && set GAME_PORT=8770 && python tools\serve_bear_run.py   # 旧版
```

| 页面 | 地址 |
|---|---|
| 游戏（新版） | `http://127.0.0.1:8771/?input=radar&radar=ws://127.0.0.1:8766&debug=1` |
| 雷达联调台 | `http://127.0.0.1:8771/radar-connect.html` |
| 雷达体检台 | `http://127.0.0.1:8771/radar-diagnose.html` |

**新旧版本差异**：仓库 `main` 分支（`v=20261030a`）才有联调台与体检台；
项目内旧的 `bear-run/` 是更早的原型，没有这两个页面，不要拿它排查。

## 3. 双通道：左右 + 上下（8766 / 8767）

游戏支持两条独立 WS，两条都要有人监听：

| 通道 | 端口 | 板子 | 角色 | 启动命令 |
|---|---|---|---|---|
| 左右换道 | 8766 | 1T2R (COM3) | `lr` | `python tools\bear_run_radar_launcher.py --no-open` |
| 上下跳蹲 | 8767 | 2T4R (COM4) | `ud` | `python dual-radar-kit\tools\radar_live_ws.py --port COM4 --ws-port 8767 --role ud` |

两条桥可以同时跑，互不干扰（各自独立进程、独立串口）。

**实测（2026-10-30）**：

```
8766  1T2R  7.7 fps  客户端已接入
8767  2T4R  1.9 fps  客户端=1  zero=-8.69
```

> 8767 只跑通「链路 + 数据格式」，跳/蹲判定精度仍属 P0 未验证路径
> （`docs/jump-duck-verification-plan.md`），且 2T4R 仅 1.9 Hz，手感粗。

## 4. 数据协议

游戏端（`bear-run-new/js/InputSource.js`）连 `ws://127.0.0.1:8766` / `:8767`，接收 JSON：

```json
{
  "ts": 1793350078769,
  "x": 0.0011,
  "height": 0.0,
  "jump": 0.0,
  "crouch": 0.0,
  "confidence": 0.9,
  "raw": {"src":"radar","board":"2t4r","role":"lr","az":-9.39,"zero":-9.41,"n":0}
}
```

- `x`：换道位置电平 `-1..1`，游戏端自己做迟滞判定（`enterThreshold=0.36` / `exitThreshold=0.22`）
- `ts`：采集时间戳（毫秒），页面用它算端到端延迟
- `confidence`：本帧可信度，低于门限游戏端直接丢弃
- 断开后游戏端每 2 s 自动重连

## 6. 延迟：必须知道的数字（2026-10-30 实测）

跑酷游戏对延迟极敏感，实测两板差距是 **9 倍**：

| | 帧间隔 | 帧率 | 传输 | 感知延迟 | 结论 |
|---|---|---|---|---|---|
| **1T2R** | 129 ms | 7.72 Hz | 1 ms | **≈145 ms** | ✅ 可玩 |
| **2T4R** | 527 ms | 1.90 Hz | 1 ms | **≈343 ms** | ⚠️ 延迟尚可，但 1.9 Hz 更新率太粗 |

**传输只占 1 ms，网络和 WebSocket 完全不是瓶颈。**

### 6.1 修掉的一个真问题：平滑按帧算

桥接器原来的角度平滑是 `0.55*prev + 0.45*az`，时间常数 ≈ 1.67 **帧**：

- 1T2R（130 ms）→ 216 ms，还能接受
- 2T4R（527 ms）→ **880 ms**，凭空多出大半秒

已改为**固定 80 ms 时间常数**（按实际帧间隔算 `alpha`），慢帧几乎不做平滑
（慢帧本来也没有抖动可压）。**2T4R 的感知延迟由此从 1317 ms 降到 343 ms。**

### 6.2 帧率是硬限制，改代码解决不了

2T4R 的 527 ms 帧周期由厂商寄存器配置决定（`docs/hardware-baseline.md`）。
要让 2T4R 达到可用帧率，只能**改雷达配置**（减少 chirp 数 / 缩短 frame period），
代价是速度分辨率下降 —— 这属于参数决策，不是代码优化。

**因此：游戏交互一律用 1T2R；2T4R 留给需要俯仰的跳蹲实验。**

## 7. 一个曾经踩过的坑（重要）

2T4R 启动序列的**帧间隔和 ACK 等待时间**必须够：

| 参数 | 失败值 | 成功值 |
|---|---|---|
| `gap` | 0.03 s | **0.05 s** |
| `ack_timeout` | 0.12 s | **0.40 s** |

`gap=0.03 / ack=0.12` 时：37 帧全部发出、回包 36、**但芯片不出流（0 字节）**。
原因是单帧最长 510 B（A32D32），配置写入后芯片需要更长时间消化。

已修正 `radar_source.SerialSource`（`boot_gap` 默认 0.05、`ack_timeout` 0.4），
与独立工具 `radar_boot_2t4r.py --send` 的参数保持一致。

## 8. 常见问题

**Q：页面显示「连接失败 / code=1006」？**
先看是不是用了 `https://gf199lin.github.io/...`。**https 页面连不了 ws://**，改用 §2 的
`http://127.0.0.1:8771/...`。若已用本地页，再确认黑色窗口还开着、日志有 `ws://... 已监听`。

**Q：两块板都插着，为什么用的是 1T2R？**
浏览器打开后看日志里的 `自动识别到雷达串口 COMx`。默认优先命中 COM3（1T2R）。
要用 2T4R：`--port COM4`。

**Q：画面里角色一直贴在左边 / 换道飘？**
是零点标定问题，不是链路问题。启动后有约 3 秒标定期，期间请**站在正前方中间别动**。
日志里 `zero=` 就是标定出的中道角度；如果它明显偏离 0（例如 30 多），说明标定时人在偏侧，
或雷达安装朝向偏了，需要重新标定 / 调整底座朝向。

**Q：联调台图里那条紫线为什么是虚线？**
是绘制样式，不是故障。`radar-connect.html` 里 crouch 曲线被指定为虚线 `[5,4]`
（与 jump 的橙色实线区分开）；黄虚线是 `±enterThreshold` 车道阈值线。若紫线平贴在 0，
说明该路数值恒为 0、没采到有效动作。

**Q：跳/蹲没反应？**
默认 `--role lr` 只驱动左右。跳/蹲仍属 P0 未验证路径（`docs/jump-duck-verification-plan.md`），
要试可另起 8767 上下桥（§3），但不保证手感。
