## 3. 被测系统与口径

### 3.1 硬件与信号

| 项 | 值 | 来源 |
|---|---|---|
| 模块 | DEV202H（ICL1122，**1T2R** ⇒ **2 个 RX**） | `AGENTS.md`；`docs/hardware-baseline.md` |

| 距离门数 / 带宽 | `BINS = 8` / `BANDWIDTH = 220e6` | `radar_dsp.py` L19、L22 |
| 距离分辨率 | `RANGE_RES = C/(2*BANDWIDTH)` = **0.6813 m** | `radar_dsp.py` L25 |
| 最大距离 | `MAX_RANGE = RANGE_RES*BINS` = **5.45 m** | `radar_dsp.py` L26 |
| 最大不模糊速度 / 速度分辨率 | **1.535 m/s** / **0.0480 m/s** | `radar_dsp.py` L27、L28 |
| 水平视场 / 垂直波束 | ±45° / ±25° | `AGENTS.md` |
| **垂直（俯仰）角** | **不可用**（`VertAngleInfo` 无通道组合）⇒ 无法直接测人体高度 | `AGENTS.md` |

**门换算**（全文统一）：距离 `r` 落在距离门 `j = round(r / 0.6813 − 0.5)`，门中心 = `(j + 0.5) × 0.6813`。
例：j=0→0.341、j=1→1.022、j=2→1.703、j=3→2.385、j=4→3.066、j=7→5.109 m。
代码里的实际分带是 `j = int(r // RANGE_RES)`（`radar_actions.py` `_gate_of`），
两者对「门心」的定义一致，偏差 ≤ 半门，不影响本文任何结论。

### 3.2 识别器的两条判据

| 判据 | 规则 | 常量 |
|---|---|---|
| `delta`（**出厂默认**） | 窗内横向位移（前段→后段） | `CRIT_DEFAULT = 'delta'`（L168） |
| `drift`（本项目新增，**非默认**） | `d = px − base`；`d ≤ −1.30` → `LANE_LEFT`；`−1.30 < d ≤ −0.25` → `LANE_RIGHT`；`base` = 近 `rest_win` 秒 `px` 的**中位数** | `REST_WIN_DEFAULT=60.0`（L169）、`DRIFT_LEFT_DEFAULT=1.30`（L170）、`DRIFT_RIGHT_DEFAULT=0.25`（L171） |

- `drift` 的缓冲**刻意不随 `TARGET_LOST` 清空**（人退场再回来时参考系仍有效）；样本 < 8 帧时**不猜、不出事件**。
- **`base` 需 10~20 s 静息预热**才收敛（`rest_win=60 s` 时）；开局即动会拿不到可靠基线 `[样本内]`。

### 3.3 点选择（这是全篇最容易误引的一处）

| 项 | 值 | 来源 |
|---|---|---|
| `TOP_K_DEFAULT` | **0 = 全保留** ⇒ 默认 `px` = 带内**幅值加权质心** | `radar_actions.py` L147 |
| 最强点实现 | `if self.top_k > 0 and len(sel) > self.top_k: sel = sorted(sel, key=pa)[:self.top_k]` | `radar_actions.py` **L635-636** |
| ⚠ 配套要求 | **`top_k=1` 时必须同时给 `min_pts=1`**，否则每帧都被判成丢失 | `radar_actions.py` L834（CLI 提示） |

> **«质心» 与 «最强点» 是两个不同的统计量，抗噪性完全不同。** 任何「命中 x/10」的说法必须先声明用的是哪一个。

### 3.4 判分口径（三个代码路径必须区分）

| 路径 | 实现 | 用途 / 出处 |
|---|---|---|
| **产线** `ActionRecognizer`（`analyze_file`，`radar_actions.py` L717） | `px` 默认质心，`top_k=1` 才用最强点；`cfar=2.6`、`min_snr=7.0`、`min_range=0.681`；`tol=±0.5 s` | **§5.1 的 2×2 矩阵、§5.2/§5.3 全部出在这条路径** |
| `label_tool.py --compare` | **自带** `compare(records, labels, tol=0.45)`（**L209**），**不是** `ActionRecognizer` | §7.25.3「换带 4 组全 0」出在这条路径（⚠ **不得**与产线成绩混用） |

判分规则（`score`，`regress_drift.py`）：
- **命中**：预测事件时刻落在真值窗 `[t_start − tol, t_end + tol]` 内，且类别（左/右）正确；
- **误报**：预测事件落在**任何**真值窗之外；
- 容差无关性已验证：`tol` 取 0.00 / 0.25 / 0.50 s，命中数与误报数完全相同 ⇒ **不是被容差撑起来的** `[已执行·可复现]`（§7.27.3）。

### 5.1 2×2 矩阵：**「相对判据 + 最强点」必须同时成立**（`[已执行·可复现]`，§7.28.2）

### 5.5 置换检验（`[已执行·可复现]`，§7.27.3）

**为什么要做**：10 条真值里 LEFT 全在 6.9~45.6 s、RIGHT 全在 52~91 s，**两半完全不重叠**
⇒ 必须排除「前半段=LEFT / 后半段=RIGHT」这类**时间巧合**。方法：把 10 个真值窗随机重新摆位 N 次，重算命中总数的零分布。

| 文件 | 观测命中 | 零分布 中位 / p95 / 最大 | p | N |
|---|---|---|---|---|
| `seg_01.25` | 8（本口径） | 1 / 4 / 4 | **≤ 0.0005** | 2000 |
| `seg_01.50` | 4 | 1 / 2 / 5 | **≤ 0.0050** | 200 |

**p 值的分辨率下限（必读，否则会被读成自相矛盾）**：`perm_p` 用 `p = (ge+1)/(n+1)`，

### 6.1 站位自检：解开「j=2 之谜」（`[已执行·可复现]`，§7.25.2）

| 1.00 m | j=2 | 1.703 m | +0.703 m | **97.0%** | j=2 ✅（第 33 帧） |

- 「偏移在 0.32~0.70 m 之间跳」**不是异常**，单一参数即可解释全部四站：

  ⇒ 10/15 的「带内 0.2 点/帧」不是环境反常，而是 **`BAND_DEFAULT=(0.70,1.35)` 恰好圈在人不在的门上**。
- **偏置 c 的来源 `[未验证]`**：「站位从雷达哪一面量」的测量约定差异 vs 雷达内部固定延迟/门索引约定。
  **待用户确认测量基准**；建议用已知距离金属标靶扫 0.50→2.00 m 做正式距离标定。
- j=0 近场泄漏：占用率 **99~100%**、**8.29 点/帧**、功率占比 **0.80% → 46.9%**（人越远占比越高）
  ⇒ `min_range = 0.681` 屏蔽**仍然必要**。（10/18 独立复现：j=0 占窗口内检出 84~92%，§7.31.5。）

### 6.2 全文件横向时间线：方向信息在「绝对水平」（`[已执行·可复现]`，§7.26.2/§7.26.3）

**⇒ `seg_01.25` 上，RIGHT 窗与静息段在符号上**完全无法区分**（都 +0.6~+1.2）。**

LEFT 窗的符号序列恒为「先正后负」，翻号点稳定滞后（+0.39 ~ +1.94 s）——

### 6.3 灵敏度：真正的硬上限（`[已执行·可复现]`，§7.25.4、§7.25.5）

- **横向信噪比 = 0.25×**：真实左移位移量 `|Δpx| = 0.291 m`，而同段噪声基线 `p95(|Δpx|) = 1.144 m`
  ⇒ 工具判词（原文）「信号与噪声不可区分 → 不给出 `angle_sign` 结论……翻符号没有意义」。
- **离线全网格搜索**：9 档 DSP（`cfar_scale` ∈ {1.2, 1.8, 2.6} × `min_snr` ∈ {0, 1, 3, 5, 7} dB）
  × 5 个距离带 × 2 个真值文件 = **90 组**，再关掉 MTI（`remove_clutter=False`）跑一遍 = **累计 180 组**：
  - `med_n`（带内点数中位数）**只出现过 2.0 / 3.0 / 4.0**；即使门限压到最松（`cfar=1.2, min_snr=1.0`，
    `occ` 已达 0.82），`med_n` 也只有 4 ⇒ **点数是硬件几何的上限**（2 RX 角度分辨率 + 0.68 m 距离分辨率 + 目标 RCS）；
  - **SNR 与占用率严格反向**：SNR 全局最大仅 1.21，而该组召回 **0/5 + 0/5**；
    **SNR 前 10 名全部是召回 0 的配置**；门限从 7.0 降到 0.0，真实位移只涨 22%（0.129→0.157 m）
    而噪声涨 150%（0.177→0.442 m）⇒ **信号不随门限增长，噪声增长**；
  - **没有任何一组满足「召回 ≥3 且误报 ≤10」**（38/90 组召回全 0；其余最高精确率仅 8.6~10.8%）；
  - 关掉 MTI 同样无效（甚至部分配置检出**下降**：静态杂波抬高 CFAR 噪声估计 ⇒ 门限升高 ⇒ 检出更少，
    即 **MTI 在这一点上是「帮」而不是「害」**）。
- **同源的现场证据（10/18）**：静息时**人所在门只占窗口内检出的 9% / 3% / 2%**（1.00/1.35/1.70 m），

### 6.5 根因假设（**`[提案·未验证]`** —— 明确不得当结论引用，§7.26.6）

**已测事实**：静息 `x ≈ +1.12 m`（θ≈+40°，`r`=1.70 m 门中心）；水平视场 ±45°；1T2R ⇒ 2 RX。
**假设**：静息站位本身已落在 θ≈+40°（**离轴 40°**，紧贴 ±45° 边缘）。于是
- **向左移** → θ 朝 0° 走，几何变好 ⇒ 能稳定读到 θ≈−42°；
- **向右移** → θ 压向/越过 +45° 边界 ⇒ 2 元阵相位差接近/超过 π ⇒ **折叠/缠绕**，读数被折回 +20~30°
  ⇒ 与静息边缘读数**混在同一区间**，故 RIGHT 与「无动作」不可分，且 1.50 m 下 LEFT 也丢检。

该假设能**同时解释**：RIGHT 与静息不可分、LEFT 翻号滞后、±42° 堆积、跨站位不对称、`--mode sign` 的 SNR 0.25×。
**不能主张**：它**尚未被验证** —— 需要**横向位置扫描真值**才能定案（§9 第 3 项）。

### ⚠ AC-3 的结构性冲突（**需要小组决策，本报告不判定**）

- 验收表 AC-3 备注明写：「理论下限受 129.5 ms 帧周期约束，**300 ms 已含 1–2 帧** + 处理开销」。
- 但本报告推荐配置所用的状态机要求 **`min_dwell = 3` 帧同类**才发事件 ⇒ **雷达侧固有确认延迟 ≈ 3 × 129.5 = 388.5 ms**，
  **已超出 300 ms 预算**（若按「确认需 3 帧 ⇒ 2 个帧间隔」算为 259 ms，则在预算内边缘）。
- ⇒ **提案（待小组确认）**：① 明确 AC-3 的延迟**起点**（建议定义为「动作在雷达可判时刻 → 游戏画面响应」，
  即**排除人类反应与起步时间**）；或 ② 把 `min_dwell` 降到 2（代价：滞回减弱、误报可能上升，**尚未实测**）。
- 参考实测（§7.27.5 第 7 条）：事件相对**提示音**的延迟 = RIGHT 1.16~1.68 s / LEFT 1.55~2.33 s，
  其中**绝大部分是人类反应与起步时间**（独立测得到位时刻 0.4~1.9 s）；`min_dwell=3` 的雷达侧贡献仅 0.39 s。

**其余 AC 简况**：AC-4（游戏帧率）、AC-5（校准）、AC-6（丢失恢复）、AC-7（模拟器兜底）、AC-8（无指导可玩）、
AC-9（回放一致性）**与本报告基本无关或仅间接相关**（AC-5 的前置「0.5–1.5 m」与本报告的站位结论一致；
AC-7 的兜底路径中**「真实录制回放」已跑满验证（§7.32）**，「合成模拟器」仍只做到「启动不崩、选带正确」，
其换道事件 `[未验证]`）。
