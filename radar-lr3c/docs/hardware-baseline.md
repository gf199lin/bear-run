## 1. 硬件清单

| 项 | 型号 / 参数 | 证据 |
|---|---|---|
| 雷达模块 | **DEV202H**（ONELAB DEV 系列） | `Radar_Config.ini` → `ModuleName = DEV202H` |
| 雷达 SoC | **ICL1122**，24GHz，**1T2R**（1 发 2 收） | `Radar_Config.ini` → `ChipName = ICL1122`；产品手册 P8、P36 |
| 模块 MCU | ARM Cortex-M4 | 产品手册 P36 |
| 天线 | 14 dBi；6dB 波束 水平 ±45°、垂直 ±25° | 产品手册 P36 |
| 模块尺寸 | 34 mm × 15 mm，UART，1.27 mm 排针 | 产品手册 P36 |
| USB 转串口 | **CP2102**（Silicon Labs USB-UART 桥） | 用户确认；工具包内含 `CP210x_Universal_Windows_Driver` |
| 上位机工具 | ONELAB 毫米波传感器开发工具 v1.5.4.1 | 项目目录 |

> 注：接线图 `接线.jpg` 中出现的模块丝印为 `D127`，**不是**本组设备，勿作为依据。

### 关键含义

- **1T2R = 2 个接收通道**，因此可以做方位角（AoA）测量，能区分目标的左右方位；
- 但 14 dBi 高增益天线对应窄波束（水平 ±45° / 垂直 ±25°），**玩家必须大致正对模块**，大范围横向跑动会离开视场；
- 模块自带 M4 MCU，算法可就地运行，不必把原始数据全部上传上位机。

## 4. 由配置推导的能力边界

| 指标 | 计算 | 结果 | 设计含义 |
|---|---|---|---|
| 帧率 | 1 / 0.1295 s | **≈ 7.7 Hz** | 每 ~130 ms 才更新一次；只适合慢速动作，**不要设计快速反应玩法** |
| 距离分辨率 | c / (2B) = 3e8 / (2×220e6) | **≈ 0.68 m** | 无法精细定位手部；**避免"精确触碰/定位"玩法** |
| 速度分辨率 | λ / (2T) ，λ=12.43 mm，T=64×2.02 ms | **≈ 0.05 m/s** | 多普勒极灵敏，**"挥手/移动快慢"是最可靠信号** |
| 水平视场 | 6dB 波束 | **±45°** | 玩家需正对模块，左右方位可分 |
| 垂直视场 | 6dB 波束 | **±25°** | 对上下动作容忍度低，安装高度需固定 |

**一句话总结能力画像**：擅长「有无 / 快慢 / 方向 / 远近粗分」，不擅长「精细位置」。

## 5. ONELAB 内置算法驱动（重要机会）

`Radar_Config.ini` 中 `DriverType` 的可选值：

```
#DriverType = transfer, algorithm_mtt, algorithm_vs, algorithm_abd, algorithm_gr
DriverType = data_transfer
```

| 驱动 | 含义 | 对体感游戏的价值 |
|---|---|---|
| `data_transfer` | 数据透传 | 自行取数做算法（当前模式） |
| `algorithm_gr` | **手势识别** | 可直接调用，快速做出可演示玩法 |
| `algorithm_mtt` | 多目标跟踪 | 多人/多目标场景 |
| `algorithm_vs` | 生命体征 | 呼吸/心跳，偏静息场景 |
| `algorithm_abd` | 异常行为检测 | 跌倒/异常，偏安防巡检场景 |

配置文件中另有 `[GESTURE]` 段（`MoveWinLen = 12`、`UD_SpeedMin = 0.400`），佐证手势算法已内置于工具。

**含义**：小组不必从零训练模型即可先做出可演示原型；`algorithm_gr` 是最短路径。

## 6. 数据采集与导出

- 工具支持数据保存（`[DATASAVE]`）：可导出并设置上限、路径（默认 `C:\RadarData`）；
- `DataType` 可选：`io_raw`、`ds_raw`、`1dfft`、`2dfft`、`2dfft_peak`、`has_raw`、`has_rdm`、`has_fft`；
- `RawSampleRate` 可选 1/2/4/8，`RawSampleSize` 可选 64/128/256/512/1024。

**含义**：自采数据集完全可行，且可导出原始 ADC 数据用于自研算法。
