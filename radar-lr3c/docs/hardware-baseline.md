> 注：接线图 `接线.jpg` 中出现的模块丝印为 `D127`，**不是**本组设备，勿作为依据。

### 关键含义

- **1T2R = 2 个接收通道**，可以做方位角（AoA）测量，区分目标左右方位；但它**没有垂直（俯仰）角通道**（`VertAngleInfo` 复合段为空），**无法直接测量人体高度**；
- **2T4R = 4 个接收通道**，原则上可同时做方位 + 俯仰二维角 → **可直接测人体高度**，是「跳起 / 蹲下」更可靠的实现路径；但其链路、授权、波形参数**正在验证**（10/16 起实验中，结论未出），须待 P0 收口；
- 但 14 dBi 高增益天线对应窄波束（水平 ±45° / 垂直 ±25°），**玩家必须大致正对模块**，大范围横向跑动会离开视场；
- 模块自带 M4 MCU，算法可就地运行，不必把原始数据全部上传上位机。

## 3. 当前雷达配置（摘自 `Radar_Config.ini`）

| 参数 | 值 |
|---|---|
| 起始 / 终止频率 | 24.015 GHz → 24.235 GHz（**带宽 220 MHz**） |
| 发射功率 | `TxPoutdBm = 6.00` |
| 接收增益 | `RxGaindB = 25.50, 25.50` |
| Chirps / 帧 | 64 |
| 帧周期 | `FrameTimeUS = 129500`（**129.5 ms**） |
| 单 chirp 采样 | `SamplesPerChirp = 8`（`RawSampleSize = 256`） |
| 1D FFT | 计算长度 256，输出 8 列 × 64 行 |
| 2D FFT | 计算长度 64 |
| 角度阵元间距 | `HorzAngleInfo = 6.250,...`（6.25 mm ≈ λ/2） |
| 输出数据类型 | `DataType = 1dfft` |
| 当前驱动模式 | `DriverType = data_transfer`（纯数据透传） |
| 数据保存 | `SaveData = 0`（当前关闭）；`DataPath = C:\RadarData`；上限 500 MB |

> 以上为 **1T2R（DEV202H）** 的实测配置。**2T4R（DEV113P）** 的上行格式已实测破解
> （见 [`radar-uplink-dev113p-2t4r.md`](radar-uplink-dev113p-2t4r.md)），
> 其波形段已从**同一份 `Radar_Config.ini`（ONELAB 上位机写出的运行配置）**读出并收口（10/19）：
>
> | 参数 | 1T2R（已核实） | 2T4R（现状） |
> |---|---|---|
> | 帧周期 | 129.5 ms（7.7 Hz） | **≈520.84 ms（1.73 雷达帧/s）** ← 实测，比 1T2R 慢 4.4 倍 |
> | 距离 bin 数 | 8（SamplesPerChirp=8） | **32**（实测） |
> | Chirps / 帧 | 64 | **64**（实测） |
> | 起始→终止频率 | 24.015→24.235 GHz | **24.001→25.000 GHz** |
> | 带宽 / 距离分辨率 | 220 MHz / **0.6813 m** | **999 MHz / ≈0.150 m**（`c/2B`） |
> | 中心频率 | 24.125 GHz | **24.5005 GHz** |
> | 速度量程 / 分辨率 | ±1.535 / 0.0480 m/s | **±0.376 / 0.01175 m/s**（`λ/(4Tc)`、`λ/(2N·Tc)`） |
> | 水平阵元间距 | 6.250 mm | **5.900 mm**（`HorzAngleInfo`） |
>
> **证据等级**：上表 2T4R 一列为**厂商配置推导 + 1T2R 交叉验证**，**非卷尺实测**。
> 交叉验证做法：同一组公式代回 1T2R 一列，得 0.6813 / 24.125 GHz / ±1.535 / 0.0480 / 6.250 mm，
> 与代码里既有模块常量 **5 项逐字吻合** ⇒ 换算链可信。
> **建议补一次卷尺点检**：已知距离（1.0/1.5/2.0/2.5/3.0 m）逐点采 5 s，看距离谱峰值 bin 是否
> 落在 `round(r/0.15)`；两种假设（0.15 vs 0.68 m）会落在完全不同的 bin，一次实验即可区分。
>
> ⚠️ **不要用 `MTT_RangeResolution`（=125 mm）当 range_res**：1T2R 配置里它同样是 125，
> 而 1T2R 真实值是 0.6813 m ⇒ 该字段与真实带宽无关（疑似上位机算法遗留值）。
>
> ⚠️ **2T4R 的 1.73 Hz 会直接改变体验预算**：当前全部交互设计建立在 7.7 Hz 之上，
> 若最终选 2T4R 做主控，必须重新评估「动作触发」的响应上限（见 §4 与 PRD）。
> 另：2T4R 速度量程只有 **±0.376 m/s**（1T2R 的 1/4），**快速挥手会速度混叠** ——
> 若用多普勒做特征，必须重新定标动作速度窗口。
>
> ✅ 已据此把网页 `cfg.range_res` 由 0.6813 改为 **0.15**、`cfg.range_res_verified` 改为 **true**
> （「距离轴未标定」提示消除），并把 `min_range` 默认改为本板型 1 个距离单元（2T4R = 0.15 m）。
>
> 📷 **1T2R 站位自检（我方自测截图 `../数据回放/2.png`，2026-10-15）**：站位 0.70 / 1.00 / 1.35 / 1.70 m
> → 距离谱峰依次落 bin **1 / 2 / 2 / 3**，中位距离 `r_med` = 1.022 / 1.703 / 1.703 / 2.385 m。
> **这是 `range_res ≈ 0.6813 m` 的独立实测佐证**：`r_med` 恰好等于 0.6813 × {1.5, 2.5, 3.5}
> （即「真实距离 / 0.6813 后向下取整 + 0.5」的 bin 中心），与「配置推导 + 交叉验证」的结论一致。
> 同批数据还暴露两件**尚未解释**的事，**不得当作已解决**：
> ① 系统偏移 **0.32~0.70 m 且不恒定**；② 带内检出率随距离明显下降（83.9% / 97.0% / 69.5% / 27.3%）。
> ⚠️ 该截图是 **1T2R** 的；**2T4R 的同类点检（卷尺真值）尚未执行** —— 用户 10/19 无法采集，**该项挂起**。

## 4. 由配置推导的能力边界

| 指标 | 计算 | 结果 | 设计含义 |
|---|---|---|---|
| 帧率 | 1 / 0.1295 s | **≈ 7.7 Hz** | 每 ~130 ms 才更新一次；只适合慢速动作，**不要设计快速反应玩法** |
| 距离分辨率 | c / (2B) = 3e8 / (2×220e6) | **≈ 0.68 m** | 无法精细定位手部；**避免"精确触碰/定位"玩法** |
| 速度分辨率 | λ / (2T) ，λ=12.43 mm，T=64×2.02 ms | **≈ 0.05 m/s** | 多普勒极灵敏，**"挥手/移动快慢"是最可靠信号** |
| 水平视场 | 6dB 波束 | **±45°** | 玩家需正对模块，左右方位可分 |
| 垂直视场 | 6dB 波束 | **±25°** | 对上下动作容忍度低，安装高度需固定 |
| 垂直角测量 | 1T2R：`VertAngleInfo` 复合段为空 | **1T2R 不可用** | **无法直接测人体高度**；跳 / 蹲 需走 2T4R 二维角或间接特征 |
| 垂直角测量（2T4R） | `VertAngleInfo = 5.900,1.000,0,2;5,2,3,`（**非空**） | **通道组合存在** | 但虚拟通道 `5,2,3` → 物理天线高度的映射**未确定**，**不得据此宣布「可测人体高度」** |

**一句话总结能力画像**：擅长「有无 / 快慢 / 方向 / 远近粗分」，不擅长「精细位置」。

## 5. ONELAB 内置算法驱动（重要机会）

`Radar_Config.ini` 中 `DriverType` 的可选值：

```
#DriverType = transfer, algorithm_mtt, algorithm_vs, algorithm_abd, algorithm_gr
DriverType = data_transfer
```

| 驱动 | 含义 | 对体感游戏的价值 |
|---|---|---|
| `data_transfer` | 数据透传 | 自行取数做算法（当前模式） |
| `algorithm_gr` | **手势识别** | 可直接调用，快速做出可演示玩法 |
| `algorithm_mtt` | 多目标跟踪 | 多人/多目标场景 |
| `algorithm_vs` | 生命体征 | 呼吸/心跳，偏静息场景 |
| `algorithm_abd` | 异常行为检测 | 跌倒/异常，偏安防巡检场景 |

配置文件中另有 `[GESTURE]` 段（`MoveWinLen = 12`、`UD_SpeedMin = 0.400`），佐证手势算法已内置于工具。

**含义**：小组不必从零训练模型即可先做出可演示原型；`algorithm_gr` 是最短路径。

## 6. 数据采集与导出

- 工具支持数据保存（`[DATASAVE]`）：可导出并设置上限、路径（默认 `C:\RadarData`）；
- `DataType` 可选：`io_raw`、`ds_raw`、`1dfft`、`2dfft`、`2dfft_peak`、`has_raw`、`has_rdm`、`has_fft`；
- `RawSampleRate` 可选 1/2/4/8，`RawSampleSize` 可选 64/128/256/512/1024。

**含义**：自采数据集完全可行，且可导出原始 ADC 数据用于自研算法。
