# 跳 / 蹲数据审计：17 轮 2T4R 数据为什么训不出识别

> 日期：2026-11-02
> 数据：`data/vertical/`（11 个会话，其中 7 个含可用 `pitch_seq`，共 17 轮）
> 复现：`python tools\eval_jumpduck_offline.py`
> 机器可读报告：`outputs/jumpduck-offline-eval/report.md` / `report.json`

---

## 1. 结论（一句话）

**这批数据能证明「有没有做动作」，但不能证明「是跳还是蹲」。**
任何在这批数据上训出来的方向分类器都接近随机，不应接入游戏，也不应写成「已验证」。

## 2. 数据长什么样

| 会话 | 轮数 | 原 verdict | 说明 |
|---|---|---|---|
| 20261029-200823 / 200943 / 201518 | 3×3 | no_signal | 早期格式，只有距离质心 `seq`，无 `pitch_seq`，未纳入 |
| 20261029-203550 | 1 | weak | 纳入 |
| 20261029-204501 | 1 | weak | 纳入 |
| 20261029-205207 | 3 | same | 纳入 |
| 20261029-210547 | 3 | same | 纳入 |
| 20261029-213237 | 3 | weak | 纳入 |
| 20261029-213458 | 3 | weak | 纳入 |
| 20261029-215347 | 3 | ok | 纳入（**唯一被判 ok 的会话，LOSO 只有 1/6 命中**） |
| 20261029-220709 | 3 | — | 空数据（无 `pitch_seq`） |

每轮 5 段：`base1 → jump → base2 → duck → base3`。
基线在整轮内从 −22° 漂到 −50°，说明**安装高度/朝向在会话之间变过**，
跨会话评估必须按会话切分，否则会把「换了个安装高度」当成「学会了」。

## 3. 段均值：方向直接是反的

用 `pitch_mean`（段均值）判跳蹲：

| 指标 | 值 |
|---|---|
| JUMP 相对基线 | +0.8°（范围 −9.3 ~ +9.6） |
| DUCK 相对基线 | −2.0°（范围 −11.6 ~ +5.3） |
| 跳 − 蹲 分离 | **+2.8°** |
| 17 轮里方向颠倒 | **6 轮** |

这是 `vertical_probe.py` 判 `same / weak / no_signal` 的直接原因。

## 4. 段内极值：看着能分，其实不行

| 统计量 | JUMP | DUCK |
|---|---|---|
| 段内最大偏离 `hi` | 均值 **+18.1°**，最小 +6.4° | 均值 **+14.5°**，最小 +5.6° |
| 段内最小偏离 `lo` | 均值 **−22.8°**，最大 −4.2° | 均值 **−22.3°**，最大 −7.0° |

这两列几乎一样。原因是动作本身是双向的：

- **跳** = 先预蹲（向下）→ 起跳（向上）→ 落地（向下）
- **蹲** = 下蹲（向下）→ 站起（向上）

所以「跳段只看 max、蹲段只看 min」得到的 +18.1 / −22.3 是**单侧命中率**，
不是分类准确率。`tools/jumpduck_detector.py` 开头写的
「17 轮实测全部命中」正是这种单侧统计，容易被误读成「分类全对」。

## 5. 多特征 + 留一会话验证

13 个特征：`hi / lo / mean / std / hi_norm / lo_norm / skew / maxdiff /
sum_absdiff / range / frac_above / peak_bin / prof_entropy`。

| 评估方式 | 结果 |
|---|---|
| 单特征最好（`sum_absdiff`） | 61.8%（13 个里挑最好，属多重比较） |
| **多特征 LOSO** | **58.8%（20/34），Wilson 95% CI 42.2% – 73.6%** |
| 随机基线 | 50.0% |
| 逐会话最差 | 215347：1/6（该会话原 verdict 是 `ok`） |

置信区间下界 42.2% **低于 50%**，即无法证明方向可分。

两点特征在两类上的均值差是 **0.00**：

- `peak_bin`（峰门）：JUMP 和 DUCK 都是 +1.00
- `dist_cen`（距离质心）：JUMP 和 DUCK 都是 +2.30

## 6. 滑窗训练（与实时同口径）

把每段切成 3 帧滑窗，真实数据得到 518 个样本：

| 配置 | 结果 |
|---|---|
| 三类（NONE/JUMP/DUCK） | 41.4%，动作召回 5%~7%（模型退化成全判 NONE） |
| **二类（JUMP/DUCK）+ 门限判静止** | **55.8%** |
| 7 折逐会话 | 18% ~ 69%（方差极大） |
| 合成可分数据（跳 +15° / 蹲 −15°） | **100%（证明管线无 bug）** |

最后一行是重点：**换一份可分的数据，同一套代码能学到 100%**。
所以 55.8% 不是代码问题，是数据里没有方向信息。

## 7. 三个根因

1. **帧率**：2T4R 帧周期 527 ms（1.9 Hz），跳一次只采到 1–2 帧。
   动作的上升/下降沿直接被欠采样抹平。
2. **只有两元相位差**：采集只算 `rx0-rx1`（灵敏度 1×）。
   2T4R 是 4 元竖排阵列，`rx0-rx3` 灵敏度 3×，且可做 DBF 俯仰谱。
3. **原始帧丢了**：`result.json` 只存 `pitch_seq` / 段均剖面。
   想换基线、换距离带、换多普勒重算，全部无从下手。

## 8. 下一步（按性价比排序）

| 步骤 | 做什么 | 验收 |
|---|---|---|
| 1 | 用 `tools/jumpduck_capture.py` 重采，**保存原始帧** | `frames.npz` 存在且帧数 > 100/轮 |
| 2 | 4 元 DBF 俯仰谱替换两元相位差 | 同一批数据上，俯仰谱峰的信噪比高于相位差 |
| 3 | 提高帧率（改 chirp 数 / frame period）或改走 1T2R 多普勒 | 帧周期 < 250 ms |
| 4 | 多人、多安装高度重采 ≥ 5 个会话 | LOSO 置信下界 ≥ 60% |

**门槛**：多特征 LOSO 置信区间下界 ≥ 60%，且用**新会话**复测通过，
才允许接进游戏演示；否则只能作为实验通道。

## 9. 复现命令

```bash
python tools\eval_jumpduck_offline.py
python tools\train_jumpduck.py            # result.json → models/jumpduck.json
python tools\train_jumpduck.py --data data\jumpduck\<时间戳>   # 重采后的原始帧
```
