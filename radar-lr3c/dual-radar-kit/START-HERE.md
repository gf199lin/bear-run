# 双雷达联调：一台管左右，一台管上下

> 目标：**第一台雷达**只负责左右（`x` → 换道），**第二台雷达**只负责上下（`jump` / `crouch` → 跳 / 滑铲）。
> 两台各连各的 WebSocket，互不影响：一台掉线，另一台照常出动作。

---

## 0. 先看清楚分工

| | 第一台（左右） | 第二台（上下） |
|---|---|---|
| 负责字段 | `x` | `jump`、`crouch`、`height` |
| 桥接器端口 | `--port 8766` | `--port 8767` |
| 联调台位置 | 上面那张"左右雷达"卡片 | 勾选"再加一台雷达"后出现的第二张卡片 |
| 游戏 URL 参数 | `radar=ws://本机:8766` | `radar2=ws://本机:8767` |

两台发**同一种完整帧格式**即可（`{ts,x,height,jump,crouch,confidence}`），
游戏会按角色裁剪：第一台只看 `x`，第二台只看 `jump/crouch`，所以不会互相抢动作，桥接器也不用改。

---

## 1. 最快路径：先用假雷达把流程走通（不用真雷达，3 分钟）

这一步验证你的电脑、解压出来的页面、两个端口都没问题。

**窗口 A**：在解压出来的目录里执行

```powershell
cd .\tools
py fake_radar_ws.py --port 8766 --channels lr --port2 8767 --channels2 ud
```

看到两行"已监听"就说明两台假雷达起来了（8766 只出左右，8767 只出上下）。

**再用 Chrome 打开** `radar-connect.html`（双击即可，建议 Chrome / Edge）：

1. 第一条输入框填 `ws://127.0.0.1:8766`，点它右边的「连接」
2. 勾选「再加一台雷达：第一台管左右，第二台管上下」
3. 第二条输入框填 `ws://127.0.0.1:8767`，点「连接」
4. 两行状态都变成绿色「已连接」，两张数值卡都开始滚数字 → 流程通了

此时：上面那张卡的 `x` 在 -0.7 ~ 0.7 之间来回动（假雷达在模拟左右走），
下面那张卡的 `jump` 每 10 秒跳一次 1.0。

> 关掉窗口 A 之前，先在联调台点「断开」，或者直接关窗口也可以，联调台会显示"已断开"。

## 2. 接真雷达：两个窗口，两个端口

**关键：两台桥接器必须用不同 `--port`；两台雷达的数据也不能混进同一个 UDP 端口。**

### 2.1 第一台（左右）

```powershell
cd .\tools
py radar_bridge.py --from udp --udp-port 8888 --port 8766 --print-sample
```

### 2.2 第二台（上下）—— 新开一个 PowerShell 窗口

```powershell
cd .\tools
py radar_bridge.py --from udp --udp-port 8889 --port 8767 --print-sample
```

注意 `--udp-port` 两行不一样（8888 / 8889）。如果两个雷达都往 8888 发，数据会混在一起，分不开。

**如果厂商软件不让改发送端口**，两种办法：

- 让两台雷达接**不同网卡 / 不同网段的电脑**，用 `--udp-host 192.168.1.10` 指定各自监听的那块网卡地址；
- 或者干脆**用两台电脑**，各自跑一份桥接器（一台 `--port 8766`，另一台 `--port 8767`），联调台里第二台填对方的 `ws://对方IP:8767`。

其他雷达类型（TCP / HTTP / 命令行）把 `--from` 换掉即可，`--port` 的规则不变：

```powershell
py radar_bridge.py --from tcp --tcp 192.168.1.50:9000 --port 8767
py radar_bridge.py --from http --http http://127.0.0.1:8080/api/target --port 8767
```

### 2.3 先分别自检，别急着开联调台

```powershell
py check_radar.py ws://127.0.0.1:8766
py check_radar.py ws://127.0.0.1:8767
```

两个都出现"收到 N 帧"这一级的结果，再去联调台连。

## 3. 在联调台里连两台

打开 `radar-connect.html`：

- **第一张卡（左右）**：填 `ws://127.0.0.1:8766` → 「连接」
  看 `x`：人往左走变负、往右走变正；站着不动接近 0。
- **勾选「再加一台雷达」** → 出现第二张卡
- **第二张卡（上下）**：填 `ws://127.0.0.1:8767` → 「连接」
  看 `jump`：起跳时冲到 1.0 左右；`crouch`：下蹲时冲到 1.0 左右。

两张卡各有自己的状态点和「连接 / 断开」按钮，**互不牵连**：
断开第二台，第一台仍然连着，页面顶部会提示"上下雷达没连上，进游戏后只有左右"。

底部波形图：**蓝线 = 左右 `x`，橙线 = 上下 `jump`，紫虚线 = 上下 `crouch`**。
三条线同时有反应，就说明两路都在正常工作。

页面下方还有两个自检按钮：

- **静息误报自检**：10 秒内站着别动，看跳/蹲有没有被误触发（双雷达模式下看的是第二台）。
- **左右方向自检**：按提示往左/往右走 1.5 秒，确认左右没反。

## 4. 进游戏

联调台右上角「进入游戏（带校准）」可以直接带着地址跳过去；
也可以手动在地址栏拼：

```
index.html?input=radar&radar=ws://127.0.0.1:8766&radar2=ws://127.0.0.1:8767
```

游戏里的「校准雷达动作」面板也能连两台：面板顶部有左右 / 上下两行地址框，
填好后点「连接」，两行的状态会分别显示，确认后直接开始校准，不用回联调台。

关掉双雷达：URL 里写 `radar2=off`，或在游戏里把第二台断开并取消勾选。

## 5. 排查表

| 现象 | 原因 / 处理 |
|---|---|
| 页面打开是白板、没有样式 | 只拷了 `radar-connect.html`，缺 `js/` 目录。整包解压，别单独拷文件 |
| 点「连接」提示连接失败 | 桥接器窗口没开、或端口写错；先用 `check_radar.py` 确认 |
| 两台只能连上一台 | 两个桥接器用了同一个 `--port`；改成 8766 / 8767 |
| 第二台有帧，但 `jump` 一直是 0 | 桥接器没收到"跳"的字段。看 `--print-sample` 的原始报文，用 `--map`、`--jump-th` 对上字段 |
| 第一台 `x` 一直不动 | 雷达没数据 / UDP 端口不对 / 上下游字段名不匹配 |
| 左右反了 | 桥接器加 `--invert-x` |
| 站着不动 `x` 不是 0 | 人站偏了：`--offset-x` 减掉零点偏移 |
| 两台同型号互相干扰、数据乱跳 | 错开摆位（别面对面正对）、拉开距离或加遮挡，必要时换不同频段 |
| 跳/蹲频繁误触 | 提高 `--jump-th` / 调游戏里的阈值；也可能雷达装得太低，人呼吸都算跳 |
| 显示"已断开"但桥接器窗口还在 | 桥接器上游 2 秒没数据会自动提示；检查雷达是否真的在发 |

## 6. 这个包里有什么

```
dual-radar-kit\
  START-HERE.md           ← 你正在看的这份
  radar-connect.html      ← 雷达联调台（双击打开，双雷达都在这里连）
  index.html              ← 游戏本体
  style.css
  js\                     ← 游戏脚本，联调台也依赖其中的 config.js / Calibration.js
  assets\  vendor\        ← 图片与依赖
  docs\                   ← 截图
  tools\
    radar_bridge.py       ← 桥接器：雷达 → WebSocket
    check_radar.py        ← 单路自检
    fake_radar_ws.py      ← 假雷达，没有真雷达时用来演练
  README.md               ← 完整开发文档（想深挖再看）
```

全部是 Python 标准库，**不需要 pip install**；需要 Python 3.7+（`py --version` 确认）。
