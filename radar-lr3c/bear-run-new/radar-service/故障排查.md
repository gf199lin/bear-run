# 故障排查（按现象查）

> 原则：先跑 `2-检查雷达.cmd`，它会明确告诉你卡在哪一环。
> 下表左边是它会打印的结论，右边是对应的处理。

---

## 1. 设备管理器里根本没有「端口 (COM 和 LPT)」，或出现带黄色叹号的「未知设备」

**原因**：USB 转串口驱动没装，或线只能充电。

**处理**：

1. 先换一根**确定能传数据**的 USB 线，换一个 USB 口，重插。
2. 还不行就装驱动（两块板芯片不同，**装错了没用**）：

| 板子 | 芯片 | 装哪个驱动 | 下载地址 |
|---|---|---|---|
| 1T2R（DEV202H） | CP2102 | **CP210x Universal Windows Driver** | https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers |
| 2T4R（DEV113P） | FT232 | **FTDI VCP Driver**（CDM212364 或更新） | https://ftdichip.com/drivers/vcp-drivers/ |

> 网上很多教程说「雷达装 FTDI 驱动」，那只对 2T4R 成立。**1T2R 是 CP2102，装 FTDI 不会让 1T2R 出现。**

3. 装完**拔掉再插**，再看设备管理器。正常应显示：
   - `Silicon Labs CP210x USB to UART Bridge (COMx)`
   - `USB Serial Port (COMy)`

---

## 2. `scan` 能看到端口，但 `check` 说「端口不存在」

**原因**：注册表里有残留项（设备已经拔掉过，或驱动卸载不干净）。

**处理**：

- 确认板子确实插着、设备管理器里有这个 COM 号；
- 拔插一次，重新跑 `2-检查雷达.cmd`；
- 如果只有一个口反复报这个，说明是别的东西留下的空号，忽略它、用另一个口即可。

---

## 3. `[FAIL] 端口被其它程序占用`

**这是最常见的故障，不是雷达坏了。** 一个串口同时只能被一个程序打开。

按顺序关掉这些（关完再跑一次 `2-检查雷达.cmd`）：

| 可能占用者 | 怎么关 |
|---|---|
| ONELAB / ICL 厂商上位机 | 直接关窗口 |
| 本项目旧的点云服务 | 关掉跑 `server.py` 的命令行窗口 |
| 之前双击的推流窗口（`radar_live_ws.py`） | 关窗口，或双击 `6-停止推流.cmd` |
| 串口助手 / PuTTY / XCOM / SSCOM | 关掉，或点「关闭串口」 |
| 另一个 `radar_autoconnect.py` | 关掉那个命令行窗口 |

查「到底是谁占着」，在命令行执行：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -match 'python|ONELAB|ICL|mmWave' } |
  Select-Object ProcessId, Name, CommandLine
```

看到 `radar_live_ws.py --port COM4` 就是它在占，按 PID 关掉：

```powershell
taskkill /F /PID 1234
```

> 本包的 `check` 会自动尝试列一次占用进程，但它只认名字里带 python / ONELAB / ICL 的，仪器软件可能认不出来。

---

## 4. `[FAIL] 端口能打开但没有数据`

**原因**：板子没上电、没进入出流状态，或 USB 线只供电不传数据。

**处理**：

1. 板子上的电源灯亮不亮？
2. 换线、换 USB 口（优先插主板后置口，别用前置扩展坞）。
3. 有些板子上电后需要厂商工具触发才开始出流 —— 先用 ONELAB 确认它自己能看到数据，再回来跑本包。
4. 两块板同时插时，供电不足也会导致其中一块不出流：换带供电的 USB Hub，或分两个口插。

---

## 5. `[WARN] 有数据但认不出格式`

**原因**：波特率不对，或固件跑在另一种上行模式。

本包会自动试 921600 / 1500000 / 460800 / 2000000 / 115200 / 230400 六档。六档都认不出，说明不是波特率问题，而是**字节流形态不是我们记录的两种**：

- 1T2R：`ICLH ... ICLT` 封装帧，或 40 字节裸帧（帧首 `0xAA`、帧尾 `0x55`）
- 2T4R：136 字节裸帧，同步字 `55 AA`

**处理**：把 `check` 的整屏结果（含「证据」那一行）发回来。不要自己改脚本猜。

---

## 6. 只认出 / 只连上一块

按可能性排序：

1. 另一块被占用 → 见第 3 节；
2. 另一块的驱动没装 → 见第 1 节（两块芯片不同，要装两个驱动）；
3. 另一块没出流 → 见第 4 节；
4. 只有一根好线 → 换线试。

`check` 的「结论」区会把没通过的那块和原因单独列出来，照着看。

---

## 7. 两块同时插，数据乱跳 / 频繁误触发

**原因**：两块同频段雷达互相照射（尤其面对面摆放时）。

**处理**：

- 两块**错开摆位**，不要正对；
- 拉开距离，或在中间加遮挡（纸板、显示器背面）；
- 采集时如果只需要一块的数据，就只插一块。

---

## 8. 推流时提示「本地 8766 / 8767 端口已被占用」

**原因**：上次的推流没关干净。

**处理**：

```powershell
py radar_serve.py stop
```

还不行就查谁占着：

```powershell
netstat -ano | findstr :8766
taskkill /F /PID <上面查到的PID>
```

---

## 9. 推流成功，但游戏/联调台连不上

按这三点查：

1. **地址写对没有**：`ws://127.0.0.1:8766`，不是 `http://`，也不是 `localhost:8766/index.html`；
2. **是不是两台电脑**：跨机器时推流那台要加 `--host 0.0.0.0`，并且 Windows 防火墙放行 8766/8767（本包默认只监听 127.0.0.1，跨机不通是正常的）；
3. **用体检器单独验证这一路**：

```powershell
py tools\check_radar.py ws://127.0.0.1:8766
```

它会分 6 层告诉你卡在 TCP、握手、帧数、字段还是数据质量。

---

## 10. 中文显示成乱码 / 问号

**原因**：Windows 控制台默认不是 UTF-8。

**处理**：本包的 `.cmd` 已经在开头执行 `chcp 65001`，正常不会乱码。如果还乱：

- 用 **Windows Terminal** 或 PowerShell 打开，别用很老的 cmd 窗口；
- 或在命令行先执行 `chcp 65001`，再运行 `py radar_autoconnect.py check`。

---

## 11. 装完 Python，`1-安装环境.cmd` 还说找不到

**原因**：安装时没勾「Add python.exe to PATH」，或装了 Microsoft Store 版。

**处理**：

1. 打开命令行执行 `py -3 -V`。能看到版本号就没问题；
2. 看不到就重装 Python，安装第一屏**勾选 Add python.exe to PATH**；
3. 装完**关掉所有命令行窗口**再重开（PATH 要重新加载）。

---

## 12. 采集出来的文件是 0 字节

说明端口打开了但没读到数据 —— 和第 4 节同一个原因。先过 `2-检查雷达.cmd`，它通过之后再采集。
