# 真雷达接入指南（给组员）

> 游戏只吃一种输入：**WebSocket + 每帧一个 JSON**
> `{"ts":毫秒,"x":-1~1 左负右正,"height":0~1,"jump":0/1,"crouch":0/1,"confidence":0~1}`
> 所以"能不能接上"只取决于一件事：**有没有人把雷达的输出翻译成这个格式**。

## 第一步：判断雷达是怎么往外吐数据的

对着雷达那台机器，回答 4 个问题：

1. 雷达是用**串口**（COM3 / ttyUSB0）接出来的吗？
2. 还是走**网口**：UDP 包、TCP 长连接、或者 HTTP 接口？
3. 还是只能用**厂商 SDK / 上位机软件**（没有明文协议）？
4. 有没有现成的 **WebSocket** 服务（很少见，但如果有就最省事）？

只要不是第 4 种，就用**桥接器**。不用改游戏、不用写代码。

## 第二条：两条路，选一条

### 路线 A —— 雷达自带 WebSocket JSON

1. 确认它绑的是 `0.0.0.0`（不是只绑 `127.0.0.1`），端口放行；
2. 联调台填 `ws://<雷达机器IP>:8766` → 连接；
3. 点「进入游戏（带校准）」→ 走完 5 步校准。

### 路线 B —— 用桥接器（绝大多数真机走这条）

在**雷达那台机器**上（装了 Python 3 即可，不用 pip 装东西）：

```bash
# 0) 先看看它到底吐什么（第一次必做，屏幕上会打印"收到原文 + 解析结果"）
python tools\radar_bridge.py --from udp --udp-port 8888 --parse json --print-sample
```

按出口形式换上游，对照下表复制一条：

| 雷达到底是什么 | 命令 |
|---|---|
| 往本机 **UDP** 端口发包，内容是 JSON | `python tools\radar_bridge.py --from udp --udp-port 8888 --parse json` |
| UDP 包是 `x=0.31 jump=1 crouch=0` 这种键值对 | `python tools\radar_bridge.py --from udp --udp-port 8888 --parse kv` |
| UDP 包是逗号分隔的一串数字 | `python tools\radar_bridge.py --from udp --udp-port 8888 --parse csv --fields x,height,jump,crouch` |
| 雷达开了 **TCP 服务**，我们连过去 | `python tools\radar_bridge.py --from tcp --tcp 192.168.1.23:9000 --parse json` |
| 雷达**主动连**本机某端口推数据 | `python tools\radar_bridge.py --from tcp-listen --listen-port 9100 --parse json` |
| 雷达有 **HTTP 接口**，定时查询 | `python tools\radar_bridge.py --from http --http http://192.168.1.23/api/target --interval 0.05 --parse json` |
| 只有**厂商 SDK / 命令行**，它每行打印一条 JSON | `python tools\radar_bridge.py --from exec --exec "python vendor_sdk.py --stream" --parse json` |

桥接器启动后会打印：

```
输出 ws://0.0.0.0:8766  →  游戏/联调台填 ws://127.0.0.1:8766
```

然后游戏/联调台就填这个地址。

### 字段名 / 量纲对不上怎么办

四个参数就够，按需叠加：

| 雷达给的 | 加什么参数 |
|---|---|
| 字段名不同（`px` / `duck` / `is_jump`） | `--map x=px,crouch=duck,jump=is_jump` |
| x 是像素或毫米，不是 -1~1 | `--scale-x 0.002`（1 单位 = 0.002 个归一化单位） |
| 人站中间时 x 不是 0 | `--offset-x -0.35`（减掉静息基线） |
| 左右反了 | `--invert-x` |
| 跳/蹲给的是连续值（不是 0/1） | `--jump-th 0.5 --crouch-th 0.5` |
| 报文外面包了一层 `{"code":0,"data":{...}}` | 不用管，桥接器会自动往里找一层 |

> 校准向导还会在游戏里现场学一次：零点、左右方向、跳/蹲阈值都能自适应，
> 所以**不必把参数调到完美**，只要 x 能随人左右移动、跳/蹲有信号就行。

## 第三步：连不上时，让工具告诉你卡在哪

在雷达那台机器上跑（把地址换成实际的）：

```bash
python tools\check_radar.py ws://127.0.0.1:8766
```

它按层给结论，对着看就行：

| 报告里的那一层 | 说明什么 | 怎么办 |
|---|---|---|
| ① TCP 连不上 / 提示"没有程序在监听" | 端口没服务、地址写错、或服务没启动 | 先起桥接器；确认端口号 |
| ② 对方不是 WebSocket 服务（回了 HTTP 200） | 填的是普通网页端口，不是雷达/桥接器端口 | 换成桥接器打印的那个端口（默认 8766） |
| ② 握手失败（code=1006） | 端口通但协议不对，或被防火墙中间拦了 | 确认对端是 ws 服务；关掉代理/VPN 再试 |
| ③ 一帧都没收到 | 服务在听但没推数据 | 雷达没采到人、或上游没启动（看桥接器窗口有没有"收到"） |
| ④ 缺关键字段 / JSON 解析失败 | 字段名不对、或发的不是 JSON | 用 `--map` 改字段名；确认 `--parse` 选对 |
| ⑤ x 几乎不动 | 探测区没人，或 x 是常量 | 让人在探测区中间左右走，看跨度是否 > 0.1 |
| ⑤ 静息基线偏离很多（均值 ±0.35 以上） | 人一直站一侧，或上游没去基线 | 校准向导会处理，或加 `--offset-x` |

## 第四步：跨机器必做的三条

1. 雷达/桥接器绑 **`0.0.0.0`**（桥接器默认就是），不要只绑 `127.0.0.1`；
2. **防火墙放行**端口（Windows 首次运行会弹窗，必须点"允许"）；
3. 两台机器**同一网段**，组员电脑上先 `ping <雷达IP>`、再 `Test-NetConnection <雷达IP> -Port 8766`。

## 第五步：进游戏

联调台 →「**进入游戏（带校准）**」→ 第一次自动 5 步校准：

| 步骤 | 做什么 |
|---|---|
| 1 | 站中间别动（同时探针统计静息误报） |
| 2 | 往左走一步（看位移幅度是否够） |
| 3 | 往右走一步（同时判左右方向，装反会自动纠正） |
| 4 | 跳一下 |
| 5 | 蹲一下 |

走完会存下来，下次直接玩。静息误报太多时，雷达的跳/蹲会被自动停用、退回键盘 —— 这是**有意降级**。

## 卡住时把这些发给我

1. `--print-sample` 那几行输出（**原始报文长什么样**，最关键）；
2. `check_radar.py` 的整段报告（哪一层是 `[FAIL]`）；
3. 雷达型号 / 接口文档里关于"数据输出格式"的那一页截图。
