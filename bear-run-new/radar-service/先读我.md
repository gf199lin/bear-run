# 毫米波雷达自动连接包 · 先读我

这个包是给你（同学）的。目标只有一个：**你不需要知道雷达插在 COM 几，也不用改任何脚本，插上就能连。**

包里有 6 个双击就能跑的步骤，加两个说明文件。全部本地运行，不联网上传任何数据。

---

## 一、你手上是什么

| 板子 | 型号 | USB 串口芯片 | 帧率（实测） | 这个包里负责 |
|---|---|---|---|---|
| 第一块 | DEV202H / ICL1122，**1T2R** | CP2102 | 约 7.7 帧/秒 | 左右（x → 换道） |
| 第二块 | DEV113P，**2T4R** | FT232 | 约 1.9 帧/秒 | 上下（jump / crouch） |

两块板的串口号在**每台电脑上都不一样**（你这里可能是 COM5 / COM7，我这里是 COM3 / COM4）。所以本包**不写死串口号**：每次运行都现场枚举端口，按 USB 芯片的 VID:PID 认板，再把真实端口号交给后续程序。

## 二、第一次用：4 步

### 第 0 步：确认插好、驱动装好

两块板各用一根**能传数据**的 USB 线（很多线只能充电）。插好后打开「设备管理器 → 端口 (COM 和 LPT)」，应该看到：

- 一块显示 **Silicon Labs CP210x USB to UART Bridge (COMx)** → 这是 1T2R
- 一块显示 **USB Serial Port (COMy)** → 这是 2T4R（FTDI 芯片）

看不到的话先装驱动，见 `故障排查.md` 第 1 节。

### 第 1 步：双击 `1-安装环境.cmd`

它会检查 Python 版本，并自动装 `pyserial`（读串口必需）和 `numpy`（推流给游戏时才需要）。

- 没装 Python 的话，先看 `Python安装说明.md`，装完再回来双击这个。
- 能联网就自动装；不能联网时它会告诉你离线怎么装。

### 第 2 步：双击 `2-检查雷达.cmd`

这是**最重要的一步**。它会：

1. 列出系统里所有串口 + 各自是什么芯片（不打开端口，零风险）；
2. 逐个试开，读 2 秒真实字节流，判断「这块板在不在出帧」。

看到这样的结果就是好的：

```
可用（出帧正常）: 2 块
  COM3     DEV202H (ICL1122) 1T2R    7.72 帧/s @ 921600
  COM4     DEV113P 2T4R             1.88 帧/s @ 1500000
[OK] 两块板可以同时使用，互不冲突。
```

只连上一块也能继续用，但另一块要按提示查原因。**这一步不通过，后面都不用试。**

### 第 3 步：双击 `3-采集数据.cmd`

输入要录多少秒（直接回车 = 60 秒），它会把两块板的**原始字节流**各存一个 `.bin` 文件到 `captures\` 目录，同时生成一个 `meta-*.json` 记录板型、端口、波特率、字节数、时长。

采完把整个 `captures` 文件夹打包发回来就行。

> 数据说明：录的是雷达原始回波（不含图像、不含音频），但按课程保密要求，**只在小组内部传，不要发到公开网盘或群里**。

## 三、想直接推给游戏：第 4 步

双击 `5-推流到游戏.cmd`。它会自动认出两块板，分别起两路 WebSocket：

```
左右 ws://127.0.0.1:8766
上下 ws://127.0.0.1:8767
```

启动后它会自己连上去数帧，确认「真的能收到数据」才打印成功。用完双击 `6-停止推流.cmd`。

游戏地址后面拼上它打印的那串参数，例如：

```
index.html?input=radar&radar=ws://127.0.0.1:8766&radar2=ws://127.0.0.1:8767
```

> 注意：**「上下」（jump / crouch）在项目里还是候选项**。1T2R 没有俯仰角，2T4R 的俯仰链路仍在验证中。所以上下那一路即使推出来了，也只能当实验数据，不能写进「已实现功能」或验收结论。左右那一路是已经验收过的。

---

## 四、随时看状态：`4-持续监视.cmd`

插拔、掉线、重新出帧都会实时打印。演示前用它确认两块都在线。

## 六、三条硬规则

1. **一个串口同时只能被一个程序打开。** ONELAB、点云服务、串口助手、旧的推流窗口，只要有一个开着，另一个就打不开那个口，会报「端口被其它程序占用」。这是最常见的问题，不是雷达坏了。
2. **别改脚本里的串口号。** 本包就是靠「不写死」才能在每台电脑上都工作。真需要强制指定时，用 `radar_serve.py --port-lr COM7 --port-ud COM9`。
3. **连不上先跑 `2-检查雷达.cmd`，把整屏结果发回来。** 它每一行都写了卡在哪一环（没插好 / 没驱动 / 被占用 / 没数据 / 波特率不对），比「连不上」三个字有用得多。

## 七、出问题找谁

先看 `故障排查.md`。还不行，把这两样发回来：

1. `2-检查雷达.cmd` 的完整截图；
2. `captures\check-result.txt`（在命令行执行 `py radar_autoconnect.py check --json > captures\check-result.txt` 生成）。

有这两样基本能定位。

## 八、这个包验证到什么程度（2026-10-30）

**已在本机实测通过**：

| 项目 | 结果 |
|---|---|
| 串口枚举 | 两块板按 USB 指纹分别认出：COM3 = CP210x / 1T2R，COM4 = FT232 / 2T4R |
| 出帧判定 | 1T2R：7.72 帧/s（典型 7.74），形态「40 B 裸帧」 |
| 单板推流 | `ws://127.0.0.1:8766` 自检收到 6 帧，8.1 帧/s |
| 停止推流 | 后台进程被正确结束，PID 文件清理 |
| 单板采集 | 4 秒录到 154.3 KB，元数据正常写入 |
| 采集结果可解析 | 采回的 `.bin` 被项目解析器识别为 `1t2r`，回放出 30 个雷达帧 |
| 角色分配逻辑 | 7 个场景离线用例全通过（双板 / 顺序颠倒 / 单板两种 / 同型号 / 手动指定） |

**本轮没有验证，不要当成已通过**：

- **2T4R 当前不出流**：端口能打开，连续读 5 秒、6 档波特率都是 0 字节。
  这不是本包的问题（判定逻辑正确地把「端口能开但没数据」和「端口不存在」分开了），
  需要先确认那块板有没有上电、要不要复位、或是否需要厂商工具触发才开始出流。
- **因此「两块同时推流」没有跑通**。代码路径已按单板验证，双板分配逻辑用离线用例覆盖；
  等 2T4R 恢复出流后，再跑一次 `5-推流到游戏.cmd` 确认两路都在。
- **jump / crouch 仍未验证**（1T2R 无俯仰角，2T4R 俯仰链路在项目里仍属候选项）。
