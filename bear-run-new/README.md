# 熊二快跑 · Bear Run

雷达体感跑酷游戏（MVP）。
美术风格：**《熊出没》式的明亮森林** —— 蓝天白云、林间土路、鲜绿草地、蜂蜜金黄。
主角是**熊二**（不是熊大），跳跃会团成球前空翻，滑铲会仰面朝天乱蹬。

## 30 秒开始

- **在线试玩**：<https://gf199lin.github.io/bear-run/>
- **本地运行**：`python -m http.server 8801`，打开 <http://127.0.0.1:8801/index.html>
- **零依赖运行**：也可以直接双击 `index.html`（`file://` 下登录加密会降级，演示够用）

### 3 分钟验收路径

1. 主菜单 → 游客模式 → 开始快跑
2. 键盘：`←` `→` 换道，`↑` 跳跃，`↓` 滑铲
3. 体感：右上角摄像头图标 → 开启 → 站立 / 左右移动 / 跳 / 蹲
4. 雷达：双击 `START-RADAR.cmd` → 选 `[1] Play the game` → 页面点「连接」→ 按向导校准
5. 结算页确认本局分数、最高分与纪录

> **已知限制**：真雷达跳/蹲仍是实验功能，未完成真机验收；登录为本地账号，无后端同步。
> 完整限制见第九节。

> **本版本是「新手指引 + 雷达连接」的整合版**，两条主线已经串成一条完整流程：
> **玩法引导（6 步）→ 雷达动作校准（5 步）→ 开局**。
>
> - 新手指引：第一次点「开始快跑」会先走 6 步玩法速览；主菜单的「**新手指引**」按钮可随时重看。
>   详见**第十一节**。
> - 雷达校准：选「雷达」输入源后自动弹出，5 步把横向零点、极性和跳/蹲阈值标到你身上，
>   并先验上游信号可信度，不可信就自动回退键盘。详见**第十一节**。
> - 雷达联调台 `radar-connect.html` 与 `tools/` 里的三个 Python 工具全部保留。详见**第十二节**。
>
> 如果你之前跑过旧版本，旧校准存档会被判过期，**第一次进来会重新校准一次**，这是预期行为。

---

> 双击仓库根目录的 **`START-RADAR.cmd`**，选 `[1] Play the game`，它会自动认板、

## 一、怎么玩起来

### 方式 A：直接双击（推荐，零依赖）

解压后双击 `index.html` 即可开始，不需要装任何东西、不需要联网。

> 游戏里的 3D 引擎（three.js）已经随包放在 `vendor/three.min.js`，全部素材都是代码实时生成的，
> 所以断网也能玩。

### 方式 B：本地服务器（手机/平板同局域网访问时用）

想用手机玩，或者只是想避免某些浏览器对 `file://` 的限制，可以起一个静态服务器：

```bash
# 在游戏目录下执行
python -m http.server 8801
```

然后浏览器打开 `http://127.0.0.1:8801/index.html`。
手机端把 `127.0.0.1` 换成电脑的局域网 IP（例如 `http://192.168.1.7:8801/index.html`）。

### 本地账号：先登录 / 注册（或游客直接玩）

打开页面第一屏是登录框（`js/auth.js`），没有账号就点「没有账号？去注册」。
登录成功后整页刷新，**最高分 / 纪录 / 输入源 / 角色选择都按账号隔离**，
主菜单左下方会显示「账号：xxx」和「退出」按钮。

不想建账号就点「以游客身份直接玩（不保存历史）」：

- 游客不需要用户名密码，直接进主菜单，键盘 / 触屏 / 雷达都能正常用；
- **最高分、纪录、输入源、角色偏好只存在内存里**，刷新或关掉页面就全部清空，
  不会写进 localStorage，也不会污染任何账号的存档；
- 账号一条显示「游客」，点「退出」回到登录页；
- 现场演示 / 多人轮流试玩时用它最省事，正式记分还是走登录账号。

几个必须知道的边界：

- 账号和存档**只存在当前浏览器的 localStorage**，没有后端。
  换设备、换浏览器、清缓存都不会同步，也防不了懂技术的人直接改本地数据。
  定位是「本地多账号演示」，不是真正的账号安全。
- 密码存的是 `SHA-256 + 随机盐`（`crypto.subtle`）；
  `file://` 打开时浏览器不给 `crypto.subtle`，会自动降级成简易哈希，仅供演示。
- 第一个注册的账号会自动接手旧版「无账号」的最高分 / 纪录，不会丢档。
- 忘记密码没有找回入口，清掉 `bear-run:users:v1` 这个键就等于重置所有账号。

## 二、操作方式

| 操作 | 键盘 | 触屏 | 雷达体感 |
|---|---|---|---|
| 左移一个车道 | `←` 或 `A` | 手指向左滑 | x 归一化值 < -0.36 |
| 右移一个车道 | `→` 或 `D` | 手指向右滑 | x 归一化值 > 0.36 |
| 跳跃 | `↑` / `空格` / `W` | 上滑 | jump 上升沿 |
| 滑铲 | `↓` / `S` | 下滑 | crouch 上升沿 |
| 暂停 | `P` / `Esc` | 右下角「暂停」 | — |
| 音效开关 | — | 右下角「音效」 | — |
| 引导前进 | `→` / `Enter` / `Space` | 点「下一步」 | — |
| 跳过引导 | `Esc` | 点「跳过引导」 | — |

手机建议横屏、全屏玩（开始时会自动尝试横屏全屏）。

> 第一次点「开始快跑」会先走一遍 **6 步玩法引导**（详见第十节），
> 选「雷达」输入源还会再走一遍 **5 步雷达动作校准**（详见第十一节）。
> 两个引导顺序衔接，不会同时弹。

### 测试模式（雷达联调专用）

主菜单「**雷达测试**」直接进一条空跑道，专门用来对雷达，不参与游戏进度：

- **没有任何障碍物**：障碍、蜂蜜罐、红苹果、蜂蜜滑道一个都不生成（场上对象恒为 0）。
- **不会死**：碰撞判定整个跳过，光头强不上场、也不会来处决，血条永远是满的。
- **熊二一直跑**：固定 **10 m/s**，不随里程加速（速度在 `js/config.js` 的 `TEST.speed`）。
  跑多久都不会进结算、不抽挑战、不写最高分与历史纪录。
- 自动展开右上角「**雷达调试面板**」：x / height / jump / crouch / 帧率 / 端到端延迟。
- 左右换道、跳、蹲照常用（键盘 / 触屏 / 雷达都行）。
- 退出：右下角「暂停」→「返回主菜单」。暂停里的「重新开始」还是测试局。

想连地址一起省掉点菜单，用 URL 参数直接进：

```
index.html?test=1&input=radar&radar=ws://192.168.1.7:8766
```

`?mode=test` 与 `?test=1` 等价。选的是「雷达」且还没校准过，会先走校准向导，
校准结束（或跳过）后自动进测试场。想临时改速度加 `testspeed`，例如
`?test=1&testspeed=14`（默认 10 m/s，持久值在 `CFG.TEST.speed`）。

## 三、玩法规则

- **3 车道**，左右移动吸附到车道，撞击判定以横向距离为准（有宽容度，不会擦边就死）。
- **3 格血**（可被红苹果养到最多 5 格）。每次受伤后约 1.15 秒无敌闪烁。
- **计分** = 距离分（1 分/米）+ 蜂蜜分（20 分/个）。蜂蜜滑道期间**分数翻倍**。
- **无尽模式**，血扣完结束。单局大约 1～2 分钟。
- **难度递增**：速度随距离线性上升（8.5 → 25 m/s），障碍密度同步变密，
  并按距离分 4 个区域解锁新障碍：**狗熊岭入口 → 密林深处 → 伐木场 → 光头强工地**。
- **最高分**存在浏览器 localStorage（键名 `bear-run:best-score`），换浏览器不通用。

### 场上的 5 种元素

| 元素 | 长什么样 | 怎么应对 |
|---|---|---|
| 木栅栏 | 木栏杆 + 顶部黄黑警示条，是唯一"该跳"的识别信号 | **跳**过去（不跳会撞） |
| 横倒的粗树干 | 一根横跨车道的大树干，最低点约 1.18m | **滑铲**钻过去（站着必撞） |
| 原木石头堆 | 双层原木 + 大石头 + 青苔 | **换道**绕开（跳不过） |
| 滚动的木桶 | 带铁箍的木桶，在两车道间来回滑 | 预判它的轨迹，**换到它不在的道** |
| 蜂蜜罐 / 红苹果 / 蜂蜜滑道 | 金黄发光蜂蜜罐 / 红苹果 / 橙色蜂蜜滑道 | 吃到即得分 / 回血 / 3.2 秒加速双倍分 |

> 每一行障碍**永远至少留一条空车道**，不会出现三条道全堵的死局。
> 蜂蜜罐串和道具都放在空车道上，跟着蜂蜜罐走就是安全路线。

### 搞笑动作（就是冲着好笑做的）

- **跳跃**：熊二在空中抱成一团球、整整前空翻一圈，落地"啪叽"压扁再弹回来。
- **滑铲**：直接仰面朝天躺平，四肢在空中乱蹬、舌头甩出来。

### 光头强：一直在后面追你

- **开局就追**：光头强贴在你身后 1.5m 左右，横着错开一个身位，所以不会挡住熊二。
  默认视角看到的是他的背影 + 右手的斧头。
- **大约 3 秒后追不上**：他会落到远处并淡出，画面恢复安静。
- **每掉一格血他会重新冲上来**：贴身狂追 2.4 秒（冲刺速度还会往上顶一档），然后再落后。
- **最后一格血被打掉 = 处决演出**（不再是普通撞击）：
  1. 镜头从背后跟拍**平滑切到侧面机位**（0.85 秒）；
  2. 光头强扑上来、高举斧头、抡下去，斧头落地溅出**星火**（粒子特效，见第五节）、屏幕震动；
  3. 熊二被拍成一张饼：身体压扁、四肢摊开、**蚊香眼 + 舌头甩出来**；
  4. 屏幕弹出漫画字幕「**臭狗熊！**」（先弹入、再左右抖两下）；
  5. 定住约 1.55 秒后进入结算界面，标题是「**被光头强逮住了**」。
- 追兵的所有参数在 `js/config.js` 的 `VICK` 段（贴多近、多久放弃、处决各阶段时长），
  处决镜头机位在 `CINE` 段。改完刷新即生效。

## 四、音效和背景音乐

**全部声音都是代码现场合成的**（`js/Audio.js`，用 WebAudio 的振荡器 + 噪声），
工程里**没有任何音频文件** —— 所以 `file://` 双击打开时不会出现"音效有时有有时没有"的
玄学问题，包体积也一点不涨。背景音乐是一段 4 小节循环（C–Am–F–G），
速度在 `CFG.AUDIO.bgmBpm`，旋律/贝斯/鼓点都是简谱数组，改数字就改曲子。

| 时机 | 声音 |
|---|---|
| 跳跃 / 落地 | 上滑"啾" + 落地闷响 |
| 滑铲 | 一段往下拉长的摩擦声 |
| 左右换道 | 极轻的一声"呼"（只在真的换了车道时响） |
| 吃蜂蜜罐 | 两段"叮叮"，**连吃会一路升 key** |
| 吃红苹果 | C 大三和弦往上滚 |
| 上蜂蜜滑道 | 带滤波打开的上冲 |
| 撞到障碍 | 下滑的刺耳声 |
| 光头强追上来（开局 / 每次掉血） | 两下低沉警告音 |
| 斧头落地（处决） | 劈风声 + 低频轰 + 金属余音，全片最重的一记 |
| 血掉光 | 一整条下行音阶；处决演出期间背景音乐自动压低 |
| 进入新区域 | 明亮的四音上行 |
| 结算 / 破纪录 | 普通结算音 / 五音号角 |
| 点任意按钮 | 一记几乎听不见的"嗒" |

- **静音开关**：右下角「音效」按钮（点一下变「静音」，按钮压暗划线），
  选择记在 localStorage（`bear-run:audio`），下次打开保持。
- **开局前是静音的**：浏览器规定 AudioContext 必须由用户手势解锁，
  所以真正出声从玩家第一次点击（「开始快跑」）或按键开始 —— 这是浏览器策略，不是 bug。
- **调音**：音量、音乐速度、金币升 key 的幅度都在 `js/config.js` 的 `AUDIO` 段；
  想彻底关掉音频排查性能问题，把 `AUDIO.enabled` 设成 `false`。
- **自查**：浏览器控制台里 `RR.Audio.stats.byName` 会列出每种音效各响了多少次
  （无头环境听不到声音，自动化测试就是靠这个数确认音效真的触发了）。

## 五、画面特效（粒子）

跑动、跳跃、吃道具、被斧头拍，都会有粒子飞出来。整套特效**只有 2 次额外绘制**
（实测：冻结同一画面、来回切换这两个点云的可见性，draw call 差值恰好是 **+2**），
而且**数量与跑得多远无关** —— 池子开局就分配好，永远不会因为跑久了越来越卡。

| 时机 | 效果 |
|---|---|
| 跑动 | 脚下持续扬起的细尘土 |
| 起跳 / 落地 | 蹬地一小撮；落地按**下坠速度**决定尘土的量与大小（跳得越高砸得越狠） |
| 滑铲 | 贴地拖出一长条尘带 |
| 吃蜂蜜罐 | 金黄闪光（带一点上升感） |
| 吃红苹果 | 绿色小星迸开 |
| 上蜂蜜滑道 | 脚下持续喷出的尾焰 |
| 撞到障碍 | 土块碎屑四溅 |
| 斧头落地（处决） | 一簇**星火** + 一圈被砸起的尘土 |

**为什么是两套池子**：尘土走**普通混合**、星火走**叠加混合**（叠加才会发亮）。
固定渲染管线没法逐粒子切换混合模式，所以拆成「尘土 260」+「星火 200」两个池，
上限合计 460 个粒子。

**为什么自己写着色器**：`PointsMaterial` 的大小对整个点云是统一的，
做不出"大土块 + 小火星"同时存在；自己写 `ShaderMaterial` 就能让每个粒子
有自己的大小、颜色和透明度，顺便在片元着色器里算出柔和圆点，**省掉一张贴图**。

- **调参**：`js/config.js` 的 `PARTICLES` 段 ——
  `enabled`（设 `false` 整个特效关闭）、`dustCap` / `sparkCap`（两个池的容量）、
  `pixelScale`（嫌粒子整体太大/太小只改这一个数）、`runDustEvery`（跑动扬尘的间隔秒数）。
- **自查**：浏览器控制台里 `RRGame.particles.stats.byName` 会列出每类特效各触发了多少次，
  `RRGame.particles.live()` 返回当前活跃粒子数（池满与回收是否正常就看这个）；
  无头环境看不到画面，自动化测试就是靠这两个数确认粒子真的喷出来了。
- **不接雾**：粒子只出现在熊二身边 3~10m 内，而雾从 70m 才开始 —— 够不到，接了也白接。

## 六、接真雷达怎么弄

游戏把输入层做成了可替换的抽象（`js/InputSource.js`），
**接雷达只需要换数据源，游戏逻辑一行都不用改。**

### 1. 先用模拟器把链路跑通

主菜单 → 选择输入源 →「雷达模拟器」。
它会以 30Hz 产出一个虚拟人体、走和真雷达完全相同的解码链路，
调试面板里能看到 x / height / jump / crouch / confidence 的全部实时数值。

### 2. 再接真雷达

主菜单 → 选择输入源 →「雷达」，或直接用 URL 参数指定地址：

```
index.html?input=radar&radar=ws://192.168.1.7:8766
```

**推荐先打开 [`radar-connect.html`](./radar-connect.html)（雷达联调台）**：填地址 → 测连通 →
看实时数值/波形 → 一键「进入游戏（带校准）」。详见**第十一节**。

地址的生效优先级：`?radar=` 参数 > 浏览器记住的上次地址（localStorage `bear-run:radar:url`）>
`js/config.js` 里的 `RADAR.defaultUrl`。前两者只要出现过一次就会被记住，
之后从主菜单点「雷达」直接就是那台机器，不用再拼 URL。

### 3. 数据帧格式（与硬件同学对齐的接口约定）

游戏通过 WebSocket 接收 JSON，**每帧一个对象**：

```json
{ "ts": 1730000000000, "x": 0.42, "height": 0.0, "jump": 0, "crouch": 0, "confidence": 0.93, "raw": {} }
```

| 字段 | 含义 |
|---|---|
| `ts` | 采集时间戳（毫秒）。用来算端到端延迟，必须是采集时刻而非发送时刻 |
| `x` | 横向位置，归一化到 `[-1, 1]`，**左负右正** |
| `height` | 起跳高度，`0~1`（当前版本未参与判定，留作后续增强） |
| `jump` | 起跳标志，`0~1` 或布尔值 |
| `crouch` | 下蹲标志，`0~1` 或布尔值 |
| `confidence` | 本帧可信度 `0~1`，低于阈值会被丢弃 |
| `raw` | 原始数据，调试面板会展示，方便标定 |

### 4. 阈值都在 `js/config.js` 的 `RADAR` 段

```js
RADAR: {
  enterThreshold: 0.36,   // 进入左右车道的阈值
  exitThreshold:  0.22,   // 回到中间车道的阈值（迟滞，防抖动）
  jumpThreshold:  0.5,
  crouchThreshold: 0.5,
  minConfidence:  0.3,
  staleMs:        500,    // 超过这个时间没收到帧 => 判定掉线
  defaultUrl: 'ws://127.0.0.1:8766'
}
```

## 九、已知限制

- 雷达**没有高度维**，垂直起跳的径向速度接近 0 —— 垂直起跳判定是最大风险项，
  建议先跑通左右车道和下蹲，起跳先留键盘兜底。
- 雷达角度分辨率较粗，横向 `x` 建议结合迟滞阈值现场标定（调试面板就是给这个用的）。
- 触屏操作已完整实现，但**尚未对接雷达手势以外的体感输入**。
- 默认机位在背后，正脸本来看不到，所以表情走两条路：HUD 左上角的**表情小窗**
  （`js/FaceCam.js`，永远正对玩家，随跑 / 跳 / 滑铲 / 受击 / 被拍扁切换），
  以及跳跃到最高点时**回头一眼**（`CFG.PLAYER.headTurn` 控制角度、时机与速度）。
- 滑铲的"仰面朝天"只对熊二那套动作成立；熊大是脸朝下的超人式趴滑（`CFG.CHARACTERS` 的 `anim.slide`）。
- 光头强的追逐 / 处决演出目前只在**桌面浏览器**上验证过（无头截图逐帧核对姿势）；
  手机端帧率未实测 —— 他会多带来约 30 个网格，低端机若掉帧可先把 `VICK` 的
  `introChase` 调小或直接停用 `beginChase()`。
- 新手引导与雷达校准向导都依赖 localStorage（`file://` 下部分浏览器会限制）；
  推荐用 `python -m http.server` 起本地服务再打开（方式 B）。
- 登录是**纯前端本地多账号**：账号数据只在当前浏览器，没有后端、没有云端同步、没有找回密码；
  `file://` 下 `crypto.subtle` 不可用，密码哈希会降级成简易版本。真要上线得换成带后端的账号服务。

## 十一、开局雷达校准向导

雷达判定的阈值（`x` 的零点、左右极性、跳/蹲的触发阈值）**因人、因摆位、因设备而异**，
写死在 `config.js` 里只能靠运气。所以这个版本加了一个 5 步校准向导，第一次用雷达时带你走一遍。

### 1. 什么时候弹、怎么重开

- 主菜单选「雷达」输入源、并且**没有可用校准存档**时，进入游戏会**自动弹出**向导（每页一次）。
- 已校准后主菜单按钮下面会显示绿字「已校准」；想重测就点主菜单的「**雷达校准**」按钮。
- 不想让它自动弹：`js/config.js` 的 `RADAR.calib.autoOpen` 改成 `false`（仍可手动开）。

### 2. 它让你做 5 件事

每一步屏幕上方都有大字提示 + 实时反馈，做对了会立刻往下走：

| 步 | 让你做什么 | 达标条件 | 通过时的提示 |
|---|---|---|---|
| 1 | 站在雷达前**别动** | 连续 8 帧 `x` 的标准差 ≤ 0.18 | 「已定位，基线 x₀ = …」 |
| 2 | 向**左**走一步并保持住 | 相对基线的位移 ≥ 0.35、连续保持 3 帧 | 「检测到左移 …（保持 3/3）」 |
| 3 | 向**右**走一步并保持住 | 同上，且必须落在第 2 步的**反侧** | 「检测到右移 …」 |
| 4 | **跳**一下 | 上游给出 jump 上升沿 | 「跳跃信号已确认（峰值 …）」 |
| 5 | **蹲**一下 | 上游给出 crouch 上升沿 | 「下蹲信号已确认（峰值 …）」 |

> 第 2/3 步故意**不假设雷达装正了**：你往左走一次、往右走一次，它拿两边的实测位置自己算极性。
> （实测数据里"往右走 `px` 反而变小"是真出现过的，所以极性不能假定。）
> 每步都有 25 秒超时，超时会自动重来一次；实在做不了可以按方向键/空格用键盘代替（见第 4 小结）。

### 3. 它在背后同时做的三件事（这版的核心）

1. **先验上游质量（探针）**：第 1~3 步你站定/走位的时候，它悄悄统计 24 帧静息数据里
   上游报了多少次跳/蹲。**静站时误报超过 2 次、或误报帧占比超过 6%**，就判定「上游把站着不动
   也当成跳/蹲」，于是**彻底停用雷达跳/蹲**（阈值写成一个不可达的值）并回退键盘，
   而不是让熊二在平地上乱跳。
2. **现场学横向零点与极性**：校准后所有帧都过一层 `x' = (x - x₀) × sign`。
   你从此"往右走 → `x` 变大"一定成立。
3. **有界自适应阈值**：只有拿到证据才放宽，而且只放宽到
   `clamp(你这次动作的峰值 × 0.6, 0.30, 0.50)` —— 上下限都在，不会为了"让你过关"把阈值压进噪声里。
   峰值低于 **0.40** 的，直接判「信号太弱、不可用」，宁可回退键盘。

### 4. 屏幕上会看到的提示，以及它们的含义

| 提示 | 含义 | 你能做什么 |
|---|---|---|
| 正在确认你在场…（3/8） | 还在采集第 1 步的静息帧 | 继续站着 |
| 你在动，先站定 1 秒 | 这 8 帧不够稳 | 别晃，站稳 1 秒 |
| 没看到你，站回雷达前面 | 上游没给 `x`，或置信度低于阈值 | 站回探测区中间 |
| 再远 0.35（幅度大一点） | 第 2/3 步的位移不够 | 步子迈大一点 |
| 检测到跳跃，但幅度只有 0.36（太弱…） | 上游确实报了，但峰值低于 0.40 | 跳高一点；或者接受"雷达跳不可用、用键盘" |
| 雷达把"站着不动"也当成跳/蹲（静站误报 N 跳 / M 蹲） | 探针判噪 → 雷达跳/蹲已停用 | 这属于上游信号质量问题，**请把这行数字反馈给我们** |
| 用键盘走了这步 —— 雷达极性没法标定了 | 你按了方向键代替 | 左右标定会退回上一次校准的极性 |
| 雷达没数据（按 ← 可用键盘代替） | 超过 500ms 没收到帧（掉线） | 检查 ws 地址/网络；按方向键可继续 |
| 未使用雷达，已按键盘模式完成 | 全程用键盘过的校准 | 存档里会记 `keyboardOnly`，不假装标过雷达 |

### 5. 结果存在哪、怎么重测

- 存档写在浏览器 localStorage，键名 `bear-run:calib:v1`（里面的版本号字段 `v` 是 **2**）。
  换浏览器 / 清缓存 / 换电脑都要重测。
- **旧版（v1）存档会被判过期并自动重新引导** —— 更新到本版本后第一次进来会重走一遍校准，正常现象。
- 控制台自查：
  - `RR.Calibration.load()` —— 看存档内容（`x0` / `sign` / `lrOk` / `jumpOk` / `crouchOk` / `probe` / `upVerdict`）
  - `RR.Calibration.clear()` —— 清掉存档，下次进入重新引导
  - `RR.CFG.RADAR.jumpThreshold` / `crouchThreshold` —— 看**当前生效**的阈值（校准后这里就是学到的值；
    `2` 表示该动作已被停用）
- 校准存档依赖 localStorage，所以**建议按第 20 行的方式 B 用 http 打开**（`python -m http.server`），
  不要双击 `file://` —— 部分浏览器在 `file://` 下会限制 localStorage，可能存不上。

### 6. 参数与调试

- 所有参数在 `js/config.js` 的 `RADAR.calib` 段：探针帧数与误报上限、`weakPeak(0.40)`、
  `learnMargin(0.6)`、阈值上下限 `thFloor/thCeil(0.30/0.50)`、单步超时、`maxAttempts`、`disableTh(2)`。
- 没有雷达也能先看链路：
  - 主菜单 →「雷达模拟器」：以 30Hz 产出虚拟人体，走**和真雷达完全相同**的解码链路，
    调试面板里能看到 `x / height / jump / crouch / confidence` 全部实时值。
  - 离线回放（开发用参数）：`index.html?input=replay&series=gt_d00p85&replaymode=truth`
    —— 用采集时的人工动作真值当输入，看画面表现（`px_*` 换成实测值，可对比）：
    `index.html?input=replay&series=px_d00p85`。

## 十二、真机联调：接上真实雷达（组员照这个走）

目标：**从拿到 zip 到看见熊二跟着你左右跑，5 分钟**。

### 1. 三步接入

先分清雷达是哪种出口，两条路都只需要三步：

**A. 雷达本身就能推 WebSocket JSON**（少见，但最省事）
1. 确认它绑在 `0.0.0.0` 而不是只绑 `127.0.0.1`，端口放行；
2. 打开联调台 `radar-connect.html` → 填 `ws://<雷达机器 IP>:8766` → 点「连接」；
3. 点「**进入游戏（带校准）**」→ 走完 5 步校准向导（见第十一节）→ 开玩。

**B. 雷达是串口 / UDP / TCP / HTTP 接口 / 厂商 SDK**（绝大多数真机）
在**雷达那台机器**上跑桥接器，把它的原始输出翻译成游戏要的 ws JSON：

```bash
# 例：雷达往本机 8888 端口发 JSON（字段就叫 x/jump/crouch）
python tools/radar_bridge.py --from udp --udp-port 8888 --parse json --print-sample
```

然后游戏/联调台填 `ws://127.0.0.1:8766`（桥接器默认就推在这个端口）。
上游形式不同就换 `--from`：`udp` / `tcp` / `tcp-listen` / `http` / `exec` / `stdin`；
字段名对不上用 `--map x=px,crouch=duck`，像素坐标用 `--scale-x 0.002`，左右反了加 `--invert-x`。
**第一次接一定加 `--print-sample`**：它会把收到的原文和解析结果都打出来，照着调参数即可。

> 报文的每帧格式见第六节第 3 小节。桥接器是纯标准库，不需要 `pip install`。
> 想一次看清卡在哪一环，用 `python tools/check_radar.py ws://<雷达地址>`（详见第十二节第 6 小节）。

> 用 `python -m http.server` 起个静态服务再打开（方式 B）会更省心：校准存档依赖 localStorage。
> 手机/平板访问同一台机器时，用 `http://<电脑 IP>:8000/radar-connect.html`。

### 2. 地址会被记住

联调台里连接成功、或 URL 里带过 `?radar=`，地址都会写进 localStorage（`bear-run:radar:url`）。
之后**从主菜单点「雷达」直接连的就是那台机器**，不用再拼 URL。
优先级：`?radar=` > 记住的地址 > `js/config.js` 的 `RADAR.defaultUrl`。
换机器、换浏览器、清缓存都要重填一次；联调台里有「清掉记忆的地址」按钮。

### 3. 进游戏之前，联调台能先帮你排掉三类问题

| 自检 | 怎么做 | 看什么结论 |
|---|---|---|
| 有数据吗 | 连上就看数值区 | 帧率、帧数在涨 → 通；一直是"—" → 见第 4 条 |
| 左右方向对吗 | 站左边点「我在左边，采样 1.5 秒」，再站右边点右侧按钮 | 给"极性正常/装反了"和幅度（第 2 步要 ≥0.35）。**装反不用改硬件**，校准向导会现场学 `sign = -1` 自动纠正；幅度不够才需要看摆位/算法 |
| 静站会不会误报 | 站着别动点「开始 10 秒静息自检」 | 报 N 跳 / M 蹲和误报帧占比。超线（>2 次 或 >6%）时，校准向导会把雷达跳/蹲停用并退回键盘 —— 这是**有意的降级**，请把这两个数字反馈给做算法的人 |

### 4. 连不上时按这个顺序查

1. 地址是不是写成了 `127.0.0.1`（那是"本机"，雷达在别的机器就得写它的局域网 IP，且同一网段）；
2. 雷达侧服务是否在听、是否绑了 `0.0.0.0`、防火墙是否放行端口；
3. 页面是 `https` 却连 `ws://` 会被浏览器拦（混合内容）—— 用 http 打开本页，或让雷达侧上 `wss://`；
4. 连上但一直没帧：雷达侧发的是二进制/非 JSON，或字段名不对（要每帧一个 JSON 对象，也支持一次发一个数组）；
5. 有帧但 `x` 恒定不动：确认有人站在探测区里走动，或采集端把 `x` 写成了常量。

### 5. 反馈给开发时请带上

- 联调台的**数值区截图**（帧率/延迟/丢帧）和 **x 波形截图**（能看出是否贴线）；
- 校准向导每一步的**提示原文**（尤其是"太弱"、"静站误报 N 跳 / M 蹲"、"雷达没数据"这些）；
- 控制台里 `RR.Calibration.load()` 的输出（含 `probe` 与 `x0` / `sign`）；
- 是**哪台机器、哪个浏览器**打开的（Chrome/Edge 版本），以及雷达服务是哪个程序起的。

### 6. 三个小工具（都在 `tools/`，纯 Python 标准库、不用 pip）

| 工具 | 用途 | 典型用法 |
|---|---|---|
| `radar_bridge.py` | **真雷达接入的核心**：把串口 / UDP / TCP / HTTP / 厂商 SDK 的原始输出，转成游戏能连的 ws JSON | `python tools/radar_bridge.py --from udp --udp-port 8888 --parse json --print-sample` |
| `check_radar.py` | 雷达体检：逐层报 TCP / 握手 / 帧率 / 字段 / 数据质量，一句话定位卡在哪一环 | `python tools/check_radar.py ws://192.168.1.23:8766` |
| `csv2replay.py` | 把动作级 CSV 展成可回放数据（离线看关卡表现，不接硬件） | `python tools/csv2replay.py in.csv out.js --go 5 --ret 8` |

`radar_bridge.py` 支持的解析方式：`json`（含数组、`{"data":{...}}` 这类外层包装）、`kv`（`x=0.31 jump=1`）、
`csv`（按 `--fields` 指定列序）、`regex`（命名组抓字段）、`raw`（纯数字按列序）。
上游类型：`udp`、`tcp`、`tcp-listen`、`http`、`exec`、`stdin`。
换算：`--map x=px,jump=j`、`--scale-x`、`--offset-x`、`--invert-x`、`--jump-th`、`--crouch-th`。

### 7. 双雷达：两台雷达一台管左右、一台管上下

一台雷达只能判左右，跳/蹲容易和左右抢；两台雷达分工会稳很多。做法就是**跑两个桥接实例、错开端口**：

```bash
# 左右那台雷达
python tools/radar_bridge.py --from udp --udp-port 8888 --parse json --port 8766
# 上下那台雷达
python tools/radar_bridge.py --from udp --udp-port 8889 --parse json --port 8767
```

两个实例的**上游端口**（8888 / 8889）和**输出端口**（8766 / 8767）都必须不同，否则第二个会起不来；两台雷达对着同一块场地时，尽量拉开间距或错开频段，避免互相串扰（详见 `docs/radar-diagnose-guide.md` 第 5.1 节）。

填地址的三个位置，任选其一即可生效：

| 位置 | 怎么填 |
|---|---|
| 游戏内校准向导 | 点「校准雷达动作」→ 勾选「两台雷达：一台管左右，一台管上下」→ 左右填 `ws://<IP>:8766`，上下填 `ws://<IP>:8767` → 连接 |
| 主页雷达地址 | 同一台机器时左右雷达用 `?radar=` 记住地址，上下雷达进游戏后在校准向导里补 |
| 联调台 `radar-connect.html` | 勾「双雷达」后两路分别填地址，可以同时看两路帧率和波形 |

游戏里两路只要有一路没连上，校准向导会直接说明是哪一路，不会让玩家对着「跳一下…」干等。

### 8. 数据体检台 `radar-diagnose.html`

比联调台更「出报告」的一个页面：双路同时录制 → 10 步打点 → 20 项自动检查（帧率、丢帧、延迟、x 抖动、极性、误报、射频互扰 A/B 等）→ 一键导出 JSON + CSV。

- 入口：主页「雷达」下方 → **雷达排障 → 数据体检**
- 什么时候用：联调台能连上但动作手感不对、或者要给别人复现问题时，用它把「哪一项不达标、差多少」量化出来
- 报告里的每一项都带阈值和建议，导出后可以直接发给做算法/硬件的同学

> 注意：页面自身不发任何数据，报告在本地生成。**线上 HTTPS 页面不能连 `ws://`**，要么本地双击文件打开，要么 `python -m http.server` 起 http 再访问。
