## 2. 纠正一处错误表述：`radar_live_ws.py` 没有 `--auto-band`

`docs/handoff-20261117-dual-radar-tuning.md` §5 第 2 条建议「改成 `--auto-band`
（lr 侧已有）」。实际 `dual-radar-kit/tools/radar_live_ws.py` 的 argparse 里
**只有 `--band`、没有 `--auto-band`**：

```powershell
Select-String -Path dual-radar-kit/tools/radar_live_ws.py -Pattern "auto.band"   # 无命中
```

| 场景 | 实际参数 | 出处 |
|---|---|---|
| 水平实时桥接 | `--band 0.5,1.9`（覆盖 1.02 / 1.70 两个 bin） | `LR_ARGS` |
| 竖直实时桥接（跳蹲） | `--jump-band 1,3`（bin 索引带） | `UD_ARGS` |
| 采集脚本 | `--auto-band`（5%~95% 分位定带） | `segment_capture.py` |
| 离线识别器 | `--auto-band` | `radar_actions.py` |

**结论**：实时桥接侧想「自适应距离带」需要新写功能，不能靠加一个参数。
现场若站距变了，先改 `LR_ARGS` 的 `--band` 或 `UD_ARGS` 的 `--jump-band`。

## 8. 现场诊断：几何未固定时的 zero 漂移（11:03 实测）

**前提**：板子是临时随手放的，没有对准人、没有固定。这组数据的作用是
**对照组**——说明"随便摆"时误差有多大，而不是可用结果。

设备：COM3（CP210x）单板在线；COM6 不在（竖直板未插）；COM5 有设备但未分配角色。

### 8.1 两次启停的 zero 不一致

同一人、同一板、同一位置，仅重启进程：

| 次 | zero | x 表现 |
|---|---|---|
| 第 1 次 | **−3.8°** | 全程 **+1.00**（饱和） |
| 第 2 次 | **+17.9°** | 全程 **−0.43 ~ −0.65** |

差 **21.7°**，x 符号翻转。满幅 20°（`--scale-deg 20`）⇒ **折合 1.08 个满幅**，
即完全饱和。

### 8.2 扇区分布（12 s / 93 帧 / 7.5 Hz）

```
有回波 32/93 (34%)
+15°~+30°  → 43 帧   （主峰）
−20°~−5°   → 18 帧   （次峰）
az 范围 [-25.3, 34.0]  中位 16.2
```

两个峰分列两侧、只有 34% 有回波 ⇒ 典型「一半帧在打墙」。

### 8.3 结论

1. `zero` 取的是"最强静止点"，环境（墙/显示器）会赢过站着不动的人。
   **几何不固定时，zero 每次都可能锁到不同位置**，x 因此整体平移并饱和。
2. 饱和后 `enterThreshold 0.12 / 0.22` 全落在同一侧，**失去区分度**。
   这是"越调越难用"的机械原因——不是判据退化，是输入坐标错位。
3. 因此在几何固定之前**不要改判据参数**。

### 8.4 固定几何的验收判据（四条，下次上台照验）

| 判据 | 对照组实测 | 达标值 |
|---|---|---|
| 有回波帧占比 | 34% | ≥ 60% |
| 主峰集中度 | 43/93 分散 | 最大桶 ≥ 40% 有回波帧 |
| 人左右移动时峰跟随 | 未测 | ≥ 10° |
| zero 落在人的角度上 | 偏 21.7° | ±5° 内 |

四条全过 → 再跑「连续启停 10 次记录 zero」的重复性实验，给出
`zero = 均值 ± 标准差` 与 `折合 x 误差`，作为可复现性与量化误差的答辩材料。
