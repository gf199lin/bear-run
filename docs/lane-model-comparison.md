# 左右移判定：规则阈值 vs 机器学习（2026-11-24 实测对比）

> **整合仓库（main）说明**：本文件的代码与数据路径以雷达工作区（`radar-lr3c` 分支）为准。本仓库里雷达代码位于 `radar-service/radar-pointcloud/`；可复现脚本 `tools/compare_lane_models.py` 目前只在 `radar-lr3c` 分支提供，结果 JSON 已一并提交在 `outputs/lane-eval/`。

> 结论先行：**现状是纯规则阈值，没有任何机器学习参与在线判定。**
> 在同一批 16 个带真值录制、224 个动作段上做留一文件验证，**机器学习（单隐层神经网络）
> 明显更准**：双门带口径 84% vs 规则 67%；把误报压到规则同一水平时 89% vs 67%。
> 但要提醒一句：`lr3b/lr3c` 这两个文件正是规则门限被调过的地方，规则在那里的分数是**样本内**的，
> ML 则是严格样本外——所以差距只会比表面数字更大，不会更小。

---

## 1. 现在到底用什么在判

### 1.1 左 / 右移：规则判据 `crit='xbase'`

实现位置 `radar-service/radar-pointcloud/radar_actions.py`：

| 环节 | 做法 | 出处 |
|---|---|---|
| 前级取点 | 距离带内**幅值加权质心** `px`（默认 `top_k=0, min_pts=2`） | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L596-L601) |
| 距离带 | 开机预热期统计各距离门点数，**锁一个门** `(j·0.68, (j+1)·0.68)` | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L855-L867) |
| 本帧证据 | `dev = median(近 0.80 s 的 px) − median(近 40 s 的 px)` | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L692-L709) |
| 判方向 | `dev ≥ +0.14 → LEFT`；`dev ≤ −0.12 → RIGHT` | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L302-L305) |
| 去抖 | 连续 3 帧同向才触发；两次触发至少隔 0.5 s | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L746-L760) |
| 滞回 | `abs(dev) ≤ 0.05` 且连续 3 帧才释放回 CENTER | [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L306-L309) |

即：**4 个手写数字（0.14 / 0.12 / 0.05 / 3 帧）+ 0.8 s 与 40 s 两个窗**，没有任何训练权重。

### 1.2 跳 / 蹲：也是规则，而且是「候选」

- 能量相对基线的比值：`≥1.9` 判起跳、`≤0.50` 判下蹲，持续 3 帧才报一次
  —— [radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L764-L793)。
- 曾经训练过一个 3 类 softmax，但**被自己标成不可用**：`models/jumpduck.json` 里
  `"usable": false`、`loso_accuracy: 0.5579`。
- 本次重跑 `tools/eval_jumpduck_offline.py` 得到同样结果：LOSO **58.8%（20/34）**，
  Wilson 95% 区间 **42.2%–73.6%**，下界低于随机 50%
  → 这批数据里**跳/蹲方向不可分**，不能用 ML，也不该记成「已验证」。

### 1.3 所以

| 动作 | 现状 | 有无 ML |
|---|---|---|
| 左 / 右移 | 规则阈值 + 滞回 + 确认 | 无（只有离线实验脚本） |
| 跳 / 蹲 | 规则能量比（仅候选） | 试过，不可用 |

## 2. 实验设计（怎么比才算公平）

脚本：`tools/compare_lane_models.py`（新增，可复现）。

**同一份输入。** 规则和 ML 都直接读产线 `ActionRecognizer(band=..., crit='xbase')` 逐帧输出里的
`px / py / energy / n`，不各算一遍——旧脚本 `tools/train_lane.py` 自己重算了「最强点 px」，
和产线不是同一个统计量，这也是它当年得出「ML 不行」的原因之一。

**同一套打分。** 命中窗口 `[t_start−0.5, t_end+0.5]`、延迟 = 段内首个同向事件 − `t_start`、
误报 = 不落在任何窗口内的事件（与 `tools/lane_eval.py` 一致），误报再按分钟归一。

**同一套状态机。** ML 的逐帧概率不是直接出事件，而是过 `confirm=3 + 最短间隔 0.5 s + 释放确认 3 帧`
的同一状态机，再产生 `LANE_*`。比的是整条链路，不是逐帧分类准确率。

**留一文件验证（16 折）。** 每折用 15 个文件训练、1 个测试，**概率阈值也只在训练折上选**
（目标 = 命中率 − 误报/分钟 惩罚），测试文件一个参数都不碰。

**数据。** 仓库里带 `LEFT/RIGHT` 真值、且是 1T2R 的录制共 16 个（按 md5 去重：
`cap-long-1020/action` 与 `m2_smoke_a/b`、`_reg-smoke` 是**字节级相同的 4 个副本**，只留 1 个；
`_dx-smoke/t.bin` 是 0 字节空文件，丢弃；`seg-2t4r` 是 2T4R 板，帧周期不同，另算）。
合计 **224 个动作段（LEFT 112 / RIGHT 112）**，约 47 分钟。

**数据有效性（用户要求只看「有效部分」）。** 用「目标检出率」做客观筛选：
`det = 有 px 的帧占比`（这里是**生产口径**：质心点 + 自动选带）。结果呈明显断崖：

| 站位 | 检出率 | 判定 |
|---|---|---|
| 0.70 m | 0.43–0.83 | 有效 |
| 0.85 m | 0.48 | 有效 |
| 1.00 m | 0.28–0.58 | 大部分有效 |
| 1.25 m | 0.24–0.41 | 边缘 |
| 1.50 m | 0.13–0.39 | 边缘 |
| 2.00 m | **0.12** | 无效（人已掉出自选距离门） |

`det < 0.35` 的 5 个文件是 `once-100`、`seg-125`、`seg-150`、`stride-150`、`m2recap-200`，
规则在上面基本 0–4/10 命中——**这不是判据不行，是数据里没信号**，不能拿来当反例。
（换成「最强点」口径后检出率整体升到 0.34–0.98，所以 §3.2 的主对比保留全部 16 个文件；
只看有效子集的结果即 §3.1 的 MVP 子集那一行。）

## 3. 结果

### 3.1 口径 A：产线默认（质心点 + 自动选带，`top_k=0, min_pts=2`）

16 文件 / 224 段：

| 方案 | 方向正确 | 延迟中位 | 误报 |
|---|---|---|---|
| 规则 `xbase` | **86/224 = 38%** | 1.94 s | 3.1 /min |
| 逻辑回归 | 158/224 = 71% | 1.30 s | 10.1 /min |
| 决策树（深 5） | 158/224 = 71% | 1.17 s | 8.4 /min |
| 神经网络（16 隐单元） | 149/224 = 67% | 1.29 s | 5.6 /min |
| 神经网络·等误报（thr 0.8） | **124/224 = 55%** | 1.30 s | 2.6 /min |

MVP 几何（0.7–1.0 m，10 文件 / 156 段）：规则 **46%** → 神经网络 73%，等误报 65%。

### 3.2 口径 B：最强点 + 覆盖两个距离门（`top_k=1, band=1.0,2.6`）

| 方案 | 方向正确 | Wilson 95% | 延迟中位 | 误报 |
|---|---|---|---|---|
| 规则 `xbase` | **150/224 = 67%** | 60.6–72.8% | 1.68 s | 7.9 /min |
| 逻辑回归 | 198/224 = 88% | — | 1.42 s | 9.5 /min |
| 决策树（深 5） | 177/224 = 79% | — | 1.42 s | 5.5 /min |
| 神经网络 | **188/224 = 84%** | 78.6–88.2% | 1.42 s | 4.1 /min |
| 神经网络·等误报（thr 0.6） | **200/224 = 89%** | 84.6–92.7% | 1.42 s | 6.3 /min |

「等误报」= 把 ML 的误报压到 **≤ 规则的水平（7.9/min）**再看命中，也就是最苛刻的比较方式。

逐文件胜负：神经网络在 **13/16** 个文件上优于规则（符号检验 p = 0.021）。
明显输的只有 `lr3c`（8/16 vs 15/16），`lr3b`（13 vs 14）和 `lr2-p1-d100`（17 vs 18）属于基本持平；
而 `lr3b/lr3c` 恰恰是规则门限被调过的那两份数据。

### 3.3 三个模型谁更合适

- **神经网络 > 决策树 > 逻辑回归。**
  逻辑回归在低误报区崩得最厉害（等误报只有 65%），说明这个决策边界明显是**非线性**的：
  光靠 `dev` 一条线性轴分不开，得同时看「检出率 / 能量变化 / 抖动」这些量。
- 决策树命中 79%、误报 5.5/min、等误报区 81%，中规中矩；
  它的价值是**能直接把学到的门限读出来**（脚本会打印整棵树），适合用来核对「人写的阈值是不是差得远」。
- 神经网络的性价比最好：**84% 命中 + 4.1/min 误报 + 1.42 s**，
  三个指标同时优于规则（67% + 7.9/min + 1.68 s）。

## 4. 一个比"换模型"更值钱的发现：距离带只锁了一个门

`_lock_band` 里是 `band = (j·0.68, (j+1)·0.68)`——**只取一个距离门**
（[radar_actions.py](radar-service/radar-pointcloud/radar_actions.py#L863-L867)）。
而 1.0 m 站位的人同时落在 **1.02 m 和 1.70 m 两个 bin**，所以自动选带后
到 1.0 m 站位时检出率只有 **28–58%**，近一半的帧根本没有 px。

把带放宽到覆盖两个门（`1.0–2.6 m`）后：

| （最强点口径） | 检出率 | 规则命中 | 规则误报 |
|---|---|---|---|
| 单门（现状） | 34–98% | 123/224 = 55% | 5.0 /min |
| 双门（1.0–2.6） | 52–99% | 150/224 = **67%** | 7.9 /min |

**规则凭空多出 12 个百分点。** 这说明过去「规则只能到 55%」里，有相当一部分是前级丢帧，
不是判据本身的问题。这个改动风险低、收益直接，建议先做。

## 5. 建议（按优先级）

1. **先修前级**：自动选带改为覆盖相邻两个距离门（或按 5–95% 分位定带，与采集脚本
   `segment_capture.py --auto-band` 同口径）。这一条不改判据、只改取数，回归风险最小。
2. **ML 不做直接替换，先做影子对比**：把神经网络作为离线「第二判据」，与规则并行记录
   1–2 周现场数据，看真实误报率能否复现 4/min。仓库里 16 个文件只有 1–2 个人、单日采集，
   泛化压力还没真正验证过。
3. **若上线 ML**：需要①模型文件（权重 + 标准化参数）②逐帧推理封装（numpy 即可，7.7 Hz 完全够）
   ③`AGENTS.md` 要求的「1 秒内热键切回规则」的兜底开关。三者缺一不要上线。
4. **跳/蹲继续等验证门**：本轮确认 2T4R 俯仰数据 LOSO 58.8%（区间下界 42.2% < 50%），
   不可分。按 `docs/jump-duck-verification-plan.md` 走重采 + 原始帧（4×RX×32 bin）再评估，
   在达标前不要把 ML 结果写进验收。

## 6. 局限（必须写在结论旁边的部分）

- **样本**：16 个文件、最多 2 个受试者、单日采集；`lr3b/lr3c` 的规则门限是**同一批数据调的**，
  规则分数偏乐观，ML 是严格留一文件外推。
- **单种子**：神经网络只跑了一个初始化种子，没有做多种子平均，逐文件波动大概 ±5 个点。
- **阈值选择**：每折在训练集上调阈值，折间阈值在 0.6–0.7 附近抖动，会带来少量方差。
- **几何**：1.25 m 以上检出率与命中一起塌，说明当前安装几何只对 0.7–1.0 m 站位成立；
  跨站位结论需要重采。
- **不含延迟优化**：ML 的 1.42 s 与规则 1.68 s 都远高于 7.7 Hz 的物理下限，
  真正的体验瓶颈是「滑动窗 + 3 帧确认」，不是分类器本身。

## 7. 复现

```powershell
# 主对比：产线默认口径（质心 + 自动选带）
python tools\compare_lane_models.py --subset all --top-k 0 --min-pts 2 ^
    --out model-compare-all-centroid.json

# 最强点 + 自动选带
python tools\compare_lane_models.py --subset all --top-k 1 --min-pts 1 ^
    --out model-compare-all-strongest.json

# 有效子集（检出率 >= 0.35）
python tools\compare_lane_models.py --subset all --top-k 1 --min-pts 1 --min-det 0.35 ^
    --out model-compare-valid.json

# 双门带：规则与 ML 同口径对比（主力结论）
python tools\compare_lane_models.py --subset all --top-k 1 --min-pts 1 --band 1.0,2.6 ^
    --out model-compare-band.json

# 只跑规则（快，用于 A/B 距离带）
python tools\compare_lane_models.py --subset all --top-k 1 --min-pts 1 --band 1.0,2.6 ^
    --min-det 0.35 --rule-only --out band-1p0-2p6-rule.json

# 跳/蹲：ML 可分性复核
python tools\eval_jumpduck_offline.py
```

产物（`outputs/lane-eval/`）：

- `model-compare-all-centroid.json` — 产线默认口径，16 文件全量
- `model-compare-all-strongest.json` — 最强点口径
- `model-compare-valid.json` — 检出率 ≥0.35 的有效子集
- `model-compare-band.json` — 双门带主力对比（规则 / 三个 ML 模型 / 等误报曲线）
- `band-1p0-2p6-rule.json` — 双门带下的规则基线（A/B 用）
- `model-compare-mvp.json` — 0.7–1.0 m MVP 几何子集

规则基线在 16 文件全量上是 **123/224 = 55%**（自动选带、最强点），
与 `outputs/lane-eval/lr3c-xbase.json` 里 `lr3c 15/16` 的口径一致，可交叉核对。
