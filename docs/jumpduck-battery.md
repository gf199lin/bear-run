# 跳/蹲 采集电池（jumpduck_battery）

> 2026-11-13。用于「换人、换场地」这一批补采，目标是**这次采完就能把跳/蹲并入游戏**。
> 界面与 `vguide_1t2r.py` 完全一致（大字 + 环形倒计时 + 语音），只换了采集段表。
> 程序：`tools/jumpduck_battery.py`；页面：`tools/jumpduck_battery.html`；
> 一键启动：`启动-竖向采集电池.cmd`。

## 1. 为什么要重采（上一批的缺口）

`docs/vguide-1t2r-analysis-1112.md` 的结论是「雷达 0.5 m + 人 1.2 m + 同一仰角」下
跳/蹲谱宽双峰 13/13 全对，但文档自己列了三条未解决：

1. **同一人**（身高、腿长、动作习惯都没变过）→ 换人会怎样，未知；
2. **同一天同一房间**（多径、背景反射固定）→ 换场地会怎样，未知；
3. **走动误报**：静息段误报谱宽 0.18–0.24，正好落在蹲的区间 → 游戏里人一定会走动，这是最大风险。

本程序就是针对这三条设计的，额外补上「幅度分层」和「游戏节奏（连跳/连蹲）」。

## 2. 一条命令

```powershell
# 单人，约 4.5 分钟（推荐先跑这个）
python tools\jumpduck_battery.py --port COM3 --id S01 --height 175 --tier p0 --tier p1

# 多人（每人一个目录，互不覆盖）
python tools\jumpduck_battery.py --port COM3 --id S02 --height 162 --tier p0 --tier p1

# 只看计划，不碰硬件
python tools\jumpduck_battery.py --plan --tier p0 --tier p1

# 先试一块，确认场地干净
python tools\jumpduck_battery.py --port COM3 --id S01 --limit 3 --no-speak
```

也可以双击 `启动-竖向采集电池.cmd`（默认跑 p0+p1）。端口默认 COM3，换板子用 `--port COMx`。

## 3. 现场五条纪律（不满足就别开始）

1. **清场**：除受试者外所有人退到雷达视场外（水平 ±45°、2 m 外）。
   实测同一位置，有人在场内走动时静息段 `nz_p90` 会从 0.10 涨到 0.38，
   动作段和噪声就分不开了。
2. **摆法沿用已验收的那套**：雷达约 0.5 m 高、仰视约 20°、人站 1.0 m。
   换摆法等于换物理模型，本次不验证摆法。
3. **一次只做一件事**，做完立刻回站姿。每段只有 3.5 s，7.7 Hz 下只够一次动作。
4. **风扇、门、窗帘、晃动的线**全部处理掉，它们会一直贡献非零多普勒。
5. **每块采完看控制台的 `nz_p90`**：静息段应 < 0.20；动作段应明显高于静息段。
   连续两块告警就停下来查环境，不要硬采。

## 4. 采了哪些段

| tier | 内容 | 作用 |
|---|---|---|
| p0 | 静息 12 s；中跳 ×4；中蹲 ×4；原地踏步 8 s ×2；左移 ×3；右移 ×3 | 生命线：标定 + 最小负样本 + 保护已有左右移能力 |
| p1 | 小跳 ×2、大跳 ×2、浅蹲 ×2、深蹲 ×2；弯腰 ×3、转身 ×3 | 找阈值余量；弯腰是最危险的负样本 |
| p2 | 连跳 ×2、连蹲 ×2、跳蹲交替 ×2 | 游戏节奏，验证「一次动作 = 一个事件」 |
| （预留）p3 | 1.4 m / 1.8 m 站位各 2 跳 2 蹲 | 未启用，站位鲁棒性等这一批看完再决定 |

每段结构固定：**准备 1.6 s（语音播报）→ 动作窗 3.5 s → 回站 3.0 s**。
动作窗标签 = 该动作真值，回站窗标签 = `rest`。真值全部由程序按段边界自动打，
不依赖人工记时（上一批的教训就是人工计时把动作推到了空档里）。

## 5. 输出

```
data/jumpduck_battery/<时间戳>_<受试者ID>/
  meta.json        受试者、身高、端口、tier、band、fps
  blocks/*.npz     每块一存（中途断电只丢当前块）
  frames.npz       合并后的原始 IQ：z(N,2,64,8) complex64、t(N,)、label(N,)
  labels.json      每块边界 + 质检结果
  metrics.csv      每块帧数、nz_p90、动作段 nz_p90
```

字段与 `data/vguide_1t2r/` 保持一致，现有分析脚本可直接读
（`np.load(..., allow_pickle=False)` 即可，label 是定长字符串）。

## 6. 质检怎么读

程序每块结束打印：

```
  2 jump_m    jump  frames=25  nz_p90=0.837
```

- `nz_p90`：该块非零多普勒能量占比的 90 分位。静息 ≈0.05–0.15，动作 ≈0.6–1.0。
- 动作段门限是**自适应**的：`max(0.25, 静息底噪 + 0.20)`，
  所以场地底噪高的时候不会把所有动作都误判成"没做动作"。
- 出现 `<< 质检告警` 表示这一段要么没做出动作，要么被环境噪声污染，**建议当场重做**。

> 这里的 0.25 / 0.20 是**采集质检门限**，不是识别阈值；识别阈值等这一批数据出来再标定。

## 7. 中断与续采

- 随时 `Ctrl+C`：已采的块都在 `blocks/` 下，`frames.npz` 会保存已完成部分。
- 续采不合并目录：换 `--id S01b` 再跑，分析时按 `meta.json` 的受试者分组即可。
- 换人要**换 id**，并在 `--note` 里写清身高、鞋、场地，例如
  `--note "赤脚/会议室/靠窗"`。
