1. 每条用例执行后，在「执行结果」栏填写 **实际值**，并在「证据」栏填写**证据文件名**（截图/录屏/CSV 名称）。
2. 「真值标注」栏说明该用例如何获得客观参照——**没有真值的测试不算测试**，不得用"看起来正常"代替。
3. 未执行的用例，「执行结果」栏保持空白，不得预填。
4. 变更阈值必须同时更新本表与 PRD，并记录变更人与日期。

### AC-1 左 / 中 / 右 识别正确率

| 项 | 内容 |
|---|---|
| 前置条件 | 校准完成；受试正对雷达 1.0 m |
| 操作步骤 | 由第三方随机指令（左/中/右，三类各 10 次，共 30 次），受试执行；记录每次**指令真值**与**系统识别结果** |

### AC-5 校准耗时与成功率

| 项 | 内容 |
|---|---|
| 前置条件 | 玩家位于雷达前方 0.5–1.5 m |
| 操作步骤 | 执行 10 次校准（每次校准前重置状态，可略微改变站位）；记录每次耗时与是否成功 |
| 判定阈值（提案） | 耗时 ≤ 5 s；成功率 ≥ 90%（10 次至少 9 次成功） |
| 真值标注 | 秒表计时 + 操作员记录成功/失败 |
| 证据 | `ac5_log.csv` |
| 执行结果 | |
| 证据文件名 | |
| 备注 | 站位过于偏离（如侧对雷达）导致的失败应单独注明，不计入"设备不可用" |

### AC-6 目标丢失与恢复

| 项 | 内容 |
|---|---|

| 真值标注 | 录屏（可回看时间点） |
| 证据 | 录屏 + 事件日志（`TARGET_LOST` / `TARGET_BACK` 时间戳） |

| 备注 | 重点确认"不扣命"——这是玩家体验的硬要求 |

### AC-8 无指导可玩性

| 项 | 内容 |
|---|---|
| 前置条件 | 找 2 名**未参与本项目**的同学 |
| 操作步骤 | 不做任何口头教学，仅让其自行开始游戏；观察并记录：是否理解操作方式、是否完成一局、卡在哪里 |
| 判定阈值（提案） | 2 人中至少 1 人无需口头帮助完成一局；2 人都在 30 s 内理解"移动身体换道" |
| 真值标注 | 观察员书面记录（含卡点描述） |
| 证据 | 观察记录 + 现场照片/录屏 |

| 备注 | 若失败，说明需增加引导界面，属产品问题而非算法问题 |

## C 组：数据链路

### AC-9 录制与回放一致性

| 项 | 内容 |
|---|---|
| 前置条件 | 已录制一段 ≥ 60 s 的真实雷达数据（含左右移动动作） |
| 操作步骤 | 用回放模式重跑同一段数据，导出事件序列；与实时运行时的事件序列对比 |
| 判定阈值（提案） | 事件序列一致率 ≥ 90%（事件类型与相对时刻在 ±1 帧内视为一致） |
| 真值标注 | 实时运行的原始事件日志本身就是参照基准 |
| 证据 | `ac9_realtime.csv` / `ac9_replay.csv` + 差异对比表 |

| 备注 | 回放不一致通常意味着依赖了非确定性元素（如实时抖动状态），需排查 |
