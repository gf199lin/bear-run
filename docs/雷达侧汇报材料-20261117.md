## 1. 一句话结论

**我用矽典微 1T2R 毫米波雷达（DEV202H / ICL1122）做出了「无摄像头的身体动作 → 游戏事件」的完整链路：自己逆向串口协议拿到点云，自己搭采集与真值标注流程，用规则法把左右换道识别从 59% 做到 93.8%（16 个动作命中 15 个，延迟中位 1.81 s），并额外验证了跳/蹲识别（96 个样本 85.4%）。**

> 我们中途试过监督学习，结论是**在这批数据上不成立**——不是模型没调好，是信号信噪比 < 1。所以我们把力气从「换模型」转到了「改采集协议、改判据、改几何」，这才是准确率真正涨上去的原因。

## 3. 硬件与链路：先把「雷达到底能看见什么」钉死 `[PPT-P3]`

### 3.1 两块板，两条完全不同的链路

| | **1T2R（主用）** | **2T4R（备用/实验）** |
|---|---|---|
| 型号 / 芯片 | DEV202H / ICL1122 | DEV113P |
| USB-UART | CP2102（装 CP210x 驱动） | FT232（FTDI） |
| 串口 / 波特率 | COM3 / 921600 | COM4 / 1500000 |
| 上行帧格式 | 裸 40 B 帧（另有一种 52 B 带包头包尾的封装形态） | 136 B（32 bin）或 72 B（16 bin）帧 |
| 实测帧率 | **7.7 Hz（129.5 ms/帧）** | 基线 **1.92 Hz（520.8 ms/帧）**；130 ms 配置可跑到 7.6～7.7 有效帧/s，但每帧只出 32/64 chirp |
| 距离分辨率 | **0.6813 m，只有 8 个距离门** | 0.150 m，32 bin |
| 速度 | 分辨率 0.048 m/s，量程 ±1.535 m/s | 量程仅 ±0.376 m/s（易混叠） |
| 视场 | 水平 ±45°，垂直 ±25° | 同量级 |

### 3.2 三件必须先讲清的事实（它们决定了后面所有设计）

1. **7.7 Hz 是全项目的体验上限**。任何交互设计都先过这一关：一帧 129.5 ms，人做一次动作只有 20 帧左右。
2. **垂直（俯仰）角不可用**：1T2R 没有可用的垂直通道组合，测不到人体高度。跳/蹲不能靠「测高」解决。
3. **距离分辨率 0.681 m，比人的站距还粗**。人站 1.0 m 时，身体的点只在 1.02 m 和 1.70 m 两个 bin 之间跳——这一点后面直接导致了一次「检出率只有 48%」的误判。

### 3.3 链路层做了什么（工程贡献，不是「接上就能用」）

- **协议逆向**：上行 52 B 封装（`ICLH` + len + seq + 40 B 帧 + `ICLT`）与裸 40 B 帧两种形态都解开，与固件行为双向核对；合成自检 40/40 通过，方位角最大误差 0.29°。
- **板型自动识别**：按 USB VID:PID 自动判板（CP210x → 1T2R 921600；FT232 → 2T4R 1500000），自动切解析器与 DSP 距离单元数。**同一条命令两块板都能跑**，避免现场插错板。
- **物理刻度收口**：2T4R 从厂商 `Radar_Config.ini` 的 `[WAVE_INFO_0]` 反算出带宽 999 MHz → 0.150 m；同一套公式代回 1T2R 得到 0.6813 m / 24.125 GHz / ±1.535 m/s / 6.250 mm，与代码常量**五项逐字吻合**，换算链可信。
- **2T4R 提帧率的结论（负面但有价值）**：1.92 Hz 采不到跳跃腾空段，尝试压到 130 ms——数据带宽只占串口 47%，**瓶颈不是波特率**；3 Mbps 芯片接受命令但不出流（已证伪，不要再试）。真正原因是每帧只出偶数索引的 32/64 个 chirp。

> 讲这一段的目的：说明「硬件对接」不是插线，而是把物理量、帧格式、板型差异都变成可复现的代码常量。

## 4. 识别链路：从点云到事件 `[PPT-P4]`

```
串口字节流
  → 解析（双格式自适应：封装帧 / 裸帧）
  → DSP：距离 FFT → 多普勒 FFT → 去静态杂波（MTI）→ CFAR 检测 → 3×3 局部极大值抑制
        → 双 RX 相位差解方位角 → 距离带 / 方位扇区过滤
  → 每帧特征：带内幅值加权横向质心 px、带内点数 n、能量 pa、径向速度 v_r、多普勒谱宽 w、非零多普勒能量占比 nz
  → 判据 + 状态机（阈值 / 滞回 / 连续确认 / 最短间隔）
  → 事件：LANE_LEFT / LANE_RIGHT / JUMP / DUCK / TARGET_LOST / TARGET_BACK
```

### 4.1 左右换道：用「相对位移」，不用绝对位置

- **横向质心 px**：每帧把距离带内的点按功率加权求横向位置 `px = Σ(pa·x)/Σpa`，比「取最强一点」稳（最强点会在人体多个散射中心之间乱跳）。
- **核心判据 `xbase`**：
  ```
  dev = median(最近 0.8 s 的 px) − median(最近 40 s 的 px)
  dev ≥ +0.14 → LEFT       dev ≤ −0.12 → RIGHT
  ```
  **为什么是「近窗减长窗」**：两个窗口都在同一段数据里现算，站位/姿态的慢漂移会同时进入两项并被相减抵消。这比早期「拿开头的静息段当参考系」（`drift`）稳得多——人一站偏，参考系就错了。
- **状态机三件套**：`|dev| ≤ 0.05` 且连续 3 帧才释放回中道（滞回）；触发要连续 3 帧确认；两次切换最短间隔 0.5 s。
- **符号是标定出来的，不是猜的**：本安装几何下「人向自己的左侧移动 ⇒ dev > 0」，LEFT 7/7 命中；代码里明确注释「勿凭直觉改」。

### 4.2 为什么先做规则法，不做深度学习

这不是偷懒，是三轮实验后的判断（见第 8 节）：**数据本身的信噪比 < 1 时，模型学到的只是噪声的形状**。规则法的好处是每一步都能用真值数据验证、能解释、能在现场调。

## 5. 数据怎么抓：这是我最花功夫、也最容易被低估的部分 `[PPT-P5/P6]`

### 5.1 第一个坑：真值不能用墙钟

最初用「按秒表记动作开始」，结果发现雷达帧率有 1～2% 漂移，一条 90 s 的录制就能错开好几帧，标签整体错位。

**解法**：采集时把原始字节原样落盘，离线再解析同一份字节 → 帧序号逐一对齐；**真值直接记帧号**，时间轴 = 帧号 × 0.1295 s。提示音响起那一刻记下的帧号就是 `frame_start`，与墙钟无关。

> 顺带修掉一个真 bug：提示函数原先返回「窗口结束帧号」，被当成动作起点用，导致真值整段偏后一格。改成返回起止帧号后，每个 2.5 s 的动作窗口能稳定捕获 19～21 帧。

### 5.2 采集协议：提示音驱动 + 分段定距 + 自动对照

一条命令跑完一轮，人只负责按提示做动作：

| 阶段 | 内容 |
|---|---|
| lead 20～30 s | 静息基线，同时用于**自动定距离带** |
| prep 3 s | 「准备」提示音 |
| move 2.5 s | 「嘟」一声开始做动作（左移/右移，跨步 0.3 m） |
| settle 3 s | 「停」静息 |
| rest 25 s | **无真值的静息段**，任何预测都记误报，用来量化误报基线 |

- 每类动作重复 8～10 次；
- 输出 `seg_XX.bin` + `seg_XX.labels.jsonl`（含 `_meta`：站位、距离带、帧率、扇区排除）+ 当场生成 `compare-all.txt` 逐段对照表；
- 浏览器引导页（`lr_guide.py` + `guide.html`）：人在雷达前看不到终端，所以用大屏显示「还要几秒」「现在该往哪走」「当前站在几度」。

### 5.3 自动定距离带（`--auto-band`）：一次真实的事故换来的

某批数据「检出率只有 47%、RIGHT 只剩 31 帧」。查下来不是信号差：

- 人的距离被量化成 **1.02 m / 1.70 m 两个 bin**（正好差一个 0.681 m 分辨率），身体厚度让点在这两个 bin 之间跳；
- 而当时写死的距离带 `[1.36, 2.04]` 只框住 1.70 那个 → 落在 1.02 的帧全判「没人」。

**修带后**：LEFT 帧 137 → 163，RIGHT 帧 31 → 162（左右帧数几乎相等），LEFT/RIGHT 的位移幅度也基本对称（0.256 vs 0.222 m）。这是「左右对称」这条硬指标第一次达标。

**落地的规则**：采集默认 `--auto-band`，用 lead 段 r 的 5%～95% 分位定带，**必须覆盖两个 bin**（如 `[0.90, 1.80]`）。不再用固定带。

### 5.4 排除「电脑那一侧」：雷达是斜放的

雷达板面不朝正前方，成像落在视场一侧，**另一侧是电脑/显示器，完全静止、反射很强**。早期用「取最强点」对准，工具报出 **−29°**，与人的实际位置差 38°，是错值。

**三条规则**（已写进工具）：

1. 采集与对准都必须 `--exclude-az lo,hi` 把电脑那侧扇区排除；
2. 判「是不是人」不看能量，看**分段时间占比**（静止体在静息/左/右三类帧里占比近似相等，人只在动作段出现）；
3. 中线以**静息段方位角中位**为准（当前实测 **+9°**），不采信单次对准读数。

## 6. 左右识别算法细节（老师可能会追问的）`[PPT-P7]`

### 6.1 一帧数据到特征

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 距离带 | 只保留人所在 bin（`[0.90, 1.80]` 覆盖 1.02+1.70） | 0.68 m 分辨率，带外全是杂波 |
| 近场门 | 排除 r < 0.7 m 的 j0 | 实测 j0 占 84% 点数、90% 功率，是 TX/RX 泄漏 |
| 扇区 | 排除电脑侧（+35°～+90°） | 强静止反射会锁死「最强点」 |
| 横向位置 | 幅值加权质心 px | 单帧最强点会乱跳 |
| 判据 | `dev = 近 0.8 s 中位 − 长 40 s 中位` | 抵消站位漂移 |
| 决策 | 阈值 + 滞回 + 连续 3 帧 + 最短间隔 0.5 s | 抑制单帧野值造成的重复触发 |

### 6.2 门限是怎么定的（不是拍脑袋）

在 `data/lr3b`（16 段，左右各 8）上扫门限，固定其余参数：

| 门限 L/R | 准确率 | 误报 |
|---|---|---|
| 0.14 / 0.18（旧默认） | 75.0% | 12 |
| **0.14 / 0.12（新默认）** | **87.5%** | 20 |
| 0.12 / 0.12 | 87.5% | 28 |
| 0.10 / 0.10 | 93.8% | 37（太吵） |

结论：**RIGHT 门限 0.18 → 0.12**。原因不对称——本安装几何下「右移」的物理位移比「左移」小（人本来就偏在一侧），所以右门必须更灵敏。这也解释了为什么不能用一套对称阈值。

### 6.3 延迟为什么压不下去（重要结论）

扫了 7 组窗口/确认/间隔组合，最好的一组仍是 93.8%，但延迟全部锁在 **1.55～1.81 s**（多数落在 1.68 s），参数只值 1 帧。拆解：

```
人的反应时间            ~0.3 s
横移 0.3 m 本身要的时间  ~1.0 s
dev 平滑需要动作过半     ~0.3 s
7.7 Hz 采样再丢 1 帧     ~0.13 s
≈ 1.7 s
```

**这是动作协议的物理下限，不是算法缺陷。** 想进 1 s 内只有两条路：改动作（快速挥臂/踏步，峰值 0.3～0.4 s 就出现）或游戏侧吸收（障碍提前 2 s 可见）。这两条都需要产品决策。

## 7. 精度提升的完整历程（最有说服力的一页）`[PPT-P8]`

> 注意：下表是**不同批次 / 不同扫描的对照**，不是同一批数据的连续迭代。每一行只改一个变量，便于讲「什么真的有用」。

| # | 数据集 / 样本 | 准确率 | 这一版改了什么 | 为什么涨 |
|---|---|---|---|---|
| 1 | 旧数据合集：7 文件 / 10522 帧 / 110 段 / **2 人** | **59%**（LEFT 25%、RIGHT 93%） | 基线：`xbase` + 旧距离带 `[1.36,2.04]` | — |
| 2 | `seg-lr2` 第二轮：**40 个动作** / 1 人 / 0.70+1.00 m | **75%**（L 11/20、R 19/20） | 判据从 `drift` 换 `xbase`（相对位移）+ 现场对准（静息 az +25.8°→+12.1°） | LEFT 从「结构性永不命中」变成能触发 |
| 3 | `data/lr3b`：**16 个动作** / 1.0 m | **75%**（L 8/8、R 4/8） | 距离带改 `[0.90,1.80]`，覆盖两个 bin | LEFT 帧 137→163、RIGHT 帧 31→162，左右首次对称 |
| 4 | 同 `lr3b` 上**扫参**（样本内） | **87.5%** | RIGHT 门限 0.18→0.12 | 右移物理位移更小，需要更低门 |
| 5 | `data/lr3c`：**16 个动作** / **独立采集** | **93.8%**（L 8/8、R 7/8） | 新默认门限 + 中线 +9° + 排除电脑扇区 | 静息位置真实了，左右位移才对称 |
| 6 | 同 `lr3c` 扫 7 组窗口参数 | 93.8%，延迟 **1.81 s** | 窗口 / 确认 / 间隔全试 | **没改善**，证明延迟是协议下限 |

**一句话**：59% → 93.8% 的涨幅里，**大头来自「把数据采对、把参考系选对」**（距离带、扇区、中线、相对位移判据），纯参数调整只占最后一步。

### 7.1 代价：误报 24 次 / 3.54 分钟

要主动讲，不要等老师问。这 24 次里绝大多数不是「静息乱触发」，而是**动作后回程触发**：人做完左移走回中位，`dev` 反向越阈 → 又发一个 `LANE_RIGHT`，游戏里会把角色换回去，危害等同误报。

已试过的三种解法：
- 峰值触发（把延迟压到 0.7～0.9 s）：有害事件涨到 8.5～30 次/分 → **否决**；
- 加冷却期 3 s：命中 90%、有害 4.9 次/分；5 s：命中 72%、3.2 次/分 → **治标**；
- 「触发后要求回到中性区并保持 0.5 s 再武装」：仍然没有一组做到「命中不降、有害下降」→ **该权衡前沿已到**。

> 讲法建议：「我们知道误报的成因，也知道三种解法的代价，现在需要产品侧决定是牺牲响应速度还是牺牲误报。」

## 8. 为什么最终没用机器学习（这一段最能体现判断力）`[PPT-P9]`

### 8.1 六种方法全部撞在 60%

同一批数据（7 个文件 / 10522 帧 / 110 个动作段 / **2 个人** / 站位 0.70、0.85、1.00 m），同一套段级口径：

| 方法 | 方向正确率 | 延迟中位 | 静息误报 |
|---|---|---|---|
| 规则 `xbase`（产线） | 59% | 1.81 s | 108 |
| 窗均值（1→30 帧） | 48% → 3% | 1.3→2.3 s | — |
| 变化率 `dx`（2→8 帧） | 32% | 1.17 s | — |
| 线性模型（无置信阈值） | **67%** | 0.39 s | **3725** |
| 线性模型（阈值 0.5） | 25% | 1.29 s | 685 |
| 线性模型（阈值 ≥0.7） | **0%** | — | 0 |
| 点云跟踪（最近邻 / +EMA） | 见下 | — | — |
| 会话内校准 + 规则 | 60% | 1.42 s | — |

**「67%、0.39 s」这一行最诱人，也是假象**：模型每帧都在猜，猜对叫命中、猜错就是误报（3725 次）。一旦要求置信度 ≥0.7，它**一个事件都不发**——说明模型从来没真正「认出」左右，只是拟合了噪声。

### 8.2 根因是信噪比 < 1（有量化证据）

| 量 | 值 |
|---|---|
| 静息 px 抖动 p90 | **0.425 m** |
| LEFT 的位移中位 | **+0.064 m** |
| RIGHT 的位移中位 | **−0.284 m** |

LEFT 的信号只有噪声的 **15%**。三个叠加原因：

1. **几何没对准**：静息 px 在 +0.33～+0.91 m，人明显偏在一侧 → 「左移」只是从偏右回到中心（位移 0.2 m），「右移」是继续远离（0.4 m）。**两个方向的物理幅度根本不对称**，任何模型都在放大这个不对称。
2. **测角精度不足**：1T2R 只有 2 个 RX，单帧测角抖动 0.4～0.65 m；而距离分辨率 0.68 m 与 0.7～1.0 m 站距同量级。
3. **检出率不稳**：部分会话带内检出只有 37～47% → 大量帧根本没有目标。

### 8.3 连「调 DSP」和「跟踪」也救不了

- DSP 放宽门限：检出率 69%→79%，但噪声同步涨，**SNR 反而从 0.88 降到 0.80**；收紧到 SNR 0.92，检出率掉到 63%。两头都不划算。
- 点云跟踪：σ 从 0.303 压到 0.262，**动作幅度也一起掉**，SNR 0.93→0.85；加 EMA 更糟（0.62）。**平滑同时衰减信号和噪声，SNR 不变。**
- 关键发现：只保留符号稳定的那一个会话，top1 的 SNR 已经是 1.23，跟踪只提到 1.32 —— **噪声不是主因，几何才是。**

### 8.4 另一个旁证：跳/蹲的学习模型直接标了「不可用」

早期用 2T4R 竖直摆法的 **685 个窗口 / 7 个会话** 训了一个线性分类器，留一会话验证 **55.8%**，代码里直接写 `usable: false`。后来换成规则状态机，同一任务做到 85.4%（见第 9 节）。

**这就是我们的方法论结论**：
> 样本量小、受试者少、信噪比 < 1 的时候，**先修数据，再谈模型**。模型只会把噪声拟合得更像。

## 9. 跳/蹲：研究结论与失败边界 `[PPT-P10]`

> 状态说明：跳/蹲**尚未进入验收结论**（验证门未走完），以下是已执行的离线研究结果。

### 9.1 三层能力，逐层看

| 层 | 判据 | 结果 | 是否可靠 |
|---|---|---|---|
| L1 有没有身体动作 | 非零多普勒能量占比 `nz_p90 > 0.30` | 静息 0.037 vs 动作 0.52～0.94（**14 倍余量**） | **可靠** |
| L2 切向（左右）还是径向（上下） | 多普勒谱宽 `w90 < 0.22 → 切向` | 块级 **34/37 = 91.9%**，两类之间有 0.09 空档 | **可靠** |
| L3 向上还是向下 | 见 9.2 | 见下 | 有条件可用 |

### 9.2 跳 vs 蹲：不能用幅值，要用「时间结构」

失败过的两条路（都有数据）：

- **谱宽**：小 0.17～0.23 → 中 0.29～0.40 → 大 0.38～0.54，单调跟着**幅度**走，与跳/蹲无关；大幅跳 vs 深蹲 Cohen d = **+0.06**（完全重叠）。
- **速度幅值/符号**：蹲的起身正峰 **0.88 m/s，比跳的正峰 0.46 还大**；平均径向速度符号在 129.5 ms 积分窗里被对称展宽抵消（正负峰几乎相同）。

**有效的判据：径向速度「同号连续段」的长度**

| 动作 | 最长负段（帧） | 最长正段（帧） |
|---|---|---|
| 轻跳 | 1～2（<0.3 s） | 0～2 |
| 深蹲 | 4～6（>0.5 s） | 4～6 |

分界 3 帧 ≈ 0.39 s。浅蹲的 `v_r` 会在 ±0 抖动，加**因果 EMA（α=0.5，只用过去帧，实时可用）**后负段从 0 变成 3～4 帧。逐帧状态机：负段累计 ≥3 帧 → `DUCK`（其后的起身正段被一起吞掉，**不再误报为 JUMP**）；负段不足 3 帧就转正 → `JUMP`。

### 9.3 实测性能（四批 96 个跳/蹲样本，单人同日）

| 指标 | 结果 |
|---|---|
| 总判对 | **82/96 = 85.4%** |
| 蹲 | **47/48 = 97.9%** |
| 跳 | **35/48 = 72.9%** |
| 轻跳 + 深蹲专项 | **24/24** |
| 延迟中位 | **388 ms（3 帧）** |
| 静息块误触发 | **0 次** |

**失败模式很集中**：14 个错例全是「自然大幅跳」（9 例）和部分中跳（4 例）——人做「尽量跳高」时会本能深蹲蓄力，实测蓄力位移 **38.2 cm，比中蹲 30.3 cm、深蹲 29.4 cm 都深**。**这跟真蹲在物理上就是同一个动作**，只是意图不同。

> 给游戏的可执行结论：教学里写「**直接起跳、不要预蹲**」，按此提示的轻/中跳全部命中（`jump_m` 8/8、`jump_k` 12/12）。自然大跳会有一半被判成蹲，这是 7.7 Hz 采样决定的物理边界。

### 9.4 还没解决的两个问题（要主动说）

1. **负样本 8/8 全误报**：弯腰捡东西、原地踏步、转身的谱宽 0.32～0.54，与径向动作同一区间 → 会被当成跳/蹲。游戏里玩家站着不动没事，一弯腰就误触发。这是并入游戏前的**首要问题**。
2. **1T2R 拿不到可用俯仰角**：即使把板子转 90°（两天线上下排布），`dphi` 仍被静态杂波锁死——静息段方位角跨度就达 **159.4°**，跳 146～165°、左右 43～165°，各组无差异，连「有人/没人」都分不开。只保留非零多普勒单元后仍是噪声（跨距 150°）。
   - 物理原因：1T2R 只有一条 λ/2 基线，而 0.68 m 的 bin 里同时混着头、躯干、手臂多个散射体，「一个 bin ≈ 一个散射体」这个测角前提不成立。
   - 2T4R 竖直摆法也不分跳/蹲（1.426 vs 1.536 rad，只差 **0.11 rad**，小于类内波动；零多普勒占 86% 能量，人体回波低 30～50 dB）。**俯仰角的现实出路在 4 RX 阵列，但尚未验证。**

### 9.5 双板标定实验（说明我们确实试过「1T2R 测左右 + 2T4R 测上下」）

2026-10-29，双板并发，6 类动作 × 4 次 = 24 样本：

- **1T2R 水平**：零多普勒最强门上的双通道相位差，三档位置单调有序（右 0.234 / 中 1.231 / 左 2.065 rad），跨距 1.831 rad，段间一致性 R > 0.98，Fisher 4.46 → **左右可用**（但静止态 0.790 距右/中分界 0.732 只有 0.06 rad，**必须加滞回**）。
- **2T4R 竖直**：左右相位差 −0.331 vs −0.227（几乎同值，物理上就不敏感）；竖直方向只能判「有人在跳或蹲」，不能分方向 → **这条双板路线关闭**。
- 若一定要用 2 个 TX 做水平孔径，需要拆 TDM 帧，每 TX 只剩约 0.95 Hz，代价不可接受。

## 10. 踩过的坑与解法（挑 6 个讲，故事性最强）`[PPT-P11]`

| # | 现象 | 根因 | 解法 | 证据 |
|---|---|---|---|---|
| 1 | 跑 657 s 后页面不动，但录制文件还在长 | USB 抖动后设备**停止加包头包尾**，改吐裸 40 B 帧，旧解析器再也同步不上（数据一直在，全被丢） | `StreamParser` 双格式自适应 + 严格校验 | 78.7 MB 录制离线回放：封装 650,090 个 + 裸帧 1,123,463 个 = **100.0% 字节可解析** |
| 2 | 管道线程活着、HTTP 活着、文件在写，但帧号不动 | 只有线程存活判断，**没有帧级停滞检测** | 停滞看门狗（8 s 不增长即重建管道）+ 串口异常自动重连 + HUD 显示重连/丢帧 | 真机 31/31 项验收通过；`read_errors=0 reconnects=0` |
| 3 | 近处一直有点在闪 | bin0（0.34 m）占 **84% 点数、90% 功率**，是雷达自身前方泄漏的逐帧起伏 | `--min-range` 整门屏蔽；距离带只取人体所在 bin | 逐门占用统计 |
| 4 | 站在正前方时点云几乎消失 | 主因不是「没信号」：正对时保留 0.4 点/帧、两侧 2.8 点/帧；**所有被丢弃的点 100% 落在 j0**；另有 3×3 局部极大值抑制（抑制率 86% vs 74%）、MTI 把正对静止的人减掉 52% | 站位取距离门中心 + 修正带口径 + `--clutter-keep` 可调 | 60.1 s 横穿扫描，463 帧，**已执行** |
| 5 | 一次动作被记成两次换道 | 释放端只判单帧：一个 px 野值就把车打回中道，随即再触发 | 释放端改为**连续 3 帧确认**；`hold` 死条件修复（原实现恒假，车永不回中道） | 离线回归锁定 |
| 6 | 真值整体错位一格，报告全 0 | 提示函数返回「窗口结束帧号」，被当动作起点 | 返回 `(start, end)`；真值一律用帧号 | 修复后每窗口稳定 19～21 帧 |

> 第 1、4 条最适合现场讲：都是「看起来像硬件坏了，其实是软件口径/协议假设错了」。这种「先证伪再定位」的过程很能体现工程能力。

## 附录 A：指标口径（被问就照读）

| 指标 | 定义 |
|---|---|
| 准确率 | 事件落在真值动作窗口 **[t_start − 0.5 s, t_end + 0.5 s]** 内记为命中；命中数 ÷ 动作总数 |
| 延迟 | 命中事件的时刻 − 真值动作起点 `t_start`（不是墙钟，是帧号 × 0.1295 s） |
| 误报 | 不落在任何动作窗口内的事件数；`rest` 段（25 s 无真值）内的事件全部计入 |
| 检出率 | 距离带内至少有一个点的帧数 ÷ 总帧数 |
| 带内点数/帧 | 每帧落在距离带内的点数（中位数），衡量「信号够不够」 |
| SNR（本项目用法） | 动作位移中位 ÷ 静息抖动（p90），<1 表示信号被噪声淹没 |

### 三条制作提醒

1. **每页只放一个数字结论**。老师记不住表格，但会记住「信号只有噪声的 15%」。
2. **不要把 85.4% 和 93.8% 放同一页**。前者是离线研究、后者是产线指标，混在一页必被追问口径。
3. **准备一页备用的「口径与样本量」**（附录 A），放在最后不主动讲，被问再翻。

### 可能的追问与答法

| 老师可能问 | 建议答法 |
|---|---|
| 为什么不用摄像头/深度相机？ | 课程选题是无接触 + 隐私友好；毫米波不含图像，且成本低。 |
| 93.8% 是不是过拟合？ | 只有 16 个动作、单人单日，我们明确标注了适用范围；门限是在 lr3b 上扫的，lr3c 是独立采集验证。 |
| 为什么不用 CNN/LSTM？ | 我们做过对照：10522 帧 / 110 段上，线性模型无阈值 67% 但误报 3725 次，要求置信度 0.7 就 0 事件；根因是 SNR<1。 |
| 延迟 1.8 s 玩家能接受吗？ | 不能，所以我们同时给了两条路：改动作协议（快速挥臂）或游戏侧提前 2 s 显障碍。 |
| 误报 24 次怎么解释？ | 多数是「动作后回程」触发，已有三种抑制方案的量化代价，需要产品决策。 |
| 换个人还能用吗？ | 未验证；我们的方案是「每人 20 s 现场校准」，而不是追求通用阈值。 |
