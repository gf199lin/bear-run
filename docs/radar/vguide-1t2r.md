# 1T2R 竖直方向采集引导（vguide_1t2r）

> 2026-11-12。第二块 1T2R（DEV202H / ICL1122）**专用**，与水平左右移那条已经
> 验收过的链路完全隔离：`radar-pointcloud/` 与 `tools/` 里的既有文件一行未改，
> 只只读复用了 `radar_protocol.py` 的字节解析器。

## 1. 为什么 1T2R 能测竖直（以及为什么必须转板子）

1T2R 固件上传的是**原始复数 IQ**：8 个距离 bin × 64 chirp × 2 RX，
**协议里没有任何角度字段**。水平方位角是上位机算出来的：

```
Δφ = 2π · d · sinθ / λ        d = 6.25 mm，λ = 12.43 mm（24.125 GHz）
   ≈ 3.160 · sinθ             θ = asin(Δφ / 3.160)
```

两个 RX 在**水平面**内间隔 λ/2，所以算出来的 θ 是方位角。

**把第二块板绕光轴旋转 90°**，让两天线一上一下，同一个公式给出的 θ 就变成
**俯仰角**。这是 1T2R 测竖直的唯一物理路径，不是软件开关。

板子平放时，人上举/下蹲几乎不改变水平方位角 → 相位差基本不动。程序会在
安装自检里当场判出这种情况，并直接告诉你「必须转 90°」。

> 与 `AGENTS.md` 事实基线一致：1T2R 的 `VertAngleInfo` 无通道组合，
> **不转板子就没有俯仰角**。本程序不假设、不猜，用自检证据说话。

## 2. 用法

```powershell
# 插上就自动跑（自动选串口、自动开浏览器）
python tools\vguide_1t2r.py --port auto

# 两块板都插着时，两块都是 CP2102，程序认不出新旧 → 指定新板的口
python tools\vguide_1t2r.py --port COM5

# 只做安装自检（15 秒），不采动作数据
python tools\vguide_1t2r.py --port COM5 --selftest-only

# 3 轮、每段更长
python tools\vguide_1t2r.py --port COM5 --rounds 3 --sec-base 5 --sec-act 10

# 排障：只列串口 / 不碰硬件跑合成数据
python tools\vguide_1t2r.py --list
python tools\vguide_1t2r.py --simulate --no-open
```

也可以双击根目录的 `启动-竖直采集.cmd`（会打印上面这些前置要求）。

## 3. 流程

| 阶段 | 内容 | 是否计入真值 |
|---|---|---|
| 安装自检 | 站定 4 s → 双手上举 4 s → 下蹲 4 s → 站定 3 s | 否 |
| 正式采集 | （站好 4 s → 跳 8 s → 站好 4 s → 蹲 8 s → 站好 4 s）× N 轮 | 是 |

每段前有 1.6 s 语音播报 + 提示音，**不计入该段真值**。

### 安装自检怎么判

```
d_up = 上举段俯仰角中位数 − 站定段中位数
d_dn = 下蹲段俯仰角中位数 − 站定段中位数
noise = 站定段俯仰角的 IQR（用来兜住 1T2R 的测角抖动）
snr  = min(|d_up|, |d_dn|) / noise
```

- **ok**：`d_up` 与 `d_dn` 符号相反、各自 ≥5°、且 snr ≥2
  → 这块板当前朝向可以测竖直。
- **weak**：有反向迹象但幅度/信噪比不够 → 加大举手/下蹲幅度、站近一点重跑。
- **none**：几乎没有响应 → 板子 RX 连线还在水平面，**必须转 90°**。

要求「符号相反」是因为上举让俯仰角变大、下蹲让它变小；如果两者同向，
多半是整体漂移或走动，不是俯仰响应。

## 4. 页面

- 环形倒计时 + 大字动作（站好 / 跳 / 蹲）
- 顶部横幅：**安装自检结论**（绿=可用，黄=偏弱，红=测不到）
- 中部曲线：最近 ~160 帧的**两 RX 相位差**，虚线是 ±5° 参考带
- 底部：8 个距离 bin 的实时能量柱 + 相位差 / 角度 / 径向速度 / 主 bin / 距离

## 5. 产出

```
data/vguide_1t2r/<YYYYmmdd-HHMMSS>/
    frames.npz   z=(N,2,64,8) complex64, t=(N,), label=(N,)
    labels.json  段边界 + 自检结论 + 物理常量 + 距离带
    metrics.csv  每帧：相位差 / 俯仰角 / 主 bin / 质心 / 径向速度 / 带内能量
    report.md    自检结论 + 各段分布 + 单特征可分性 + 建议
```

`label` 取值：`idle`（播报准备）、`check_stand1/armsup/crouch/stand2`（自检）、
`base1/jump/base2/duck/base3`（正式段）。

**原始 IQ 全部保留**，所以后面换距离带、换加权方式、换多普勒特征都能重算，
不必重采（这是 `tools/vertical_probe.py` 只存统计量、17 轮数据作废的教训）。

## 6. 报告怎么读

`report.md` 给三块证据：

1. **安装自检**：能不能测竖直，一句话结论 + 三个角度值 + 信噪比。
2. **跳 / 蹲 单特征可分性**：Cohen's d 与留一最近质心准确率。
   `d ≥ 1.2` 算强分离；`0.8~1.2` 中等；`< 0.8` 单特征不够。
3. **动作 vs 站定**：用「相对站定基线的绝对偏离」，因为跳和蹲方向相反，
   直接求均值会互相抵消。

结论只回答「数据里有没有可分性」；**阈值、滞回、最小切换间隔都还没定**，
报告里出现的任何阈值建议都属**提案，待小组确认**，不得写进已实现功能
或验收结论（`AGENTS.md` 验证门）。

## 7. 已知限制

- **1T2R 距离分辨率 0.681 m、只有 8 个 bin**：1.0 m 站位通常落在 bin1/bin2
  （1.02 / 1.70 m）。跳 20~30 cm 不足以稳定跨 bin，所以「靠距离门移动判跳/蹲」
  在这块板上基本不可行，报告里会直接体现（质心变化接近 0）。
- **帧率 7.7 Hz**：一次跳/蹲只有 3~5 帧落在动作里，动作要放慢。
- 两块 1T2R 的 USB VID:PID 完全相同（`10c4:ea60`），程序**无法自动分辨新旧板**，
  只能按 COM 口名区分；同时插着时建议拔掉旧板，或用 `--port` 指定。
- 多普勒（`v_r`）作为第二条独立证据同时记录，但它不是俯仰角；
  即使角度不可用，跳/蹲的径向速度符号仍可能可分，结论要单独标注。
