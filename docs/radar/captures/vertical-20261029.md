# 采集记录：2T4R 垂直（俯仰/高度）标定 11 轮

> 日期：2026-10-29 20:08 → 22:07
> 板型：前 3 轮 1T2R，后 8 轮 2T4R（COM4）
> 目的：验证「用俯仰角测人体高度」能否支撑跳/蹲识别（跳蹲验证门 T0）
> 结论：**不稳定，8 轮 2T4R 里只有 1 轮判定 `ok`**

## 采集方式

每轮按 `base1 → jump → base2 → duck → base3` 五段采集：
先记静息基线，再做一次跳、再记基线、再做一次蹲、最后记一次基线。
用跳/蹲相对基线的偏移量判断是否可分。

判定含义（取自 `tools/vertical_probe.py` 的实际阈值，`sep = 跳俯仰均值 − 蹲俯仰均值`）：

- `ok`：`sep ≥ 10°`，跳明显高于蹲，方向正确；
- `weak`：`5° ≤ sep < 10°`，方向对但分离度中等；
- `same`：`-5° < sep < 5°`，跳和蹲俯仰角接近，**区分不开**；
- `reversed`：`sep ≤ -5°`，方向相反（本次未出现）；
- `no_signal`：缺少基线/跳/蹲的俯仰读数，数据不足。

## 结论

1. **1T2R 三轮全部 `no_signal`**：符合硬件基线——1T2R 的垂直角没有可用通道组合，
   测不了高度。这轮是为了把「1T2R 走不通」变成实测证据，而不是凭文档推断。
2. **2T4R 八轮只有 1 轮 `ok`（12.5%）**，其余 3 次 `weak`、2 次 `same`、1 次 `no_signal`
   （另有 2 次单轮 `weak`）。同一站位、同一动作，复现性差。
3. `same` 说明跳与蹲在俯仰维度上的响应方向一致、幅度接近——**只看俯仰角区分不了
   向上跳和向下蹲**，这是方法本身的限制，不是阈值没调好。
4. 因此「2T4R 俯仰角测高」这条路径**不能直接作为跳蹲 MVP 的证据**；按验证门要求，
   仍需 T1 离线特征可分性 + T2 决策。
