|---|---|---|---|
| 雷达事件流（`ActionRecognizer`） | `L7/10 R10/10` | `L4/10 R9/10` | 28 / 20 |
| 游戏画面（`px` 绝对值 + EMA） | `L9/10 R3/10` | `L6/10 R0/10` | **135 / 112** |

**决定性证据**：`x` 全域 **[-0.280, +0.691]** 与 **[-0.324, +0.607]**，中位 **+0.305 / +0.29**；
门槛 ±0.36 ⇒ **`x` 从未低于 −0.36，游戏侧 LEFT 在数学上不可能触发**
（0.70 m 的 9/10 是 73 个瞎切事件恰好盖住真值窗）；`p50 ≈ 0.30` 紧贴 +0.36 ⇒ RIGHT 频繁误触发；
1.00 m 更会 **卡死在右道**（回中要求 `x ≤ 0.22`，而中位 0.29），RIGHT 反而 0/10。

⇒ **AC-1 必须先定口径**；按游戏画面口径，现在不是"准确率多少"，而是"左右乱切 + 左移不可能"。
**边界**：游戏内置「雷达校准向导」可能改写 `scale_x/offset_x/invert`，
本轮未验证该校准是否作用于 bridge 偏置，上表按 `x_scale=1.0`、无偏置计算。

### R3 ★ 跳/蹲候选会真的让角色跳（先前判断已撤回）

`radar_actions.py` L762-791 的 JUMP/DUCK 候选**默认启用**（`jump_duck_confirm=3`）。
实测 **JUMP 68 次 / DUCK 83 次 / 240 s**（≈17 次/分钟），而该段真值**无任何跳/蹲**。
经 `serial_to_udp.py` L78-83 → bridge → `InputSource.js` L244-250，**会触发 `emit('jump')`**。
与 `AGENTS.md` 硬约束 5（跳/蹲在 T2 前不得算已实现）直接冲突。
**先前"游戏层不消费事件流、暂不影响画面"的表述已撤回。**
