# 1T2R 竖直采集：参数与分辨率推算

> 记录本批（2026-11-12）竖直实验用到的雷达参数，以及由参数推出的速度/距离分辨率。
> 数值来源：`Radar_Config.ini`（厂商 ONELAB 目录）与本批实测帧周期。

## 一、配置项

| 项 | 值 | 来源 |
|---|---|---|
| `ChirpsPerFrame` | 64 | `Radar_Config.ini` |
| `FrameTimeUS` | 130440（130.44 ms） | `Radar_Config.ini` |
| 距离 bin 数 | 8 | 固件输出 |
| 接收通道 | 2（1T2R） | 板型 |
| 载频对应波长 λ | 12.426 mm | 由中心频率换算 |

实测帧周期 **0.130 s**（四批数据 `labels.json` 的 `frame_period` 均为 0.1295~0.130），
即 **7.7 Hz**。这个数字是整条交互链路的体验上限，任何交互设计都要先过这一关。

## 二、速度分辨率

相干处理间隔（CPI）≈ 一帧时长：

```
CPI ≈ 130.44 ms / 64 chirp ≈ 2.04 ms/chirp，整帧 CPI ≈ 130 ms
```

速度分辨率按 `V_RES = λ / (2 · CPI)` 推算：

```
V_RES = 0.012426 / (2 × 0.130) ≈ 0.048 m/s
```

最大不模糊速度 `V_MAX = V_RES × N/2`：

```
V_MAX = 0.048 × 32 ≈ 1.53 m/s
```

与实测 ±1.53 m/s 一致，说明推算自洽。

## 三、距离分辨率

```
ΔR = c / (2B)，本配置实测约 0.68 m
```

8 个 bin 覆盖约 0.68~5.4 m，相邻 bin 间隔 0.68 m。

**这带来一个硬约束**：人体站立时距离波动只有几厘米，远小于 bin 宽，
所以「靠距离变化判断跳/蹲」在 1T2R 上永远不可行，`peak_bin` 不会动
（四批数据实测峰值 bin 恒为 2）。

## 四、为什么没有改 `ChirpsPerFrame`

把 64 降到 16，CPI 会缩到约 32.5 ms，`V_RES` 升到约 0.19 m/s，帧率可提到约 27 Hz。
理论上能让单帧内的多普勒方向更可分辨。

但本批已经用**多普勒谱宽**在现有配置下拿到 46/49 的事件级结果，
改配置会同时改变帧率、波形与厂商工具链的兼容性，收益不确定。
因此**本批不改**，仅在文档中记为备选路径。

## 五、未验证

- 上述 `V_RES` / `V_MAX` 为按配置推算值，未做注入已知速度的标定验证。
- `FrameTimeUS` 与实测 130 ms 的一致性只在四批数据上核对过，未测长期漂移。
