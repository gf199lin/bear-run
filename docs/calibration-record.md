## 2. 两级标定

`JCDet` 的标定分两步，缺一不可。第一步解决"人在哪个距离"，第二步解决"什么角度算动"。

### 2.1 第一级：零速能量剖面定"人门"

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `G` / `ND` | 32 / 32 | 距离门数 / 多普勒格数 |
| `GATE_M` | 0.176 m | 每门对应距离 |
| `P_LO` / `P_HI` | 4 / 9 | 搜索区间，对应 **0.70 m ~ 1.58 m** |

取法：对 `bin0`（零速格）能量剖面在 `P_LO ~ P_HI` 内取峰值门作为 `personG`。

**为什么不用运动残差找人**：静止的人会被 MTI 当背景滤掉。`05-证据与日志/截图/grade113p-waterfall.png`
左图为原始 range-time 幅度、右图为 MTI 后，右侧静止目标基本被抹平 —— 这就是必须改用零速剖面的直接证据。

### 2.2 第二级：安静帧池定俯仰基准

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `CALIB_N` | 6 帧 | 至少收够 6 帧安静帧才算校准完成（按 0.52084 s/帧 ≈ **3.1 s**） |
| `QUIET_R` | 0.35 | 安静度门限：该门邻域非零速能量占比 < 0.35 才算"安静" |
| `CALIB_MAX` | 40 帧 | 最长等待；超时则按安静度排序取最安静的 6 帧 |

流程：收帧 → 用中位数剖面定临时人门 → 用人门邻域活跃度筛出安静帧 → **在安静帧池上重新定门 + 取俯仰基准中位数**。

**这条筛选是踩坑换来的**：若校准窗里混入挥手/走动帧，人门会锁到错误距离
（实测挥手时身体在 1.4 m，平时 0.9 m），基准相位也会被带偏，导致全程乱报。
代码第 1506–1507 行保留了这条注释作为依据。

### 2.3 判定与维护参数

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| `TH_SPIKE` | 18° | 跳：单帧尖峰达到 18° 且**次帧回落** |
| `TH_ON` | 12° | 蹲：连续 ≥ 2 帧达到 12° |
| `TH_OFF` | 7° | 回落到 7° 以下判为结束 |
| `LOST_R` / `LOST_N` | 0.35 / 4 | 零速能量低于基准 35% 连续 4 帧 → 判"玩家离开"，自动重新校准 |
| 慢漂系数 | α = 0.03 / 帧 | 仅静止帧更新基准，时间常数 ≈ 17 s（0.52084 s/帧） |

**免标方向**：判据用"持续时长"而不是符号，板子倾斜或安装高度变化翻转符号时判定不失效 ——
这是刻意设计，不是巧合。

**出厂默认只看不发**：`observeOnly = true`（第 2253 行），判定只闪面板、不向游戏侧发事件。
原因见第 4 节：v1 阈值在离线回放中被证伪，定稿 v2 前不让误报进入游戏。

## 4. 复测结论

| 判定 | 项目 | 实测 |
| --- | --- | --- |
| ✅ 通过 | P1 站 1.5 m 距离 | 实测 1.23 m（n=5） |
| ✅ 通过 | P4 站 3 m 距离 | 实测 2.99 m（n=5） |
| ⚠️ 偏差 | P2 站 2 m | 实测 1.23 m，偏低 |
| ⚠️ 偏差 | P3 站 2.5 m | 实测 1.76 m，偏低 |
| ⚠️ 偏差 | P1–P4 阶梯线性 | 门间距 0.0 / 3.0 / 7.0，期望 ≈2.84 门 / 0.5 m |
| ✅ 通过 | P5 慢靠近 | v = −0.58 m/s（期望 0.4 量级，n=7） |
| ✅ 通过 | P6 慢远离 | v = +0.63 m/s（n=6） |
| ❌ 未通过 | P7 快靠近 | 速度无输出（n=2） |
| ❌ 未通过 | P8 快远离 | v = −0.00 m/s（n=3） |
| ⚠️ 偏差 | P11 左移 1 m 方位角 | 相对中线 dPhi ≈ −22/22/111°，偏小 |
| ✅ 通过 | P13 右移 1 m 方位角 | 相对中线 dPhi ≈ 107/78/16° |
| ❌ 未通过 | P10–P14 左右对称性 | 左 +22° / 右 +78°，**同号**（λ/2 期望 ∓67°/±67°） |
| ✅ 通过 | P16 跳（俯仰·瞬时） | 偏移范围 −148° ~ +93°，与蹲反向 |
| ✅ 通过 | P17 蹲（俯仰·持续） | 偏移 68° / 149°，基准 −52° / −99° |
| ✅ 通过 | P19 跳+蹲连招 | 组合偏移 −153° ~ +144°，双特征可分 |
| ✅ 通过 | P21 挥手 | 宽展布帧 6/6、近距帧 5/6、最大展布 31 bin |

**结论分两层，不能混为一谈**：

1. **判据层面**：跳、蹲、连招、挥手在离线回放中特征可分，判据成立（上表 ✅ 项）。
2. **端到端层面**：只有**左右移动**在真机上跑通；跳/蹲因 `observeOnly = true` **尚未接入游戏**。
3. **误报率**：离线回放统计为 **85%~91% 误报**（该数值来自作者离线回放，见
   `03-动作判定/analyze_v2.js` 的统计口径；本文件未复算）。这是跳/蹲不定稿的直接原因。

## 5. 失败项归因与下一步

| 失败项 | 归因（有依据的部分） | 下一步 |
| --- | --- | --- |
| P7/P8 快速动作无速度输出 | 快靠近/远离时目标在单帧内跨越多普勒格，且目标易丢（P21 挥手时可见展布达 31 bin，说明同一人可占多格）；n=2/3 样本不足 | 提高帧率或按时间窗合并多普勒；补采 ≥5 次/项 |
| P10–P14 左右同号 | 方位相位差符号随站位/安装角漂移，与 `docs/radar-calibration-plan.md` §1.2 记录的"左右符号不可用、逐站位失效"一致 | 交由游戏侧开局校准取符号（`js/Calibration.js` 第 2/3 步只记两侧、不判方向） |
| P2/P3 距离偏低、阶梯非线性 | 人门取 `bin0` 能量峰值，站位远时人体回波展宽，峰值门偏近 | 用重心而非峰值定门，或按展布做补偿；需另一批站位数据验证 |
| 跳/蹲误报 85%~91% | 新板 `dev` 近似白噪声，单帧相位差抖动已达阈值量级 | 增加"多门一致性"约束（同一动作需在相邻 2~3 门同时成立）后再统计 |

## 6. 给游戏侧的答复（对应 `docs/radar-calibration-plan.md` §4.3 的三个待定参数）

| 参数 | 雷达侧结论 |
| --- | --- |
| `jumpThreshold` | **雷达侧不输出 `height`**，链路里 `radar_fusion.js` 只发 `jump` / `crouch` 电平事件。建议游戏侧只吃事件，不要依赖 `height` 阈值；若必须保留 `height`，需要先由雷达侧把俯仰偏移量映射成高度代理，目前**没有这项标定数据** |
| `crouchThreshold` | 同上，走 `crouch` 事件 |
| `minConfidence` | 现有链路只有"上游掉线"一种降级：`radar_fusion.js` 在 1500 ms 无事件时把 `confidence` 降到 0.2（低于游戏侧 0.3 的门限）。**没有做过置信度的定量误差统计**，因此建议维持 0.3，并在文档中注明"无数据支撑" |

**校准向导 5 步与 JCDet 的关系**：游戏侧校准解决的是"游戏看到的 `x` 归零与方向符号"
（`x' = (x − x0) × sign`），属于**坐标层**；JCDet 解决的是"这一帧算不算跳/蹲"，属于**事件层**。
两者互不替代：即便游戏侧校准全过，跳/蹲事件仍受第 4 节误报率约束。
