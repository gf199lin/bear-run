## 1. 三分钟上手

### 第一次拿到包（只需做一次）

1. 双击 **`安装依赖.cmd`** —— 装 `pyserial` + `numpy`（约 30 秒）
2. 双击 **`环境检查.cmd`** —— 全绿才继续

### 每次开机

1. 先插 **水平板**（横放，管左右），等 2 秒
2. 再插 **竖直板**（竖放，管跳蹲）
3. 双击 **`一键-自动启动.cmd`**

它会自动：识别串口 → 按插入顺序分配角色 → 起两路桥接（8766 / 8767）
→ 打开游戏页面。**不需要在网页上点任何按钮。**

> 想先确认"分对了没有"、或者板子插反了要手动改，就用
> **`启动-双雷达游戏.cmd`**：它只打开分配台，你确认后自己点「启动」。

## 4. 硬件与摆放

- 1 块或 2 块 **1T2R（DEV202H / ICL1122）** 雷达板 + USB 线
- USB-UART 芯片是 **CP2102** → 装 **CP210x 驱动**（**不是 FTDI**）
- 两块板 USB 指纹相同（`10C4:EA60`），软件分不出谁是谁，
  只能靠"插入先后"或页面上手动指定

| 板子 | 摆法 |
|---|---|
| 水平板 | 横放，人站正前方约 **1 m** |
| 竖直板 | 绕光轴转 90° **竖放**，离地约 0.5 m，人站约 **1.2 m** |

两块都**不要正对显示器 / 机箱**——静止强反射会抢走目标，
表现为「连上了但坐标乱跳」或 `zero` 锁到 −28°。

> 11/03 实测：人固定在 +9° 一侧时手感最好；另一侧是电脑，必须排除。
> 如果你的场地电脑换了位置，先跑第 5 节。

## 5. 上机第一件事：确认波束打得到人

> 这一步不做，后面所有"识别率"都是不可信数据。

```powershell
# 1) 停掉正式服务
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8778/api/stop -Body '{}'

# 2) 起一个保留静止点的诊断实例
py -3 radar-bridge\tools\radar_live_ws.py --port COM3 --role lr --ws-port 8781 --clutter-keep 0.0

# 3) 空场扫 12 秒
py -3 tools\sector_scan.py --secs 12 --port 8781

# 4) 人站到计划位置，再扫一次
py -3 tools\sector_scan.py --secs 12 --port 8781
```

判读：

- 两次峰都在同一段 → 那是墙/显示器，用 `--exclude-az lo,hi` 排除
- 人站进去后峰移动 15° 以上 → 那个角度才是人，写回
  `radar-pointcloud/center.json` 的 `1t2r.az_deg`
- 人站 +9° 仍无回波 → **转板**，别改站位（历史数据和联调台口径都是 +9）

## 6. 常见故障对照

| 现象 | 先查这个 |
|---|---|
| 双击后一闪而过 | 没装 Python，或没勾 "Add python.exe to PATH" → 跑 `环境检查.cmd` |
| 提示缺 pyserial / numpy | 双击 `安装依赖.cmd` |
| 页面打不开 | 8778 被占用；关掉旧的命令行窗口重开 |
| 竖直板没反应、8767 空着 | 板子没插/没分到角色；用 `启动-双雷达游戏.cmd` 看页面 |
| 连上了但坐标乱跳 | 板子正对显示器 → 换角度或 `--exclude-az` |
| 站着不动也一直换道 | 幅度门太灵敏：`bear-run-new/js/config.js` 的 `enterThreshold`（当前 0.22）调大 |
| 挥手没反应 | 先跑第 5 节；再看 `x` 是否在 ±0.6 内往返（贴 ±1 = `zero` 锁错） |
| 画面卡 / 延迟大 | 正常帧率只有 **7.7 Hz（129.5 ms）**，这是硬件上限 |
| 想不插板演示 | 游戏侧支持模拟器热键切换，见 `docs/PRD-motion-game-MVP.md` |
