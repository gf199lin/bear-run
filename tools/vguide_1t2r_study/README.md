# 1T2R 竖直判跳/蹲 · 分析脚本集

这一组脚本是 2026-11-12 判定方案的**推导过程**，每层否掉一条路，最后留下的
才是现在 `tools/vguide_1t2r.py` 里的实时判定逻辑。所有脚本都只读 `frames.npz`，
不连接雷达，可离线复现。

## 前提

帧周期 129.5 ms（64 chirp × 1.96 ms），最大不模糊速度 ±1.53 m/s，速度分辨率 0.05 m/s。

## 五层推导

| 脚本 | 回答的问题 | 结论 |
|---|---|---|
| `01_dc_dilution.py` | 为什么不能直接用 `v_r`？ | 静息段 DC 占比 97~100%，动作段 42%~44%；正负多普勒对称展宽，净速度≈0，符号无意义 |
| `02_single_frame_features.py` | 单帧上哪个特征可分？ | 谱宽 d=1.88 / AUC 91.8% 最好；谱熵 d=1.27 / AUC 81.7%；`nz_share`、不对称度在跳/蹲间几乎无区分力 |
| `03_temporal_window.py` | 要不要上时序模型？ | 时间域特征（抖动、过零率）没有超过单帧谱宽，因此只用 5 帧滑窗均值 |
| `04_three_class.py` | 能不能做三分类？ | 可以做，三轮留一平均约 84%，但帧级准确率被静息帧稀释 |
| `05_event_replay.py` | 游戏真正需要什么？ | 事件级：先检出「有人在动」，再判跳/蹲；四批合计 46/49 = 93.9% |

## 用法

```bash
# 默认读取 data/vguide_1t2r/20261112-203419
python tools/vguide_1t2r_study/01_dc_dilution.py

# 指定批次
python tools/vguide_1t2r_study/05_event_replay.py data/vguide_1t2r/20261112-205706
```

更完整的逐批汇总（含两簇空隙与命中率）用：

```bash
python tools/vguide_1t2r_feat_eval.py data/vguide_1t2r
```

## 阈值性质

`gate=0.30`、`thr=0.255`、`lo=0.16` 均为本批数据推出的**提案值，待小组确认**。
换人、换场地、雷达高度变化时需重新标定。

## 已知缺陷

- 走动误报：走动谱宽 0.18~0.24 与蹲重叠，尚未解决。
- 一次蹲可能被切成两个事件（计数偏多，分类不受影响）。
- 仅在「雷达离地约 0.5 m + 人站约 1.2 m」这套摆法下验证。
