# 1T2R 跳/蹲可分的证据边界（2026-11-25）

> **一句话结论**：1T2R 上「跳」和「蹲」**不是完全不可分**——逐帧不可分（AUC≈0.5），
> 但按动作段聚合后 4 会话留一能到 **81–91%**，且「动作相对最近静止段的偏移」
> 在 4 个会话里方向一致（Δv_std AUC **0.738**）。
> **但它还不能上线**：数据是单人多会话、每段录制里 jump 整块在前 duck 整块在后，
> 「段级 9 成」里有多少是动作、多少是时间漂移，现有数据无法彻底分开。
> 所以本项**不接入实时链路，不写进已实现功能**，MVP 跳/蹲仍走 2T4R 俯仰角。

## 1. 为什么重做这件事

11-05 的结论是「跳/蹲方向几乎不可分（58.8%）」，但那个数字建立在两件事上：

- 用的是 **2T4R 的俯仰角 `pitch_seq`**（`data/vertical/`），不是 1T2R 点云；
- 评估样本是「每轮 2 个」（jump 段、duck 段各 1 个），全数据只有 34 个样本，
  4 折留一会话时每折测试集只有 8 个左右 —— 统计噪声极大。

11-13 补采了 **1T2R 逐帧真值**数据（`data/jumpduck_battery/`），一共有
48 个 jump 段、48 个 duck 段，这才第一次具备"按帧学、按段判"的条件。
本文就是在这批数据上重做一遍。

## 3. 方法

### 3.1 特征（与实时链路同源）

每帧先过产线 DSP `radar_dsp.PointCloudProcessor`（`remove_clutter=True`、`min_range=0`），
取点云后聚合成 11 维物理量：

| 维度 | 含义 |
|---|---|
| `n` | 点数 |
| `r_med` / `r_top` | 中位距离 / 最强三分之一点的中位距离 |
| `v_w` / `v_top` | 功率加权径向速度 / 最强三分之一点的中位速度 |
| `v_abs` / `v_p90` | 加权 \|v\| / \|v\| 的 90 分位 |
| `v_pos` / `v_neg` | 正 / 负多普勒所占功率比 |
| `v_std` | 速度的功率加权标准差 |
| `deg_med` | 中位方位角 |

再取 **4 帧因果窗口**（≈0.52 s，7.7 Hz 下）的 均值/标准差/首尾差/最大/最小，
拼成 **55 维**输入。窗口不跨段、不跨会话。

### 3.2 评估

- **留一会话交叉验证**：4 折，每次留一个会话做测试，其余三个训。
- **窗口级**：每个窗口判一次。
- **段级**：一个动作段内所有窗口概率取均值再判一次 —— 这贴近游戏里
  「一次动作触发一次事件」的真实用法。
- **配对检验**：Δ = 动作段均值 − 时间最近的 rest 段均值。慢漂移在相减时抵消，
  这是目前最能排除混淆的设计。
- **置换检验**：会话内打乱段标签 200 次，看真实准确率是否落在零分布之外。

## 4. 结果（三层，越往下越可信）

### 4.1 逐帧单变量：不可分

| 特征 | jump vs duck 的 AUC |
|---|---|
| `n` | 0.564 |
| `v_std` | 0.570 |
| `v_pos` | 0.518 |
| `v_abs` | 0.502 |
| `v_w` | 0.503 |
| `r_med` | 0.447 |
| `deg_med` | 0.493 |

**全部落在 0.43–0.57**。也就是说：看任何一帧，判断不了这个人是正要往上跳还是往下蹲。
物理原因很直接——1T2R **没有垂直角**（`VertAngleInfo` 无通道组合），
而径向多普勒只反映「朝向/远离雷达」的分量，跳和蹲在径向上的投影差别很小。

### 4.2 窗口 + 模型：段级才起来

| 特征口径 | 窗口级 | 段级 | 逐会话（段） |
|---|---|---|---|
| 绝对特征 | 66.2% | **88.5%** (85/96) | 18/20、20/20、23/32、24/24 |
| 因果基线差（20 s 中位） | 60.5% | **78.1%** (75/96) | 16/20、16/20、19/32、24/24 |

（口径：`tools/train_jumpduck_1t2r.py`，MLP 16 隐单元 400 epoch，留一会话 4 折。）

置换检验（绝对特征，100 次会话内打乱段标签）：零分布中位 **0.500**、
p95 **0.573**、max **0.615**，真实 0.885 → **p < 0.01**。

⚠ 这个 p 值**不能**当成"混杂已排除"。原因：置换打乱的是"段 ↔ 标签"的绑定，
但每段录制里 jump 整块在前、duck 整块在后这个**时间结构没变**；
如果存在慢漂移（站位、温漂、增益），真实标签恰好与漂移同向，置换后这种同向性被破坏，
零分布自然回到 0.5。所以置换只证明"标签与特征有对应"，不证明"这个对应是动作造成的"。

### 4.3 配对检验：方向在 4 个会话里一致（最强证据）

把每个动作段和时间上最近的 rest 段配对（96 对，jump 48 / duck 48，平均间隔 3.1 s），
计算 Δ = 动作 − rest：

| 特征 | jump Δ 中位 | duck Δ 中位 | AUC |
|---|---|---|---|
| **`v_std`** | **−0.149** | **−0.293** | **0.738** |
| `r_top` | +0.523 | +0.681 | 0.343 |
| `r_med` | +0.586 | +0.701 | 0.354 |
| `n` | −1.890 | −2.660 | 0.605 |
| `deg_med` | +9.845 | +8.603 | 0.507 |

逐会话一致性（这是关键，单个会话巧合不算数）：

| 会话 | Δr_med jump/duck | Δv_std jump/duck | Δn jump/duck |
|---|---|---|---|
| …133307 | +0.63 / +0.76 | −0.11 / −0.32 | −2.52 / −2.01 |
| …134832 | +0.58 / +0.66 | −0.15 / −0.29 | −3.77 / −2.65 |
| …140614 | +0.71 / +0.63 | −0.23 / −0.27 | −1.59 / −2.08 |
| …142228 | +0.53 / +0.80 | −0.07 / −0.40 | −1.28 / −2.93 |

4 个会话中 **4/4 都是**「蹲下时距离增加更多、速度离散度下降更多」。
这与物理直觉一致：蹲下去是持续、幅度更大、把身体压出雷达主波束的过程；
跳起来是短促的向上冲量，随后落回原姿势。差别不在"方向"，而在**幅度与时间包络**。

## 5. 为什么"段级 9 成"仍不能上线

1. **段切分是免费的**。段级评估假设"这个动作从哪帧到哪帧"已知，而实时链路里没有段标记，
   必须靠能量/运动门限自己切；切错一拍，段级准确率就会掉。窗口级 61–66% 才是
   "不知道段边界"时的真实水平。
2. **块顺序混杂未排除**。每段录制都是 jump 整块 → duck 整块，这是采集设计造成的，
   不是数据能自证的。唯一能一次排除的办法是**交替重采**（A/B/A/B）。
3. **单受试者**。4 个会话都是 S01。换人、换身高、换衣服的反光特性都可能使 `v_std` 的
   阈值失效。
4. **一个会话明显更差**（`…140614`：20–25/32），说明对动作幅度敏感。

## 6. 判读与建议

- **不要**把它写成"跳/蹲已实现"。按 `AGENTS.md` 硬约束 5，跳/蹲路径未定前不得进验收结论。
- 如果要做，正确顺序是：
  1. **交替重采**（jump/duck 各 10 次交替，约 3 分钟），用本文同一脚本重跑；
     若配对 Δ 的方向仍一致且段级仍 ≥80%，才算把这个混杂排除；
  2. 再加第二个受试者，看 `v_std` 阈值是否跨人稳定；
  3. 通过后再谈"用能量门限自动切段"的实时实现。
- 更可靠的路线仍是 **2T4R 俯仰角**（能直接测高度变化）。本项的价值是：
  证明了 **1T2R 有一条"不是完全没戏"的间接路径**，并且把它的上限和混杂量化清楚了。

## 8. 与已有规则法的关系（2026-11-25 补充）

### 8.1 「同号段长度」这条规律本来就有

`docs/jumpduck-decision-spec.md` 早就把跳/蹲判据定成了三层，第 3 层（跳还是蹲）用的是
**因果 EMA 后同号段的长度**，不是速度幅值：

```
vs = EMA(径向速度, alpha=0.5)
nb = 连续满足 vs < -0.15 的帧数（允许段内 1 帧回落）
nb <= 2  ->  JUMP
nb >= 3  ->  DUCK   （0.39 s）
```

判成 DUCK 后，后面的正向段（起身后摇）被吞掉，不再发 JUMP。

**为什么不能用幅值**——这是当年实测出来的反直觉结论：

| 动作 | 最大负峰 | 最大正峰 |
|---|---|---|
| 跳（14 次） | 0.36–0.71 | 0.38–0.78 |
| 蹲（14 次） | 0.45–0.64 | **0.38–0.88** |

**蹲的起身正峰比跳的还大**。按「短负 + 大正 = 跳」判，会把蹲的起身当成一次更强的跳。
根本原因是 7.7 Hz 抓不到跳跃的爆发：上冲只占 1–2 帧，被 129.5 ms 的窗口平均掉；
而蹲的起身是受控的 3–5 帧，峰值反而完整。

### 8.2 ML 能不能学到这条规律 —— 能，但不占便宜

四个口径在同一批 96 段上比较（`tools/compare_jumpduck_rule_ml.py`）：

| 口径 | 段级 | 说明 |
|---|---|---|
| 纯规则 `nb_max >= 3` | **78.1%** | 本次用点云加权速度重算，段内取最大 `nb` |
| 规则 v1.0 逐帧状态机 | **85.4%** | 文档口径，4 批 96 样本，延迟 388 ms |
| ML 55 维（**不含任何符号时序**） | **88.5%** | 今天的模型 |
| ML 64 维（+`nb`/`pb`/`negPk`/`posPk`/EMA 速度/差分） | **90.6%** | 窗口级从 66.2% 升到 69.6% |

结论：

- **ML 自己就学到了这条规律的一大半**。55 维里只有 `v_pos` / `v_neg` / `v_std` 三个量
  跟速度符号有关，加上 4 帧窗口的 mean/std/diff/max/min，就够到 88.5%。
- **把规律显式喂给它，只再涨 2.1 点（2 个段）**，在 96 样本上不显著。
  也就是说：这条规律的信息量已经被常规统计特征近似覆盖，ML 并没有「看不见」它。
- 纯规则 78.1% 低于 ML，是因为段内取 `nb_max` 会被动作尾部的残余拉长，
  而逐帧状态机在负段到 3 帧时就即时判定（这才是 85.4% 的来源）。

### 8.3 但 ML 有一个规则没有的致命短板

jump/duck 二分类**没有「没有动作」这个类**，它对任何输入都会给出一个非 0.5 的概率。
实测负样本段级误报（全量模型，`tools/compare_jumpduck_rule_ml.py` 的 D 段）：

| 负样本 | 段数 | 判 jump | 判 duck | 误报率 |
|---|---|---|---|---|
| walk（原地踏步） | 2 | 2 | 0 | **100%** |
| bend（弯腰） | 3 | 0 | 3 | **100%** |
| turn（转身） | 3 | 3 | 0 | **100%** |
| alt（跳蹲交替） | 2 | 2 | 0 | 100% |
| **rest（静止）** | 116 | **109** | 7 | 100% |
| left / right | 6 | 5 | 1 | 100% |

**连静止段 116 个里有 109 个被判成 jump。** 这证明 ML 不能替代前两层门：

```
第 1 层  有没有动作      nz_share      （静息 0.00-0.03 vs 动作 0.60-0.90，余量 14 倍）
第 2 层  切向还是径向    doppler_width （左右移 0.15-0.20 vs 跳蹲 0.29-0.54）
第 3 层  跳还是蹲        <- 这一层才是 ML 能做的
```

`docs/jumpduck-battery-analysis-1113.md` §5.5 记录的规则版负样本误报同样是
**弯腰/转身/踏步 8 块全部误报**。所以这不是 ML 的问题，是**第 3 层判据本身
（无论规则还是 ML）都不含「拒绝」能力**，必须靠前两层门。

### 8.4 最终判读

1. 那条规律是对的，但**关键变量是负段的长度（<=2 帧 vs >=3 帧），不是正峰大小**；
   正峰反而会误导，因为蹲的起身比跳更猛。
2. ML 能看出这条规律（88.5%），显式加时序只多 2.1 点，**不值得为此替换规则**。
3. 无论规则还是 ML，第 3 层都只能做「已经确定是上下动作之后，判是跳还是蹲」，
   前两层必须是规则门。
4. 真正的天花板是物理：7.7 Hz 抓不到跳跃爆发；大跳必须先深蹲蓄力、与真蹲同构；
   弯腰/转身/踏步在速度轴上同样有径向分量。要突破只能提高帧率或上 2T4R 测高度。
