# 雷达联调操作手册（组员版）

> 适用场景：两台电脑 — 你这台连雷达，前端那台跑游戏。
> 目标：让前端能连上 `ws://<你的电脑IP>:8766`。
> 首次配置约 20~30 分钟。
> 文档版本：v1　｜　如有疑问直接把报错截图发我。

---

## 这份文档怎么用

你只需要做**第 1~6 步**。每一步都有"做完应该看到什么"，看到不一样的就把截图发我。

分工：

| 谁 | 做什么 |
|---|---|
| **你（雷达侧）** | 把雷达数据转成一个 WebSocket 地址，并告诉我你的 IP |
| **我（前端侧）** | 连你的地址，验证数据能不能驱动游戏 |

---

## 第 0 步：先回答这三个问题

这三件事决定了后面用哪条命令，麻烦先确认再动手。

**问题 1：雷达数据从哪里出来？**

- [ ] UDP 数据包（最常见，网口雷达）
- [ ] TCP 数据流（雷达是服务端，或主动连你）
- [ ] 串口 COM 口
- [ ] 厂商程序提供 HTTP 接口
- [ ] 厂商程序本身就是 WebSocket
- [ ] 只能看厂商软件界面，没有数据接口

> 如果是最后一种，先别往下做，直接告诉我，我们得先找厂商要 SDK 或数据协议。

**问题 2：端口号 / COM 口号是多少？**
例如 `UDP 8888`、`TCP 192.168.1.50:9000`、`COM3`。

**问题 3：一帧里哪个字段代表左右？单位和正负方向是什么？**
例如"`px_m`，单位米，向左是负"。这个字段名决定了要加哪个参数。

> 三个问题答完发我，我会直接给你一条填好参数的启动命令。

---

## 第 1 步：准备环境（约 5 分钟）

### 1.1 确认有 Python

打开 PowerShell，输入：

```powershell
py --version
```

看到 `Python 3.7` 以上就跳过。没有的话去 python.org 下载安装，**安装时务必勾选 "Add Python to PATH"**。

### 1.2 拿到两个文件

找我要，或者从游戏代码包里复制，放到同一个目录，例如 `D:\radar\`：

```
radar-runner\tools\radar_bridge.py     桥接器：把雷达数据转成 WebSocket
radar-runner\tools\check_radar.py      体检工具：验证链路通不通
```

放好后确认：

```powershell
cd D:\radar
dir
```

应该能看到这两个 `.py` 文件。

### 1.3 确认雷达真的在出数据

**先用厂商自己的软件确认**：人走动时，界面上的数字/点云会变化。

这一步不做，后面全是白忙。雷达没数据，桥接器也变不出来。

---

## 第 2 步：启动桥接器

**新开一个 PowerShell 窗口，保持它一直开着。**

### 2.1 UDP 雷达（最常见）

```powershell
cd D:\radar
py radar_bridge.py --from udp --udp-port 8888 --print-sample
```

`--udp-port 8888` 要换成雷达实际发送的端口（第 0 步问题 2 的答案）。

### 2.2 其他类型雷达

| 雷达输出 | 启动命令 |
|---|---|
| UDP 数据包 | `py radar_bridge.py --from udp --udp-port 8888` |
| TCP，雷达是服务端 | `py radar_bridge.py --from tcp --tcp 192.168.1.50:9000` |
| TCP，雷达主动连你 | `py radar_bridge.py --from tcp-listen --listen-port 9100` |
| HTTP 接口 | `py radar_bridge.py --from http --http http://127.0.0.1:8080/api/target` |
| 厂商程序输出到命令行 | `py radar_bridge.py --from exec --exec "你的程序.exe 参数"` |

> **串口雷达注意**：当前工具没有内置串口模式。优先看厂商软件能不能改成 UDP/TCP 输出；如果不行，告诉我，我单独给你一个读串口的小脚本。

### 2.3 加不加 `--print-sample`

- **第一次接入**：加上，用来确认字段名和数值范围。
- **确认没问题之后**：去掉，界面更干净。

---

## 第 3 步：看输出，调三个参数

加了 `--print-sample` 后，终端应该开始滚动打印，类似：

```
原始: {"px_m": 0.42, "jump": 0, "crouch": 0, "confidence": 0.9}
解析: x=0.42 jump=0 crouch=0 conf=0.90
```

### 3.1 三个要检查的点

**① 有没有输出？**

- 10 秒内一行都没有 → 雷达没往这个端口发，回到第 0 步确认端口。
- 有输出但 `x=` 后面是 `0` 或 `nan` → 字段名不对，用 `--map` 改名（见下）。

**② `x` 的范围对不对？**

游戏要的是 **-1 到 1** 的横向位置。

| 你看到的 x | 说明 | 加这个参数 |
|---|---|---|
| `0.42` 这种 | 已经归一化，很好 | 不用加 |
| `420` 这种（毫米） | 单位是毫米 | `--scale-x 0.001` |
| `-1200` 到 `1200`（毫米） | 同上，视量程调整 | `--scale-x 0.0008` 左右，试出来为准 |
| 几百上千的像素值 | 像素坐标 | 用探测宽度换算，例如宽 800px → `--scale-x 0.0025` |

**③ 左右方向对不对？**

让人往**左**走一步，看 `x` 是变大还是变小。

- 往左走 `x` 变小 → 正确。
- 往左走 `x` 变大 → 加 `--invert-x`。

### 3.2 常用调整参数

```powershell
# 字段改名：上游叫 px_m，游戏要 x
py radar_bridge.py --from udp --udp-port 8888 --map x=px_m,jump=jmp,crouch=duck

# 单位换算 + 纠正左右
py radar_bridge.py --from udp --udp-port 8888 --scale-x 0.001 --invert-x

# 静息时 x 不是 0（人站在偏一侧），把这个偏移减掉
py radar_bridge.py --from udp --udp-port 8888 --offset-x 0.35
```

调的判断标准很简单：**人站在雷达正前方不动时，`x` 接近 0；往左走变负，往右走变正。**

## 第 4 步：本机自检（关键一步）

**桥接器窗口不要关**，另开一个 PowerShell 窗口：

```powershell
cd D:\radar
py check_radar.py ws://127.0.0.1:8766 --seconds 5
```

## 第 5 步：查你的 IP，发给我

```powershell
ipconfig
```

找到 **IPv4 地址**，通常是 `192.168.x.x` 或 `10.x.x.x`。

把这个 IP 发我，例如 `192.168.1.23`。

**如果列出了多张网卡**（VMware、虚拟机、VPN、WSL），把**所有** IPv4 都发我，我来试哪个能通。

---

## 第 6 步：放行防火墙

Windows 默认会拦外部访问 8766，这一步不做我连不上。

**以管理员身份**打开 PowerShell（右键开始菜单 → "Windows PowerShell (管理员)"），执行：

```powershell
New-NetFirewallRule -DisplayName "RadarBridge 8766" -Direction Inbound -Protocol TCP -LocalPort 8766 -Action Allow
```

验证是否添加成功：

```powershell
Get-NetFirewallRule -DisplayName "RadarBridge 8766"
```

能看到这条规则就说明放行成功。

> **公司电脑没有管理员权限？** 别折腾了，直接告诉我，我们改用 SSH 隧道方案，不需要动防火墙。

---

## 第 7 步：等我来连

我会在你电脑上验证：

```powershell
py check_radar.py ws://<你的IP>:8766 --seconds 5
```

- 六项全绿 → 开始联调，我这边填进游戏就能看到角色动。
- 有红项 → 我告诉你卡在哪一层，你按下面第 8 步处理。

**这一步通过，你的任务就完成了。** 之后桥接器窗口一直开着别关就行。

---

## 第 8 步：连不上时按顺序排查

| 我这边看到的现象 | 可能原因 | 你做什么 |
|---|---|---|
| TCP 连接超时 | 防火墙没放行 | 重做第 6 步 |
| TCP 连接被拒绝 | 桥接器没启动 / 端口不是 8766 | 确认窗口还在跑，看有没有 "Address already in use" |
| TCP 通但握手失败 | 8766 被别的程序占用 | 跑 `netstat -ano`，看 8766 那一行是哪个 PID |
| 连上了但 0 帧 | 雷达没出数据 | 看桥接器窗口是否在滚；检查雷达是否在探测区 |
| 帧率不是 20Hz | 上游采样率不同 | 正常，桥接器会统一重采样到 20Hz |
| `x` 一直是 0 或 nan | 字段名不对 | 用 `--map x=实际字段名` |
| `x` 范围不对 | 单位没换算 | 用 `--scale-x` |
| 左右反了 | 符号约定不同 | 用 `--invert-x` |
| 人不动 `x` 也在跳 | 噪声大 / 人不在探测区 | 站到雷达正前方 1~3 米内 |
| 两台电脑互相 ping 不通 | 不在同一网段 / WiFi 客户端隔离 | 用手机热点给两台电脑组网 |

## 第 9 步：参数速查表

> 如果下面的参数和你机器上的脚本对不上，以 `py radar_bridge.py --help` 的输出为准（脚本可能会更新）。

| 参数 | 作用 | 默认值 / 常用值 |
|---|---|---|
| `--from` | 上游类型 | `udp` / `tcp` / `tcp-listen` / `http` / `exec` / `stdin` |
| `--udp-port` | UDP 监听端口 | 默认 `8888`，按雷达实际填 |
| `--tcp` | 上游 TCP 地址 | `192.168.1.50:9000` |
| `--listen-port` | TCP 监听模式端口 | 默认 `9100` |
| `--http` | 上游 HTTP 接口 | `http://127.0.0.1:8080/api/target` |
| `--port` | **对外 WebSocket 端口** | 默认 `8766`，**不要改** |
| `--parse` | 报文格式 | `json`（默认）/ `kv` / `csv` / `raw` / `regex` |
| `--map` | 字段改名 | `x=px_m,jump=jmp` |
| `--scale-x` | x 缩放 | 毫米→归一化约 `0.001` |
| `--offset-x` | x 零点偏移 | 静息时 x 的均值 |
| `--invert-x` | 左右反转 | 加上即可 |
| `--jump-th` | 上游是连续值时，超过它算跳 | 按数据实测填 |
| `--crouch-th` | 同上，算蹲 | 按数据实测填 |
| `--rate` | 输出帧率 | 默认 `20`（游戏按 20Hz 设计） |
| `--print-sample` | 打印原始报文 | 首次接入必开 |

---

## 两条铁律

1. **桥接器窗口不能关。** 关了前端立刻断，游戏会判定雷达掉线。
2. **前端页面不能用 `https://` 打开。** 浏览器会拦掉 `ws://` 连接。用 `http://` 或本地文件打开。

---

## 名词对照

| 词 | 意思 |
|---|---|
| 上游 | 你的雷达数据 |
| 下游 / 前端 | 我的游戏页面 |
| 桥接器 | `radar_bridge.py`，把雷达数据转成 WebSocket |
| 8766 | 前端连接用的端口 |
| 归一化 | 把横向位置压到 -1 ~ 1 之间 |
