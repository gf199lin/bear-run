## 1. Project Overview and Users（概述与用户）

**一句话**：一款用**毫米波雷达做体感操控**（无雷达时键盘/触屏）的 3 车道无尽跑酷网页游戏——玩家用**左右移动、跳跃、下蹲**三个真实身体动作，控制卡通小熊「熊二」在森林跑道狂奔、躲避障碍、收集蜂蜜。

| 项 | 内容 |
|---|---|
| 用户 / 场景 | 校园休闲玩家（同学、室友）；课间、宿舍、摊位，**1～2 分钟**一局，零安装。次要为评审师生（扫码即玩、无需指导） |
| 认定的问题 | 校园可及的小游戏**清一色触屏手势、身体不动**；真体感需**专用主机或摄像头**，门槛高 |
| 最小方案 | **不采集影像**的 1T2R 雷达 + **零安装网页**；无雷达时键盘/触屏保底 |

**证据与假设**：用户证据 **E-01 访谈 / E-02 零指导试玩 / E-03 三动作波形可分性实验** 均 **`[待补]`**（D / D / A，10-16 / 10-16 / 10-17 前）——详见提案 §3，**提交前必须补齐**。已有材料 M-01 需求记录、M-02 设备授权、M-03 可运行原型，**均不能替代用户证据**。

**未证实假设**：**H-01** 用户愿站起来用身体玩 1～2 分钟 ｜ **H-02** 雷达**侧面**安装时左右判定稳定 ｜ **H-03** 用户无需指导即懂「三动作↔三操作」｜ **H-04** 现场空间与网络允许雷达与游戏机互通 ｜ **H-05** 真 3D 方案下手机仍达标帧率。

## 2. MVP Scope（MVP 范围）

核心闭环：**用四种输入源之一操控小熊在三条车道的纵深跑道无尽奔跑，躲避障碍、收集蜂蜜与道具，血格扣完结束并记录本地最高分。**

| ID | 核心能力 | 为什么必须 | 覆盖 |
|---|---|---|---|
| **SC-1** | 三动作操控（换道/跳跃/滑铲），四源统一切换 | 验证"体感输入能否被游戏消化"的最小闭环 | FR-01~04 |
| **SC-2** | 三车道无尽跑道 + 4 类障碍与组合、分段解锁 | 提供持续挑战，也是测试三动作的必要场地 | FR-05~07 |
| **SC-3** | 生存与资源循环（血格、无敌帧、回血、蜂蜜、加速滑道） | 把"能玩"变成"想再玩一局" | FR-08~10 |
| **SC-4** | 完整对局流程 + 本地最高分 | 完整用户任务必须能从头跑到尾 | FR-11~12 |
| **SC-5** | 真实雷达接入与调试面板 | 无可观测手段就无法现场标定阈值 | FR-13~15 |
| **SC-6** | 熊出没式森林美术 + 搞笑角色动作 | 不接受简陋占位图形；障碍**可读性**决定玩法成立 | FR-17~18 |

## 3. Out of Scope（明确不做）

| 排除项 | 理由 |
|---|---|
| 音效/背景乐 ｜ 屏幕震动 ｜ 碎片特效 | 不影响核心玩法验证（当前仅**命中闪红**）｜ OQ-07 |
| 多人/联网 ｜ 排行榜 ｜ 账号 ｜ 云存档 | 需后端、账号与隐私处理，远超 MVP |
| 手机端接雷达 | 手机无雷达链路，**只用触屏** |
| 关卡编辑器 ｜ 攻击战斗系统 | 与跑酷核心循环无关 |
| 任何形式的用户数据上传 | 隐私与合规成本 |

**明确不适用项**：认证/登录、数据库、支付、微服务/后端、产品内 AI 功能——**均不适用**（单人本地休闲游戏，唯一持久化项是本机最高分，本地存储足够；唯一进程间通信是雷达经**本机回环** WebSocket 传入；AI 仅用于**开发辅助**）。**公网托管**为**部分适用**（NFR-06）：便于手机扫码可静态托管，但**运行时零网络依赖**，本地双击亦可完整运行。

## 4. User Journey and Prototype（用户旅程与原型）

### 4.1 单局主流程

```
打开 index.html（本地双击 或 手机扫码）
  → 开始界面：选输入源（键盘/触屏/雷达/模拟器）+ 玩法提示 + 历史最高分
  → 点「开始狂奔」：小熊自动前进，速度随距离递增
  → 循环：木栅栏→【跳】｜悬空粗树干→【滑铲】｜石头原木堆→【换道】
          滚动木桶→预判【换道】｜组合障碍（第 4 区）
          撞障碍→扣 1 格血 + 1.15 s 无敌闪烁 ｜ 蜂蜜罐→加分
          红苹果→回 1 格血 ｜ 蜂蜜滑道→3.2 s 提速且得分 ×2
  → 血格扣完 → 结束界面：得分/距离/蜂蜜/最高分（破纪录显示「新纪录」）
  → 再来一局 或 返回主菜单
```

**关键决策点**：① 开局前选输入源（决定这局靠身体还是键盘）；② 每次遭遇障碍都要在**跳/滑铲/换道**间判断——这正是三动作被反复验证之处。

可运行原型 `radar-runner/index.html`（含开始/暂停/结束三态与雷达调试面板）。截图依次为：开始界面、游戏中+结算（真实跑至 1480 m / 5639 分 / 187 蜂蜜）、跳跃（空中团成球并前空翻）、滑铲（仰面朝天、四肢乱蹬）。

### 4.3 关键界面要求

**开始**可选输入源并显示本局绑定的输入方式与历史最高分 ｜ **HUD** 显示生命格、得分、最高分、距离、蜂蜜、速度、区域、输入源 ｜ **暂停**含继续/重开/返菜单，且**逻辑完全冻结** ｜ **结束**显示得分、距离、蜂蜜、最高分，破纪录显示「新纪录」｜ **移动端**竖屏显示「请把手机横过来」遮罩，不进入游戏。

## 5. Functional Requirements（功能需求）

> 「验收」列指回 §7。**FR-17 / FR-18 为本次新增**（熊出没主题带来的美术与动作要求）。

| ID | 需求 | 验收 |
|---|---|---|
| **FR-01** | **统一输入层抽象**：键盘/触屏/真实雷达/雷达模拟器四源；切换输入源**不影响任何游戏逻辑** | AC-01 |
| **FR-02** | **左右移动 → 车道切换**：3 车道**吸附式**切换（非连续跟随），适配雷达横向分辨率不足 | AC-02、03 |
| **FR-03** | **跳跃**：按键/上滑/雷达起跳后起跳并按重力落地；**瞬时动作**，空中不可重复触发 | AC-04 |
| **FR-04** | **滑铲**：按下/下滑/雷达下蹲后压低身位约 0.6 s，可穿过**悬空树干**；短冷却防连发 | AC-05 |
| **FR-05** | **伪纵深无限跑道**：三车道持续滚动，远小近大、按深度遮挡；资源**循环复用**，内存不持续增长 | AC-06 |
| **FR-06** | **障碍与应对动作一一对应**：① 木栅栏 `low`（黄黑条）→**跳** ② 悬空粗树干 `high`（最低点约 1.18 m）→**滑铲** ③ 石头原木堆 `block`（跳不过）→**换道** ④ 滚动木桶 `mover`→预判**换道** ⑤ 组合 `combo`→第 4 区解锁 | AC-07、08 |
| **FR-07** | **难度递增**（三维度同时生效）：速度随距离提升、障碍密度变大、按距离**分段解锁**新障碍（4 区域） | AC-09 |
| **FR-08** | **血格与受伤**：初始 3 格、上限 5 格；撞障碍扣 1 格并进入约 1.15 s 无敌闪烁；扣完结束 | AC-10 |
| **FR-09** | **计分**：距离分（每米 1 分）+ 蜂蜜分（每罐 20 分）；蜂蜜滑道期间得分 ×2 | AC-11 |
| **FR-10** | **拾取物**：蜂蜜罐（加分，成排出现）、红苹果（回 1 格血，不超上限）、蜂蜜滑道（约 3.2 s 提速 + 得分 ×2） | AC-12 |
| **FR-11** | **完整对局流程**：开始/暂停（继续、重开、返菜单）/结束/再来一局；暂停时逻辑完全冻结 | AC-13 |
| **FR-12** | **本地最高分**：本地存储保存并显示、刷新后保留；**不联网、不上传** | AC-14 |
| **FR-13** | **雷达调试面板**：实时显示渲染帧率、雷达帧率、端到端延迟、`x/height/jump/crouch/confidence` 原始值、判定车道、触发事件、场上对象数 | AC-15 |
| **FR-14** | **雷达数据接口**：经**本机 WebSocket** 接收标准化 JSON 帧；低置信度帧与超时掉线做降级 | AC-16、17 |
| **FR-15** | **离线回放数据源**：可解析采集端保存的真实帧数据文件，供离线复现 | AC-18 |
| **FR-16** | **移动端适配**：横屏全屏、纯手势（左右滑/上滑/下滑）；竖屏提示；防双击缩放与滚动误触 | AC-19 |
| **FR-17** | **美术风格与可读性**：《熊出没》式明亮森林卡通（蓝天白云、鲜绿草地、蜂蜜金 UI），造型圆润厚实；**素材全部由代码实时生成、不用外部贴图**（保证断网可玩）；**可读性优先**——黄黑警示条纹**只**出现在"需跳"的障碍上 | AC-20 |
| **FR-18** | **角色动作表现**：主角**熊二**（浅棕黄毛、米色肚皮与口鼻、圆耳朵、呆毛、腮红）。动作须**夸张、有喜感、背后视角可读**：① **跳跃**＝空中收拢四肢团成球、完成**一整个前空翻**，落地"啪叽"压扁再回弹 ② **滑铲**＝**仰面朝天**躺平滑出、四肢乱蹬、舌头甩出 | AC-21 |

## 6. Business Rules and Edge Cases（业务规则与边界情况）

### 6.1 业务规则（摘要 · 共 13 条）

三条最关键：

| ID | 规则 | 基线参数 |
|---|---|---|
| **BR-11** | **公平性硬规则**：任何一行障碍**至少留一条空车道**，绝不出现三车道全堵的死局；蜂蜜串与道具**只放空车道** | 生成器强约束 |
| **BR-02** | 雷达车道判定用**迟滞**：进左右车道需超较大阈值，回中间需低于较小阈值，防边界抖动 | 进入 0.36 / 退出 0.22 |
| **BR-13** | 任一阶段能力未跑通则**退回上一阶段演示**；无雷达的键盘/触屏版本**永远必须可玩** | 降级原则 |

其余 10 条（完整版）：车道吸附与间距、置信度过滤、掉线超时、无敌时间、滑铲冷却、生命上限、双倍分不叠加、区域推进、道具里程投放、警示色语义。

### 6.2 边界情况（摘要 · 共 12 条）

三条最关键：

| # | 情况 → 期望行为 |
|---|---|
| **EC-01** | 雷达突然断连 → 不崩溃；保留当前状态；面板显示掉线；可切换其他输入源继续 |
| **EC-05** | 异常雷达帧（缺字段、`NaN`、越界）→ 丢弃该帧，不用默认值造成误动作 |
| **EC-08** | 本地存储不可用（隐私模式）→ 正常运行，仅最高分不保存，不报错 |

其余 9 条（完整版）：后台切回的时间补偿上限、120 Hz 屏幕、竖屏、同帧"跳+蹲"冲突、回血溢出、连跳限制、无最高分、雷达未连接、未知输入源。

### 6.3 权限、校验、冲突动作、空状态与失败行为（指南 5.1 第 6 项）

**权限**：不适用（无账号、无角色、无多用户）。**校验**：对象是雷达输入帧，`x` 须落在 `[-1,1]`，缺字段或 `NaN` 直接丢弃（BR-03、EC-05）。**冲突动作**：同帧同时判定"跳"与"蹲"时按固定优先级取其一（EC-06）。**空状态**：无历史最高分、雷达未连接（EC-10、EC-11）。**无效输入**：异常雷达帧、未知输入源（EC-05、EC-12）。**失败行为**：雷达掉线与本地存储不可用，均要求**不崩溃、可继续玩**（EC-01、EC-08）。

## 7. Acceptance Criteria（验收标准）

> 形式 **Given / When / Then**，可观测、可复现。
> **§7 是验收标准**（系统是否按规格运行），与 §9.1 的**成功度量**（是否真的帮到用户）**不可混用**。

| ID | 场景 | 关联 |
|---|---|---|
| **AC-01** | Given 开始界面，When 依次选四种输入源各开一局，Then 每种都能正常操控，且**游戏逻辑与规则完全一致** | FR-01 |
| **AC-02** | Given 键盘，When 按一次 `←`/`→`，Then 换到**相邻**车道并稳定停住，不会越过中间车道直跳最外侧 | FR-02 |
| **AC-03** | Given 雷达输入且人稳站中间车道，When 小幅晃动未超进入阈值，Then **不换道**（迟滞生效，无抖动） | FR-02、BR-02 |
| **AC-04** | Given 奔跑中，When 触发跳跃，Then 离地后按重力落回，且落地前再次触发**不会二次起跳** | FR-03 |
| **AC-05** | Given 前方是悬空粗树干，When 滑铲通过 Then 不受伤；When 直接撞击 Then 扣 1 格血 | FR-04、BR-06 |
| **AC-06** | Given 游戏进行中，When 持续奔跑 5 分钟，Then 场景持续生成与回收，**无内存增长、无元素消失或穿透错乱** | FR-05 |
| **AC-07** | Given 前方是木栅栏，When 跳跃通过 Then 不受伤；When 不跳直接撞击 Then 扣 1 格血 | FR-06 |
| **AC-08** | Given 前方是石头原木堆，When 换道绕开 Then 不受伤；When 正面撞击 Then 扣 1 格血 | FR-06 |
| **AC-09** | Given 一局从 0 m 跑到 1300 m 以上，Then 速度上升、障碍间距变小，且分别在第 2/3/4 区出现新增障碍类型 | FR-07 |
| **AC-10** | Given 血格 3，When 连续撞击（间隔大于无敌时间）Then 每次扣 1 格，第 3 次后结束；When 无敌时间内再接触 Then 不扣血 | FR-08、BR-05 |
| **AC-11** | Given 本局已跑 100 m 且拾取 3 罐蜂蜜，Then 得分 = 100×1 + 3×20 = 160（无蜂蜜滑道时） | FR-09 |
| **AC-12** | Given 血格 3/上限 5，When 吃红苹果 Then 变 4；When 踩蜂蜜滑道 Then 提速且此后得分 ×2 累计，约 3.2 s 后恢复 | FR-10 |
| **AC-13** | Given 游戏中，When 暂停 Then 画面与逻辑冻结；When 继续 Then 从暂停点无跳变恢复 | FR-11 |
| **AC-14** | Given 已打出一局最高分，When 关闭并重开页面 Then 仍显示；When 打出更高分 Then 更新并显示「新纪录」 | FR-12 |
| **AC-15** | Given 雷达已连且游戏进行中，When 打开调试面板 Then 可实时看到帧率、延迟与 `x/height/jump/crouch/confidence` 随动作变化 | FR-13 |
| **AC-16** | Given 雷达送入一帧 `confidence = 0.1`，Then 游戏**不产生任何动作** | FR-14、BR-03 |
| **AC-17** | Given 雷达正常供数中，When 停止发送超过 500 ms，Then 面板显示掉线，游戏不崩溃且不产生错误动作 | FR-14、BR-04 |
| **AC-18** | Given 已有一份真实采集的帧数据文件，When 作为回放源载入，Then 能离线完整复现该段操作，无需雷达在线 | FR-15 |
| **AC-19** | Given 手机横屏全屏，When 左右滑/上滑/下滑，Then 分别触发换道/跳跃/滑铲，且无页面缩放或滚动 | FR-16 |
| **AC-20** | Given 游戏运行中，When 观察画面 Then 为明亮森林卡通风格；**断网重开仍完全一致**（无外部贴图请求）；黄黑警示条纹**仅出现在木栅栏**上 | FR-17、BR-12 |
| **AC-21** | Given 用键盘触发跳跃与滑铲，When 从**默认背后视角**观察，Then 能看出"空中团成球并前空翻"与"仰面朝天滑行、四肢乱蹬"两种夸张姿态 | FR-18 |

## 8. Non-Functional Requirements（非功能需求）

> 共 13 条（NFR-01 ~ NFR-13）。四条硬指标：

| ID | 类别 | 要求与目标值 |
|---|---|---|
| **NFR-01** | 性能·渲染帧率 | 桌面 ≥ 30 FPS；手机（2 年内安卓中端机）≥ 24 FPS |
| **NFR-03** | 性能·端到端延迟 | 从"人做动作"到"角色响应" **≤ 300 ms** |
| **NFR-06** | 兼容·零外部依赖 | 第三方代码**本地同目录**存放、**不用 CDN**；本地双击或静态托管均**运行时不请求外部资源** |
| **NFR-10** | 安全·隐私 | **不向外部服务器发请求**、不采集不上传用户数据（雷达经本机回环 `ws://127.0.0.1`，**不属外部通信**） |

其余 9 条（完整版）：逻辑帧率解耦 60 Hz、雷达 ≥ 20 Hz、单局 1～2 分钟、浏览器兼容、跨平台一致、移动端适配细节、可维护性、交付可读性、健壮性。
