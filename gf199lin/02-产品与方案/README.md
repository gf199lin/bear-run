# 02 · 产品与方案

本目录是**动手前想清楚**的部分：做什么、不做什么、雷达数据要满足什么条件。

| 文件 | 写给谁 | 一句话 |
|---|---|---|
| `PRD-BearRun-MVP-v1.0.md` | 全组 / 评审 | 玩法、数值、状态机、验收口径的完整定义 |
| `PROPOSAL-BearRun-v1.0.md` | 评审 | 为什么做体感跑酷、技术选型、风险与取舍 |
| `雷达数据采集需求单-v3.md` | 雷达组 | 每帧字段、单位、帧率、坐标系、动作脚本的硬性要求 |
| `雷达联调-组员操作手册.md` | 雷达组 / 现场 | 从接线到进游戏的逐步操作，含常见故障 |
| `双雷达双开-组员操作手册.md` | 雷达组 | 左右 + 上下两路同时开的具体步骤与角色分配 |

## 阅读顺序建议

1. 先看 `PROPOSAL` 了解目标与边界；
2. 再看 `PRD` 的「验收口径」一节，知道什么算完成；
3. 如果要接硬件，直接跳到 `雷达数据采集需求单-v3.md` 第 2 节的字段表；
4. 现场操作只看两份手册，不要临场翻 PRD。

## 关键约束（摘自需求单 v3）

- 帧率 **≥ 20 Hz**，低于此值跳/蹲在物理上不可判；
- 每帧必须带 `ts`（毫秒时间戳）与 `seq`（自增序号），否则无法算丢帧；
- 长度单位统一为**米**，角度为**度**，不允许混用；
- 坐标系必须写明原点和正方向，`geometry.txt` 不允许出现 `not-measured`；
- 静息误报率 ≤ 6%，否则游戏侧只能停用该动作。

这些不是"建议"，是四道数据门的判定依据，见 [`../03-雷达评估与校准/radar-diagnose-guide.md`](../03-雷达评估与校准/radar-diagnose-guide.md)。
