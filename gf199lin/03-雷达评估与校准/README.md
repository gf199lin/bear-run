## 核心设计（校准向导 v2）

五步流程，每步都有明确的通过条件：

| 步 | 玩家做什么 | 系统测什么 | 通过条件 |
|---|---|---|---|
| 1 | 站好别动 | 静息基线 + 误报探针 | 连续 8 帧，x 标准差 ≤ 0.18 |
| 2 | 向左走一步 | 相对基线位移 | ≥ 0.35 且保持 3 帧 |
| 3 | 向右走一步 | 相对基线位移 | 同上，且左右位移差 ≥ 0.5 |
| 4 | 跳一下 | `jump` / `height` 上升沿峰值 | 峰值 ≥ 学到阈值且 ≥ 0.40 |
| 5 | 蹲一下 | `crouch` 上升沿峰值 | 同上 |

**拒绝策略**（这是 v2 最重要的部分）：

- 第 1–3 步若探针判定上游不可信，第 4/5 步直接跳过，省玩家 25 秒；
- 峰值太弱或需要放宽到 0.30 以下才认得出，一律 `disableTh = 2` 停用该动作；
- 停用后玩家用键盘继续玩，**宁可少给一个功能，也不给一个会自己乱动的角色**。

## 已知边界

- 校准只解决符号、基线、上游可用性，**不能让不可用的雷达变可用**；
- 探针是"必要条件"而非充分条件；
- 未做多人/多站位自动适配，雷达板移动后必须重新校准。
