## 1. 这个目录是什么

这里集中保存我在「熊二快跑」项目中产出的**方案、评估、工具、验收证据和版本包**，

1. 让评审能**只看这一个目录**就判断我做了什么、做到什么程度；

3. 保留版本演进的可追溯证据，避免"最后只剩一个 zip"。

本目录**不包含**原始雷达回波抓包、浏览器缓存、`node_modules`、运行时日志和个人身份信息。

## 4. 关键结论（都有数据支撑，不粉饰）

这一节是整个归档里最重要的部分。结论来自 `03-雷达评估与校准/` 下的原始分析。

### 4.1 左右换道：可用，但依赖现场校准

- 早期数据里左右方向符号准确率只有 **53.3%**（≈ 抛硬币），且三个站位符号会漂移。
- 因此没有走"把分类器做得更强"的路线，而是做**开局 5 步校准**：
  站中 → 左 → 右 → 跳 → 蹲，现场学零点、极性和阈值。
- 校准后会校验左右位移差 `minSpread`，防止"原地晃一下就过"。
- 结论：**换道可用，但每换一个站位/移动一次板子就要重新校准。**

### 4.2 跳 / 蹲：代码链路已通，真机尚未验收

- 解码链路已实现：`jump` / `height` 上升沿 → 跳跃；`crouch` 上升沿 → 滑铲。
- 但历史数据的硬伤是：
  - 帧率仅 **1.92 Hz**，一次起跳在数据里中位只占 **2 帧**；
  - 上游跳/蹲判据静息误报率 **39.4% / 54.3%**，等长窗 FPR **89%**；
  - 单帧 AUC ≤ 0.63，说明数据里没有稳定可提取的信号。
- 所以游戏侧的设计是**「能测就学、不能测就关」**：校准第 4/5 步学不到可信峰值时，
  直接把雷达跳/蹲停用（`disableTh = 2`），玩家用键盘继续玩，而不是让角色自己乱跳。
- **结论：跳/蹲属于实验功能，不能对外宣称"已支持"。**

### 4.3 调试方法：先过四道门，再谈调阈值

`radar-diagnose.html` 把"不准"拆成四道可判定的门：

| 门 | 检查内容 | 不过的后果 |
|---|---|---|
| G0 通路 | 帧率、空洞、字段完整性 | 后面全部无意义 |
| G1 坐标 | 静息噪声、左右分离度、单调性 | 换道会抖或反向 |
| G2 时间 | 双路到达差、时钟偏斜 | 跳蹲串扰、动作错位 |
| G3 事件 | 静息误报率、命中率 | 角色自己乱动 |

原则：**门没过，不进游戏调阈值**。漏采的动作不会因为阈值变低而回来。

## 5. 如何复现

### 5.1 直接玩

- 在线：https://gf199lin.github.io/bear-run/
- 本地：解压 `01-交付版本/bear-run-20261020h-share.zip`，双击 `index.html`
- 单文件离线：直接双击 `07-离线单文件版/index.html`，不需要解压或服务器
- 没有硬件也能验判定：主菜单 → 输入源 →「雷达模拟器」

### 5.2 跑雷达数据体检

1. 用浏览器打开 `04-工具与脚本/radar-diagnose.html`
2. 导入一段逐帧 CSV（字段说明见 `03-雷达评估与校准/radar-diagnose-guide.md`）
3. 看 G0–G3 四张表，任何一门 FAIL 就先修数据，不要改游戏阈值

### 5.3 离线回放，不依赖硬件

```bash
python 04-工具与脚本/scripts/fake_radar_ws.py      # 起一个假雷达 WebSocket
python 04-工具与脚本/scripts/gen_lr_replay.py       # 把 CSV 转成回放数据
python 04-工具与脚本/scripts/capture_replay.py      # 录制/回放校验
```

### 5.4 自动化回归

`04-工具与脚本/scripts/` 下的 `cdp_*.py` 是基于 Chrome DevTools Protocol 的端到端脚本，
覆盖校准流程、组合动作、最高分记录、粒子效果、难度曲线。

> 注意：这些脚本是开发期在本机跑的一次性工具，里面的路径、端口按当时环境写死，
> 复现时需要先改 `CHROME`、`URL`、`PORT` 等常量。它们保留价值在于**测试思路和断言**，
> 不是开箱即用的产品代码。
